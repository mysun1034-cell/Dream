# 한정욱 이력서·취업·학습 전략 통합 인수인계

> **용도:** 이 문서를 읽는 Claude 또는 협업자가 앞선 대화를 반복하지 않고, 확정 사실을 보존하면서 이력서·학습·지원 계획을 이어서 정리하기 위한 내부 문서다.
>
> **중요:** 채용 제출용 이력서 자체가 아니다. 사용자 직접 진술, 기존 이력서 초안, 조언, 미검증 사항을 구분한 인수인계 자료다. 회사별 공고·과정 명칭·채용 요건은 이번 문서 작성에서 새로 웹 검증하지 않았다.
>
> **공개 범위:** 전화번호·이메일·주소·계정 비밀정보는 제외했다. 그러나 실명, 경력, 진로 고민, 회사 프로젝트 설명이 포함되어 있으므로 공개 저장소에 그대로 올리기보다 비공개 검토용으로 취급한다. 공개본은 별도로 검토한다.

## 빠른 인수인계: 가장 먼저 읽을 12개 항목

1. 사용자는 **한국항공대학교 항공운항학과, 2027년 8월 졸업 예정**이다. 졸업일을 다시 미확정 상태로 되돌리지 않는다.
2. 공군 복무 보직은 **행정병**이다. 과거 초안의 **관제 업무·관제병 표기는 오류**다.
3. **2022년부터 주식회사 시드닝 이사로 등재**되어 중국 제조사 직접 접촉, 가격·거래조건·A/S·권한 협의, KC 인증 관련 전기안전·전자파 실무를 담당했다.
4. **2026년 11월 시드닝 정식 입사 계획**은 이사 등재 및 기존 프로젝트 참여와 구분한다. 이번 문서 기준으로 정식 입사 완료라고 쓰지 않는다.
5. 미국 **Acron Aviation Academy**의 비행훈련 기간은 **2025-10-28~2026-03-10**이다. 사용자는 약 5개월이라고 설명했다. 자격 취득·과정 수료를 자동으로 붙이지 않는다.
6. 필리핀 고등학교는 **St. Lino Science High School**이다. 사용자의 최초 표기는 `St.lino science High school`이며 제출 때 학교 서류의 공식 표기를 맞춘다.
7. 핵심 프로젝트는 **EDENING**과 **CareLink / EdenCare**다. 후자는 기존 이력서에서 `EdenCare (구 CareLink)`로 정리되어 있다.
8. 초기 목표는 **Palantir Deployment Strategist 신입**이었다. 이후 사용자가 **컨설팅이 예전부터의 꿈**이라고 밝혔으므로 컨설팅을 단순한 차선책으로 취급하지 않는다.
9. 사용자는 학벌 경쟁, AI 대체, 40~50대 고용·소득 안정성을 중요하게 생각한다. 어떤 직무도 안전하다고 보장하지 않는다.
10. **이력서는 이미 작성 중이고 영어는 강점**이다. TOEIC·영어 기초와 이력서 신규 작성을 핵심 추가 숙제로 반복하지 않는다.
11. 최신 학습 의향은 **SQL·Python, 두 프로젝트, Palantir·Anthropic·OpenAI·AWS 공식 교육, ML·DL 과정**이다. 기관 과정 수강·수료는 아직 확인하지 않았다.
12. 채용 점검 자동화는 활성화 상태로 확인했다. 다만 **푸시·이메일 알림 설정은 꺼져 있으며 실행·발송 성공은 아직 확인되지 않았다.** 상세 내용은 15절을 본다.

## 1. 근거와 상태 표기

### 1.1 정보의 우선순위

**사용자의 최신 직접 정정 > 사용자의 이전 직접 설명 > 당시 작성한 산출물 > 이전 답변의 추론·제안.**

기존 산출물 역시 AI가 작성한 초안일 수 있으므로, 그 안의 문장을 곧바로 객관적 경력 증명으로 취급하지 않는다. 수치·직함·자격·고객 성과는 제출 전에 원본으로 확인한다.

| 표기 | 의미 | 사용 원칙 |
|---|---|---|
| `사용자 확정` | 사용자가 직접 말하거나 정정한 사실·의향 | 경력의 사실과 미래의 의향은 구분한다. 공식 서류 확인 완료를 뜻하지 않는다. |
| `기존 초안` | 이전 DOCX·PNG에 적혀 있는 내용 | 실제 구현·성과·수료 여부의 별도 증거는 필요하다. |
| `제안` | 이전 대화에서 어시스턴트가 권한 방향 | 사용자가 모두 채택했다고 기록하지 않는다. |
| `가정` | 계획 수립을 위해 둔 전제 | 변경 가능하며 실제 확정일·입사조건과 다를 수 있다. |
| `재확인` | 증빙·최신 공고·실제 상태가 필요한 항목 | 이력서의 확정 사실로 승격하지 않는다. |
| `도구 확인` | 이번 정리에서 직접 조회한 파일·자동화 상태 | 확인 범위를 넘겨 해석하지 않는다. |

## 5. 이력서 구성·문장 초안

이 절은 **제출 전에 검증할 문장 초안**이다. 아직 확인되지 않은 프로젝트 성과나 고객 수를 넣지 않는다.

### 5.1 중심 포지셔닝

> 해외 제조사와 제품 도입 조건을 직접 협의하고 국내 인증 실무를 수행해 온 경험을 바탕으로, 소프트웨어 제품 기획과 개발까지 업무를 확장하고 있습니다.

컨설팅·DS 공통 요약:

> 사업 요구를 기능·데이터 구조·검증 조건으로 구체화하고, 실제 사용 과정에서 문제를 확인하고 개선하는 기술제품·솔루션 실무자.

위 표현은 지원자 소개 문구이며 **현재 공식 직급이나 전문 자격의 이름이 아니다.**

### 5.2 권장 문서 순서

1. 이름·지원 직무·공개 가능한 연락처
2. 핵심 소개 3~4문장
3. 시드닝 경력: 이사 등재 / 실제 해외사업 업무 / 정식 근무 구분
4. EDENING·CareLink 대표 프로젝트와 본인 기여
5. 기술·업무 역량: 활용·학습·설계 검토 상태 구분
6. 학력·교육·어학·군 복무·해외 비행훈련
7. 지원 직무에 필요한 추가 프로젝트만 선택적으로 포함

이력서는 이미 작성 중이므로 새 문서를 무조건 다시 만드는 것이 아니라 **기존 초안에 정정·증거·직무별 강조점을 반영**한다. 국문·영문 버전에서 사실과 수치는 동일하게 유지한다.

### 5.3 시드닝 경력 문장

**주식회사 시드닝 | 이사 등재 및 해외사업·제품 실무**

- 2022년부터 이사로 등재되어 중국 제조업체에 직접 접촉하고 제품 도입 협의와 제조사 커뮤니케이션을 담당.
- 제품 가격, 거래조건, A/S 및 거래 관련 권한 등 핵심 계약사항을 직접 조율.
- 국내 제품 도입을 위한 KC 인증 관련 전기안전·전자파 실무를 전담.
- 이후 EDENING·CareLink의 제품 기획·백엔드 개발에 참여하며 업무 범위를 소프트웨어 제품으로 확장.

**기간 표기 예시:**

```text
이사 등재: 2022년~ [정확한 등재일·현재 상태 확인]
해외사업 실제 수행: [기간·참여 형태 기재]
제품 기획·개발 참여: [실제 시작일]~
```

`이사`라는 이유로 CTO·상근 임원·공동창업자·팀장 등의 명칭을 추가하지 않는다. 직함과 실제 수행 업무를 별도로 보여준다.

### 5.4 제출 전에 채울 성과

제조사 수, 협상 품목 수, 인증 완료 품목 수, 조건 개선 내역, 일정 단축, 사용 기관 수, 실제 작업 개선 등을 후보로 검토할 수 있다. **숫자와 효과는 본인 자료로 확인된 경우에만 넣는다.**


- **컨설팅 회사에서 일하는 것이 예전부터의 꿈**이다. `U-05`
- 40~50대 해고·소득 불안, AI 대체 가능성, SKY 출신과의 학벌 경쟁이 걱정된다. `U-06`
- 개발을 선택한 이유 중 하나는 AI 시대에도 사람의 기술적 역할이 필요할 것이라는 생각이었다.

### 8.2 논의가 바뀐 흐름

```text
Palantir DS 1순위
→ 비슷한 고객 문제 해결 직무로 선택지 확대
→ 컨설팅도 독립적인 목표로 확인
→ 안정성·AI·학벌 우려를 함께 고려
→ 기술·업무 전문성을 유지하는 컨설팅과 기업 내부 역할을 함께 비교
→ SQL·Python·두 제품·공식 교육/ML·DL 학습을 현재 실행 중심으로 선택
```

### 8.3 이전 대화에서 권한 방향 — 최종 입사 결정은 아님

**주력 비교군:** 기술·업무혁신 컨설팅, 고객 AI 도입, 데이터·ERP 솔루션, 기업 내부 IT·제품·업무개선.

**도전군:** Palantir DS, 순수 전략컨설팅, 높은 요구 수준의 AI Deployment 역할.

**유지할 선택지:** 기술 역량에 맞는 개발 직무. 컨설팅을 선택했다고 개발 경험을 버리지는 않되, 코딩을 오래 하지 않고도 언제든 개발자로 복귀할 수 있다고 가정하지 않는다.

### 8.4 안정성 논의의 핵심

- **고용 유지:** 같은 회사에서 계속 일할 가능성.
- **직업 지속:** 회사를 바꾸어도 필요한 사람으로 일할 가능성.
- 개발·컨설팅 어느 쪽도 AI 대체나 해고에서 안전하다고 보장할 수 없다.
- 기술이 좋아져도 사람의 역할이 남는다는 것과 기존 인원만큼 채용된다는 것은 별개다.
- 모든 컨설팅 회사를 같은 승진·평가·영업 구조로 묶지 않는다.
- 40~50대 한국 컨설턴트와 개발자의 해고 위험을 수치로 비교할 근거는 이 대화에서 확보하지 않았다.
- 학벌의 영향이 없다고 단정하지도, 한국항공대 출신이 불가능하다고 단정하지도 않는다.
- 학교 간판만으로 경쟁하려 하지 말고 실제 업무·데이터·구현·검증·협업 경험이 평가되는 모집 단위를 찾는 것이 이전 제안이다.

### 11.4 ML → DL 이론 트랙

### 12.3 사용자·현직자 피드백

이전 제안은 초기 실무자·운영자 등 **3~5명에게 현재 작업 사례를 듣고**, 주기적으로 강사·경험 있는 개발자·현직 컨설턴트에게 결과물을 보여주는 것이었다. 인원·횟수는 의무 수치가 아니다.

좋은 질문의 예:

> 최근 이 일을 처리한 사례를 보여줄 수 있나요? 어디에서 시간이 가장 오래 걸렸고, 잘못됐다는 것은 언제 알게 됐나요?

기능 선호만 묻기보다 실제 업무와 실패를 확인한다. 다른 사람의 피드백으로 본인 판단을 무엇을 바꿨는지도 기록한다.

### 12.4 숫자·사업 판단

매출·비용·이익·현금흐름, 고정비·변동비, 손익분기점, 가정 변화, 도입 비용과 효과를 프로젝트에서 연습한다. EDENING에서는 AI·음성·결제·영업·지원 비용을, CareLink에서는 시간 절감·처리량·실제 비용 절감을 구분해서 분석한다.

통계는 평균·중앙값·분포, 비율·퍼센트포인트, 표본·기간, 상관과 인과, 비교 조건을 우선한다. 개선 전후의 수치가 나와도 기능 변경만의 효과라고 자동 단정하지 않는다.

Excel은 표·피벗·조회·조건부 집계·시나리오·차트 정도를 우선하고, Power BI는 기존 학습을 활용한다. 시각화 도구를 여러 개 동시에 깊게 늘리지 않는다.

### 12.5 컨설팅 문제해결·보고·협업

주 1회 사례 또는 Excel 비용·효과 분석, 의사결정 메모 한 장을 제안했다. 사용자는 아직 이 시간표 전체를 확정하지 않았다.

```text
목표·제약 확인 → 문제 분해 → 가설 → 필요한 데이터
→ 대안 비교 → 권고 → 불확실성·다음 검증
```

의사결정 메모는 **결정할 것 / 권고 / 근거 / 대안 / 위험 / 다음 행동**으로 구성한다. 영어는 별도 시험 공부보다 필요할 때 이 내용을 실제 면접·고객 설명에 쓰는 방식으로 유지한다.

협업 사례는 모호한 요구 정리, 반대 의견, 하지 않기로 한 결정, 실패 수정, 동료 지원, 불편한 사실 보고를 중심으로 찾는다. `혼자 모두 했다`는 설명만 남기지 않는다.

## 18. Git 관리 제안과 공개 검토

### 18.1 현재 작업 범위

이번 요청의 범위는 **Markdown 파일 작성**이다. GitHub 저장소를 생성·선택하거나 파일을 커밋·푸시하지 않았다. 이 대화에는 GitHub 도구가 제공되지만, 실제 업로드에는 대상·권한·공개 범위의 확인과 별도 실행이 필요하다.

### 18.2 분리할 때 사용할 구조 — 제안

이 파일 하나로 먼저 검토하고, 필요할 때만 아래처럼 나눈다. 기존 프로젝트의 루트 `CLAUDE.md`나 개발 규칙을 임의로 덮어쓰지 않는다.

```text
career/
  00_context.md                 # 이 통합 인수인계의 정리본
  01_verified_facts.md          # 사실·증빙·정정 이력
  02_resume_ko.md               # 국문 제출용
  03_resume_en.md               # 영문 제출용
  04_target_roles_companies.md  # 후보와 실제 공고 구분
  05_learning_plan.md           # 수강·적용·완료 상태
  06_evidence_register.md       # 성과·역할·검증 근거
  cases/
    edening.md
    carelink.md
  decisions.md                 # 진로·지원·학습 변경 이유
```

이 구조는 아직 실제 저장소에 생성하지 않았다. 전화·이메일을 넣는 제출용 문서와 개인 진로 고민·회사 내부자료는 공개용 포트폴리오와 분리한다.

### 19.3 문서 범위의 한계

현재 대화에 제공된 이력서·취업 논의, 기존 DOCX 두 개, PNG 한 개, 자동화 상태를 통합했다. 전체 개발 저장소·인사 서류·성적표·계약서·현행 채용공고를 감사한 문서는 아니다.

과거 대화의 감정적 표현은 과장하지 않고 진로 판단에 필요한 선호·걱정만 정리했다. 건강·연애·가족관계 등 취업 인수인계에 불필요한 개인사는 제외했다.
