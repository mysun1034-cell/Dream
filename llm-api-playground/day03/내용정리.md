## 1부 · 배열은 어디로 갔나

실습: `01_responses.py`

### 새 문 하나 — Responses API

| | |
|---|---|
| 이름 | Responses API — "응답 API" |
| 만든 곳 | OpenAI |
| 언제 | `chat.completions`보다 나중 |
| 왜 둘인가 | 옛것 미폐지 · 세상의 코드 대부분이 아직 옛 문 |

새 것 = 좋은 것이 아니다. **무엇이 달라지는지 보고 고르는 것**이 오늘 할 일이다.

### 첫 호출 — 달라진 이름 셋

```python
r = client.responses.create(
    model=API_MODEL,
    input="한 문장으로 자기소개.",   # messages= 가 아니라 input=
)
print("답 :", r.output_text)        # choices[0].message.content 자리
print("id :", r.id)                 # ← 곧 쓴다
print("usage :", r.usage.input_tokens, "→", r.usage.output_tokens)
```

슬라이드 실행 예:

```text
답 : 안녕하세요, 저는 다양한 질문에 답하고 필요한 정보를 알기 쉽게 전달하는 AI 어시스턴트입니다.
id : resp_0b32c1a751a4b064006a83df90fcfc819ab54f3dcea5e2d398
usage : 13 → 53
```

달라진 것 셋:

- 리스트 → **문자열 하나** (`input`)
- 긴 경로 → **`output_text`**
- 응답에 **`id`**

### Day 1의 약속 — 다시 확인

> 모델은 우리를 기억하지 않는다. 앞 대화를 매번 통째로 다시 보낸다.

이번 호출이 보내는 것은 한 줄뿐이다. "방금 내가 뭘 물었지?"를 보내면 앞 대화는 한 글자도 안 간다.

### 배열 없이 이어지는 대화

```python
r2 = client.responses.create(
    model=API_MODEL,
    input="방금 내가 뭘 물었지?",
    previous_response_id=r.id,   # 배열 대신 앞 응답의 id 하나
)
print(r2.output_text)
# “한 문장으로 자기소개.”라고 물으셨어요.
```

안다. 배열을 안 보냈는데도.

### 맥락은 어디에?

| Day 1 · 2 | 오늘 |
|---|---|
| `messages=[…]` | `previous_response_id` |
| 내 프로그램이 보관 | OpenAI 서버가 보관 |
| 매 턴 통째로 전송 | 그 자리의 번호표 = `id` |

맥락은 사라진 게 아니라 **서버로 옮겨간 것**이다.

### 그럼 요금은?

Day 1은 턴이 늘수록 배열이 자라서 눈에 보였다. 오늘은 배열이 없다. 요금도 없어졌을까?

아니다. **보낸 글자는 줄고, 청구 토큰은 는다.**

```python
prev = None
for i, q in enumerate([
    "내 이름은 금이야. 취미는 등산이고 서울에 살아.",
    "내 취미가 뭐랬지?",
    "내가 어디 산다고 했지?",
    "내 이름은?",
], 1):
    rr = client.responses.create(
        model=API_MODEL, input=q, previous_response_id=prev,
    )
    prev = rr.id
```

슬라이드 실측:

| 턴 | 내가 보낸 글자 | 청구된 입력 토큰 |
|---:|---:|---:|
| 1 | 27자 | 23 |
| 2 | 10자 | 115 |
| 3 | 13자 | 148 |
| 4 | 6자 | 169 |

왼쪽은 27 → 6, 오른쪽은 23 → 169. **반대 방향.**

`previous_response_id`가 줄이는 것은 **보내는 양**이지 **요금**이 아니다.

앞 대화 → 서버가 보관 → 매 턴 모델에 다시 투입. 하는 일은 Day 1과 동일하고, 내 코드에서 안 보일 뿐이다.

Day 1은 배열이 자라는 게 보였다. **안 보이는 쪽이 더 위험하다.**

### 남기지 않기 — 부탁이 아니라 스위치

```python
r3 = client.responses.create(
    model=API_MODEL,
    input="짧게 인사만 해.",
    store=False,   # 모델에게 부탁하는 게 아니라 내가 켜고 끄는 스위치
)
```

`store=False`로 받은 `id`는 `previous_response_id`로 못 쓴다.

```text
BadRequestError — Error code: 400
Previous response with id 'resp_0938…'
```

Day 2의 습관 회수: **서버의 말을 소리 내어 읽으면 고칠 곳이 적혀 있다.**

### 이름 대조표

| 하는 일 | Chat Completions (Day 1·2) | Responses (오늘) |
|---|---|---|
| 부르기 | `chat.completions.create` | `responses.create` |
| 입력 | `messages=[{"role":"user",…}]` | `input="…"` |
| 시스템 지시 | `{"role":"system", …}` | `instructions="…"` |
| 답 꺼내기 | `choices[0].message.content` | `output_text` |
| 멈춘 이유 | `finish_reason` | `status` · 아이템 타입 |
| 대화 잇기 | 배열 재전송 | `previous_response_id` |
| 구조화 출력 | `parse(response_format=…)` | `parse(text_format=…)` |
| 도구 결과 재투입 | `{"role":"tool", "tool_call_id":…}` | `{"type":"function_call_output", "call_id":…}` |

대부분 이름만 교체다. **진짜 다른 것 = 대화 잇기 · 도구 결과 재투입.**

### 이름만 바뀐 걸까? — 응답 해부

같은 질문 `"한 단어로 인사해."`를 두 API로 보낸다.

| | Chat Completions | Responses |
|---|---|---|
| 최상위 키 | **9개** | **39개** |
| 성격 | 답만 담긴 봉투 | 내가 보낸 설정이 되돌아온다 |

Responses의 응답은 **서버에 저장된 객체**다. 그래서 키가 많다.

저장된 객체라서 되는 일:

```python
got = client.responses.retrieve(rr.id)   # 나중에 다시 꺼내 오기
client.responses.delete(rr.id)           # 서버에서 지우기
```

지운 뒤 다시 꺼내면:

```text
NotFoundError — Error code: 404
Response with id 'resp_0123f055…' not found
```

`chat.completions`에는 `retrieve`도 `delete`도 없다. 돌려받은 그 순간이 전부다.

`previous_response_id`와 `background`가 되는 이유가 여기다.

### 칸이냐, 목록이냐

```text
Chat Completions                    Responses
────────────────                    ─────────────────────
choices[0]                          output[ ]          ← 리스트
 └ message                           ├ reasoning        ← type
    ├ content                        ├ web_search_call  ← type
    ├ tool_calls   ← 칸이 고정        └ message          ← type
    ├ refusal                          └ content[ ]     ← 또 리스트
    └ audio                              └ output_text
```

Chat은 메시지 하나 · 칸이 미리 다 뚫려 있다. 안 쓰는 칸은 `None`.

Responses는 **타입 붙은 아이템이 쌓인다.** 개수도 종류도 그때그때다.

새 기능이 생기면:

| Chat Completions | Responses |
|---|---|
| `message`에 칸을 하나 더 뚫는다 | 아이템 종류를 하나 더 만든다 |
| 그래서 `function_call`처럼 안 쓰는데 못 지우는 칸이 남는다 | `[o.type for o in r.output]`은 종류가 늘어도 그대로 돈다 |

Chat이 나쁜 설계가 아니다. 답이 글 하나뿐이던 시절엔 평평한 쪽이 읽기 쉬웠다.

### `finish_reason`이 간 자리

```python
short = client.responses.create(
    model=API_MODEL,
    input="파이썬을 열 문장으로 설명해.",
    max_output_tokens=16,   # 어제의 max_completion_tokens 자리
)
# status : incomplete
# incomplete_details: IncompleteDetails(reason='max_output_tokens')
# output_text : ''
```

| 알고 싶은 것 | Chat Completions | Responses |
|---|---|---|
| 왜 멈췄나 | `choices[0].finish_reason` | `status` + `incomplete_details.reason` |
| 답 길이 제한 | `max_completion_tokens` | `max_output_tokens` |

Day 1의 그 빈 응답 — 같은 사건, 읽는 자리만 이동.

### 보내는 쪽도 목록

`input="문자열"`은 줄임말이다. 원래 모양은 아이템 목록이다.

```python
r5 = client.responses.create(
    model=API_MODEL,
    input=[
        {"role": "developer", "content": "너는 한 단어로만 답한다."},
        {"role": "user", "content": "대한민국의 수도는?"},
    ],
)
# 서울
```

오후의 도구 결과 재투입이 특별해 보이지 않는 이유: 목록에 조각 하나를 끼워 넣은 것일 뿐이다.

```python
input=[{"type": "function_call_output", "call_id": …, "output": result}]
```

### 원천적 차이 셋

1. **결과냐 리소스냐** — Chat은 답만. Responses는 서버에 남는 객체. → `retrieve` · `delete` · `previous_response_id` · `background`
2. **칸이냐 목록이냐** — 고정된 칸 vs 타입 붙은 아이템 목록. → 추론 · 검색 · 코드 실행이 같은 자리에 나란히
3. **입력도 목록** — 문자열은 줄임말. → 도구 결과 재투입이 특별해 보이지 않는 이유

이름 대조표는 이 셋의 겉면이다. 셋을 알면 외울 필요가 없다.

### 구조화 출력 — 클래스는 그대로

어제 그 클래스, 한 글자도 안 바꾼다.

```python
class ReviewAnalysis(BaseModel):
    sentiment: str
    rating: int
    summary: str

rp = client.responses.parse(
    model=API_MODEL,
    input="이 리뷰를 분석해 줘: 배송은 느렸지만 물건은 기대 이상. 또 살 듯.",
    text_format=ReviewAnalysis,   # 어제는 response_format=
)
print(rp.output_parsed)
# sentiment='긍정적' rating=4 summary='배송은 느렸지만 상품 품질이 기대 이상이어서 …'
```

바뀐 것 둘:

| 어제 | 오늘 |
|---|---|
| `response_format=` | `text_format=` |
| `.parsed` | `.output_parsed` |

### 편해진 값 — 고를 수 있어야 한다

| | 내가 배열을 든다 (Day 1·2) | 서버가 든다 (오늘) |
|---|---|---|
| 대화 내용 | 내 메모리 · 내 DB | OpenAI 서버 |
| 자르기·고치기 | 리스트를 내가 조작 | 내 마음대로 불가 |
| 매 호출 전송량 | 대화가 길수록 증가 | 짧다 |
| 다른 제공자로 이전 | 배열만 들고 가면 됨 | 불가 |

05의 로컬 sLLM 서버는 `/v1/chat/completions`만 개방한다.

**오늘 배우는 편한 길 = OpenAI 안에서만 통용.**

## 2부 · 왕복은 그대로다

실습: `02_tools_responses.py`

### 어제 그 함수 그대로

```python
def get_weather(city: str, latitude: float, longitude: float) -> str:
    """그 좌표의 지금 날씨를 open-meteo 에서 가져온다 (키 불필요)"""
    ...

print(get_weather("서울", 37.5665, 126.9780))
# 서울 기온 30.0도, 습도 64%, 바람 6.0m/s
```

이 함수는 OpenAI와 무관하다. 그냥 파이썬. **내 코드는 API가 바뀌어도 안 바뀐다.**

### 함수 설명서 — 한 겹 얕게

```python
# 어제 · Chat Completions
{"type": "function",
 "function": {                 # ← 한 겹 더
     "name": "get_weather",
     "description": "...",
     "parameters": {...}}}

# 오늘 · Responses
{"type": "function",
 "name": "get_weather",        # 바로 여기
 "description": "...",
 "parameters": {...}}
```

안쪽 `parameters`는 어제와 한 글자도 동일하다. 어제 오전에 손으로 쓴 그 JSON 스키마다.

### 응답 = 답이 아니라 요청서

```python
r = client.responses.create(
    model=API_MODEL,
    input="서울 지금 몇 도야?",
    tools=tools,
)
print("output 아이템 :", [o.type for o in r.output])
print("output_text :", repr(r.output_text))
```

슬라이드 실행 예:

```text
output 아이템 : ['reasoning', 'function_call']
output_text : ''
부르라는 함수 : get_weather
넘겨준 인자 : {"city":"서울","latitude":37.5665,"longitude":126.978}
call_id : call_djkVkxxeR1jWZWvfcwGmJMxI
```

`reasoning`은 답하기 전 생각의 흔적이다. 내용은 비공개. 이름은 마지막 시간에.

`output_text`가 비면 **output 아이템 타입부터 본다.**

### 어제 ↔ 오늘 · 자리만 이동

| 어제 (Chat Completions) | 오늘 (Responses) |
|---|---|
| `finish_reason == "tool_calls"` | `output`에 `function_call` 아이템 |
| `msg.tool_calls[0].function.name` | `fc.name` |
| `msg.tool_calls[0].id` | `fc.call_id` |
| `content is None` | `output_text`가 빈 문자열 |

**모델은 여전히 실행하지 않는다.**

### 재투입 — 조각 하나만

```python
result = get_weather(**args)   # ← 여기서 실제로 실행된다
r2 = client.responses.create(
    model=API_MODEL,
    previous_response_id=r.id,  # 앞 대화는 서버가 보관
    tools=tools,
    input=[{
        "type": "function_call_output",  # 어제의 {"role": "tool", …} 자리
        "call_id": fc.call_id,           # 요청 ↔ 결과 짝짓기
        "output": result,
    }],
)
# 최종 답 : 서울은 현재 **30.0°C**예요. 습도는 **64%**, 바람은 **6.0m/s**입니다.
```

어제 = 요청서까지 배열에 재투입(조각 둘). 오늘 = **결과 조각 하나.**

### 없어진 것 = 배열 재전송뿐

| | Day 2 | 오늘 |
|---|---|---|
| 함수 설명서 쓰기 | 내가 | 내가 (한 겹 얕게) |
| 모델이 요청서를 준다 | 그렇다 | 그렇다 |
| 함수 실행 | 내 코드 | 내 코드 |
| 결과 재투입 | 내가 | 내가 (이름만 교체) |
| 앞 대화 재전송 | 배열 통째로 | `id` 하나 ← **유일한 소멸** |

왕복은 도구 호출의 구조다. **API를 바꿔도 안 없어진다.**

어제 그린 네 걸음과 같은 도형 — 상자 안 낱말만 바뀌었다.

1. 함수 설명서 `tools` (한 겹 얕게)
2. 모델의 요청서 `function_call`
3. 실행은 내 코드가 `get_weather(**args)`
4. 결과를 다시 `function_call_output` (`call_id`로 짝짓기) → 최종 답

### p2 회수

Spring AI 애너테이션 한 줄 `@Tool` 아래에, 어제 손으로 돈 네 걸음이 있다. 오늘 API를 바꿔도 그대로다.

**감춰져 있었을 뿐, 없었던 적이 없다.**

## 3부 · 내가 실행하지 않는 도구

실습: `02_tools_responses.py` 후반

### `web_search` — 한 줄

```python
rw = client.responses.create(
    model=API_MODEL,
    input="오늘 서울 날씨 한 줄로 알려 줘.",
    tools=[{"type": "web_search"}],   # 이게 전부. 함수도, 왕복 루프도 없다
)
print(rw.output_text)
# 오늘(8월 18일) 서울은 대체로 흐리고 습하며, 현재 30°C·최고 31°C입니다.
```

오전의 네 걸음은 어디로 갔나?

### 내 코드에 실행하는 줄 없음

| | 내 함수 도구 | 내장 도구 (built-in tools) |
|---|---|---|
| 함수 정의 | 내가 | 없음 |
| `json.loads` | 내가 | 없음 |
| 실행 | 내 컴퓨터 | OpenAI 서버 |
| 결과 재투입 | 내가 | 없음 |

주의: 내장이라고 서버가 다 실행하지는 않는다.

- `local_shell` · `apply_patch` · `computer` → **여전히 내 컴퓨터가 실행**

실행 칸이 서버 안으로 옮겨 간 그림:

```text
OpenAI 서버 안
① tools=[{type: web_search}] 한 줄
② 검색이 필요한지 판단
③ 여기서 검색한다
④ 결과 반영 → 최종 답 (검색 내용이 문장 속에)
```

없어진 게 아니라 OpenAI 서버 안으로 옮겨 갔다. **그래서 토큰을 치른다.**

### 그런데 정말 검색했나?

답이 그럴듯하다 = 검색했다? 모델이 아는 척했을 수도 있다. 추측하지 않는다. **응답에 적혀 있다.**

확인하는 자리 셋:

```python
print("아이템 :", [o.type for o in rw.output])
for o in rw.output:
    if o.type == "web_search_call":
        print(" 검색함 · 상태:", o.status)
        print(" 실제 검색어 :", getattr(o.action, "query", None))
print("입력 토큰 :", rw.usage.input_tokens)
```

슬라이드 실행 예:

```text
아이템 : ['reasoning', 'web_search_call', 'message']
검색함 · 상태: completed
실제 검색어 : weather: South Korea, Seoul
입력 토큰 : 4885   ← 검색 결과가 통째로 들어와서 크다
```

| 어디를 보나 | 알 수 있는 것 |
|---|---|
| `[o.type for o in r.output]`에 `*_call` | 썼다 |
| 그 아이템의 `action.query` · `.code` | 무엇을 검색·실행했는지 |
| `usage.input_tokens` 급증 | 도구 결과 유입의 흔적 |

### 대가 = 토큰

| | 내 함수 왕복 | `web_search` |
|---|---|---|
| 입력 | 수백 토큰 | 4,885 토큰 |
| 실행 | 내 컴퓨터 | OpenAI 서버 |

편한 만큼 값을 치른다. **공짜로 편해지는 것은 없다.**

### 같은 질문 · 같은 도구 · 다른 모델

```python
QUESTION = "739521468 * 8462137 을 계산해 줘. 숫자만."
CODE_TOOL = [{"type": "code_interpreter", "container": {"type": "auto"}}]

for model in ["gpt-5.4-nano", "gpt-5.6-luna"]:
    rc = client.responses.create(model=model, input=QUESTION, tools=CODE_TOOL)
```

슬라이드 한 회차:

| 모델 | 도구 | 정답 |
|---|---|---|
| `gpt-5.4-nano` | 안 씀 | X · `6255407608184276` |
| `gpt-5.6-luna` | `['code_interpreter_call']` | O · `6257931976657116` |

정답: `6257931976657116`

**도구를 주는 것 ≠ 모델이 쓰는 것.**

5회 반복 경향:

| 모델 | 도구 사용 | 도구를 쓴 회차의 정답률 |
|---|---|---|
| `gpt-5.4-nano` | 1 / 5 | (쓴 회차는 정답) |
| `gpt-5.6-luna` | 5 / 5 | 전 회차 정답 |

작은 모델이 계산을 못 하는 것이 아니다. **도구를 안 쓴 회차가 오답.** 판단 주체는 모델이다.

쉬운 계산(`2**10`)엔 luna도 안 쓴다. 난이도를 보고 판단한다.

화면마다 결과가 다를 수 있다. 경향은 여러 번 돌려야 보인다.

### `tool_choice` — 강제

```python
rf = client.responses.create(
    model="gpt-5.4-nano",
    input=QUESTION,
    tools=CODE_TOOL,
    tool_choice={"type": "code_interpreter"},  # 자동 판단 대신 '무조건 이걸 써라'
)
# 강제 : ['code_interpreter_call', 'message'] · 정답 True
# 모델이 실행한 코드 : 739521468 * 8462137
```

검색은 `action.query`, 코드는 `.code`. 자리는 다르되 원리는 같다 — **응답을 열어 본다.**

### 값 비교 — 좋은 모델 ≠ 비싼 모델

| 모델 | 입력 (100만 토큰당) | 출력 (100만 토큰당) | 도구 자동 사용 |
|---|---:|---:|---:|
| `gpt-5.4-nano` | $0.20 | $1.25 | 1 / 5 |
| `gpt-5.6-luna` | $0.20 | $1.20 | 5 / 5 |

재보고 고르는 것 = 오늘의 제목.

## 4부 · 흘러나오는 답

실습: `03_stream.py` · `stream_app.py`

### 왜 흘리나

지금까지는 답이 다 만들어진 뒤 한 번에 도착했다. 긴 답 = 그동안 화면 정지 → 고장으로 오인.

ChatGPT에서 글자가 하나씩 나오는 그것.

### `stream` — `with`로 열기

```python
with client.responses.stream(model=API_MODEL, input=question) as stream:
    for event in stream:                              # 서버가 보내는 사건을 차례로
        if event.type == "response.output_text.delta":  # 그중 '글자 조각'만
            if first_at is None:
                first_at = time.time() - t0
            print(event.delta, end="", flush=True)    # end="" — 이어 붙인다
```

슬라이드 한 실행: 첫 글자까지 0.61초 · 전체 1.85초. 숫자는 회차마다 다르다.

### 총량이 아니라 체감

전체 시간은 비슷하다. 달라진 것은 **첫 글자까지의 시간.**

스트리밍은 빨라지는 기술이 아니라 **기다림을 바꾸는 기술**이다.

### 이벤트 = 이름표 붙은 조각

| 사건 | 언제 |
|---|---|
| `response.created` | 시작할 때 한 번 |
| `response.output_text.delta` | 글자 조각마다 — **우리가 고른 것** |
| `response.output_text.done` | 그 덩어리 종료 |
| `response.completed` | 전부 종료 |

Chat Completions는 이름 없는 조각(`chunk`). 꺼내 봐야 정체를 파악한다.

Responses는 사건에 이름이 있다. **필요한 것만 골라 쓴다.**

### 흘러나오는 챗봇

Day 1 `app.py`에서 사라진 둘:

| 없어진 것 | 오늘 |
|---|---|
| 배열 `session_state.messages` | `prev_id` 한 줄 |
| 답을 다 기다리던 시간 | 흘러나오는 글자 |

캡션 예: 토큰 141 → 29. 13자 질문에 입력 141 토큰. 오전의 그 자람이 내 화면에 보인다.

### 앱의 핵심 — 자리 잡고 덧쓰기

```python
placeholder = st.empty()          # 여기에 계속 덧붙인다
answer = ""
with client.responses.stream(
    model=API_MODEL,
    input=prompt,                                    # 이번에 할 말만
    previous_response_id=st.session_state.prev_id,   # 앞 대화는 서버가
) as stream:
    for event in stream:
        if event.type == "response.output_text.delta":
            answer += event.delta
            placeholder.markdown(answer + "▌")       # ▌ 는 커서 흉내
    final = stream.get_final_response()
placeholder.markdown(answer)                         # 커서를 지운 최종본
st.session_state.prev_id = final.id                  # 다음 턴이 이어붙일 자리
```

### 도구 + 스트리밍 = 오늘은 보류

도구 호출까지 흘려받으면 함수 이름·인자도 조각으로 분해된다.

```text
{"ci … ty": "서 … 울"}
```

전부 모아 붙인 뒤에야 `json.loads`가 가능하다. 가능하지만 마지막 날에는 보류.

**오늘 흘리는 것 = 도구 없는 단순 챗.**
