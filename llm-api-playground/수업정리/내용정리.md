## 핵심

### 1. 배열이 대화다 — `(i)api.py` · `(i)cli_chat.py` · `(i)app.py`

```text
system  → 나는 누구로 말하나 (배열 맨 앞)
user    → 질문
assistant → 모델 답
```

매 턴 앞 대화 전체를 다시 보낸다. 그래서 `prompt_tokens` 가 커지고, 요금도 그 수다.

세 그릇은 같다.

| 그릇 | 배열 |
|---|---|
| 스크립트 | `messages` |
| 터미널 | 같은 리스트 + `while` |
| Streamlit | `st.session_state.messages` |

Streamlit은 스크립트를 매번 다시 실행한다. 그래서 배열을 세션에 두고, 루프 시작 때 `system` 빼고 다시 그린다. 2:29 코드는 이번 턴만 그려서 대화가 날아 보였고, 2:33에서 다시 그리기를 넣었다. `(i)app.py` 는 최종본.

강사님 CLI 원문에는 `"cotent"` 오타가 있었다. 파일에는 `content` 로 고쳐 둠.

### 2. 답의 모양을 약속한다 — `(i)structured.py` · `(i)quiz.py`

코드가 `data["감정"]` 을 쓰려면 칸이 고정돼야 한다.

| 단계 | 보장 |
|---|---|
| `json_object` | JSON이기만 하면 됨. 키는 흔들림. 프롬프트에 `JSON` 필요. |
| `json_schema` + `strict` | `required` + `additionalProperties: False` + `strict: True` |
| `parse` + Pydantic | 위와 같고 `.parsed` 가 객체 |

`strict` 는 스키마 안이 아니라 `json_schema` 옆이다.  
`description` 은 장식이 아니다. 칸에 무엇을 넣을지 모델이 읽는 설명이다.

400 은 키가 틀린 401이 아니다. 요청서 양식 문제. 함정: `JSON` 미언급, `propeties` 오타, `required`/`additionalProperties` 없음, `strict` 위치.

퀴즈는 그 응용이다. 모델은 문제 JSON만, 채점은 파이썬.

### 3. 도구는 내가 실행한다 — `(i)tools.py` · `(i)tool_app.py`

모델은 함수를 실행하지 않는다. `tool_calls` 로 요청만 한다.

```text
함수 정의 → tools 스키마 → create(..., tools=)
→ finish_reason == tool_calls
→ json.loads(arguments) 로 내 함수 실행
→ messages 에 요청서(msg) + {role:tool, tool_call_id, content}
→ 다시 create → 말 답
```

`parameters` 는 오전의 JSON 스키마다. 자리가 답 모양이 아니라 함수 인자다.

`calc` 의 `expression` 은 모델이 만든 문자열이다. 검사 없이 `eval` 하면 안 된다.

`tool_app.py` 는 `app.py` 와 그릇만 같고 왕복은 `tool_chat` 과 같다. 말풍선에는 user/assistant 말만. 상한 5바퀴. 빈 답은 대체 문구 — `None` 이 실리면 다음 턴 400.
