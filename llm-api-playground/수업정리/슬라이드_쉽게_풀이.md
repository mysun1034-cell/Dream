# 1일차 (8/14) — API와 대화하기

## 「모델은 우리를 기억하지 않는다. 대화는 배열이다」

과목 첫날이다. 어제는 키를 발급하고 호출 한 번 성공한 날이다. 오늘은 그 **호출 하나**를 **대화가 되는 프로그램**으로 만든다. 연휴 앞이라, 오늘 안에 완성해서 손에 들고 나간다. 다음(8/18)은 모델이 함수를 부르는 날이다.

저녁 목적지는 하나다. **브라우저에 직접 만든 챗봇 화면**이 뜨는 것.

새 주제가 세 개가 아니다. **리스트 하나**를 **세 그릇**에 담는 날이다.

그 리스트 이름이 `messages`다.

| 그릇 | 어디에 사나 | 누가 쌓나 |
|---|---|---|
| 1. 노트북 셀 | 변수 `messages` | 손으로 `append` |
| 2. 터미널 `chat.py` | 같은 리스트 | `while` 루프 |
| 3. 브라우저 `app.py` | `st.session_state.messages` | Streamlit이 다시 실행될 때마다 그 보관함을 씀 |

비유하면, **대화 녹취록 한 권**을 공책에 쓰든, 카톡에 쓰든, 홈페이지에 쓰든 **녹취록 자체는 같다**.

## 1. 키가 살아 있나

새 파일에서 확인한다.

환경변수 `OPENAI_API_KEY`를 꺼내 본다. 있으면 “예”, 없으면 “아니오 — ~/.bashrc를 확인한다”. 아니오가 나온 사람은 바로 잡는다.

그다음:

```python
from openai import OpenAI
client = OpenAI()  # 인자 없이. 환경변수를 알아서 찾는다
API_MODEL = "gpt-5.4-nano"
```

`OpenAI()`에 키를 직접 넣지 않는다. **지갑을 코드에 적지 않고, 환경이라는 금고에서 꺼내 쓰라**는 뜻이다.

그리고 첫 호출:

- 모델: `gpt-5.4-nano`
- 메시지: “금요일 아침을 기분 좋게 시작하는 한마디를 해 줘.”
- `max_completion_tokens=300` — 답 길이 상한

오후를 위해 미리 `uv pip install streamlit` 해 둔다.

### 도구 상자 하나 — SDK

- **API**: 프로그램끼리 부탁을 주고받는 **약속된 창구**. 우체국 창구와 같다.
- **SDK**: 그 창구를 편하게 쓰라고 회사가 만든 **개발 도구 상자**.
- `openai` 패키지 = OpenAI의 파이썬 SDK.

편지를 직접 쓰면 주소, 우표, 봉투 형식을 다 알아야 한다. SDK는 **대필 비서**다. `create()`라고 하면 비서가 HTTP 편지를 대신 쓴다.

## 2. 응답을 연다 — 문자열이 아니라 객체다

`print(response)`를 하면 한 줄이 아주 길게 나온다.

`ChatCompletion(id=..., choices=[...], usage=...)`

이건 “금요일 아침엔 …”이라는 **글자 하나**가 아니다. **칸이 여러 개인 꾸러미**다. 택배 상자 겉면에 송장, 무게, 내용물이 같이 적혀 있는 것과 같다.

우리가 평소 꺼내 쓰는 별칭은 `response.choices[0].message.content`다.

상자 안 → 선택지 목록 → 첫 번째 → 메시지 → 본문.

`model` 칸을 보면 `gpt-5.4-nano`라고 보낸 것과 달리, 서버가 실제로 돌린 날짜 버전 `gpt-5.4-nano-2026-03-17`이 찍힌다. **주문한 메뉴 이름과, 주방에서 찍힌 제조일이 다른 칸에 있다**고 보면 된다.

`model_dump_json`으로 펼치면, 인터넷을 타고 온 **원본 JSON**이 보인다. 이게 진짜 응답의 원형이다.

### 오늘 계속 쓸 세 자리

1. **`choices[0].message.role`**
   답의 신분. 항상 `assistant`(모델의 답).
   `choices`가 리스트인 이유: 답을 여러 개 받는 옵션 `n`의 흔적. 기본은 1개라서 `[0]`만 쓴다.

2. **`choices[0].finish_reason`**
   멈춘 이유. `stop`이면 **할 말을 다 하고 멈춤**.

3. **`usage`**
   토큰 사용량. 실측 예: 보낸 25, 받은 31, 합계 56.
   **API 요금이 여기서 나온다.** 오후 내내 이 숫자를 본다.

### 오늘의 모델 — gpt-5.4-nano

- OpenAI, 효율(나노)급. 능력을 줄이는 대신 빠르고 싸다.
- 실측 응답 약 1.9초. `temperature` 지원.
- 같은 회사의 **다른 나노 모델은 성질이 다르다.** 바로 확인해 보자, 가 다음 장이다.

### 빈 응답의 범인 — gpt-5-nano

모델 이름만 `gpt-5-nano`로 바꾼다.
내용은 빈 문자열 `''`, 멈춘 이유 `length`, 받은 토큰 300.

범인은 **생각 토큰(reasoning_tokens)** 이다.

어떤 모델은 답하기 전에 속으로 생각한다. `max_completion_tokens=300`은 “답+생각” 공동 예산이다. 생각에 300을 다 쓰면 **입으로 나올 몫이 0**이다.
시험 시간 50분을 연습장에 다 쓰고 답안지는 백지로 내는 것과 같다.

빈 응답이 와도, 응답 꾸러미를 읽을 줄 알면 원인이 보인다.

### 왕복의 정체 — 사실은 HTTP

`with_raw_response.create`로 껍질째 받으면:

- HTTP 상태 200
- 요청 ID (문의할 때 쓰는 일련번호)
- 처리 시간 (서버가 일한 시간. 체감 대기의 나머지는 네트워크)
- 주소 `https://api.openai.com/v1/`

`create()`는 이 주소로 가는 **HTTP POST**다. SDK는 편지 쓰기 대행일 뿐이다.

상태 코드:

- **200** 성공
- **401** 키 문제
- **429** 호출 한도

### 일부러 실패 — 401

잘못된 키 `sk-wrong-key`로 보낸다.
`try/except AuthenticationError`로 **받아서** 처리하면 프로그램이 안 죽는다.

서버 말: `Incorrect API key provided: sk-wrong-key`
오류 메시지 안에 원인이 그대로 있다. **읽으면 된다.**

금요일에 처음 보는 `try/except`다. 본격 재시도·타임아웃은 셋째 날이다.

### 토큰 — 요금의 단위

토큰은 글자도 단어도 아닌 **조각(서브워드)** 이다.

실측:

- “좋은 아침!” → 보낸 토큰 11
- “인공지능은 우리의 일상을 빠르게 바꾸고 있습니다.” → 20
- 같은 뜻 영어 → 15

길수록 토큰이 늘고, 요금은 길이에 비례한다.
같은 뜻인데 한글이 더 잘게 쪼개진다. 모델 사전이 영어 중심이라서다.
**한국어 서비스는 같은 내용도 조금 더 비싸게 오간다**는 뜻이다.

놀이터: https://platform.openai.com/tokenizer — 조각이 색으로 보인다.

## 3. 역할 — 배열 안에 대화의 구조

조각의 신분은 **셋뿐**이다.

| role | 우리말 | 자리 |
|---|---|---|
| `system` | 지시 | 배열 맨 앞. 화면에는 안 보이는 무대 뒤 |
| `user` | 나 | 내가 한 말 |
| `assistant` | 모델의 답 | 응답에서 본 그 값 |

`messages`가 리스트인 이유는 잠시 뒤(멀티턴)에 답이 나온다.

### 같은 질문, 지시만 셋

질문 하나: “감기는 왜 걸려?”
`system`만 바꾼다.

- 초등 선생님 → 쉬운 말, 바이러스·기침·문고리
- 논문 저자 → 상기도 점막, 비말, 상피세포
- 조선시대 어의 → 전하, 기혈과 호흡, 하옵니다

**같은 모델, 같은 질문.** 배열 맨 앞 조각 하나가 답의 성격을 바꿨다.
배우에게 “초등 선생님으로 말해”라고 쪽지를 먼저 주는 것과 같다.

## 4. 멀티턴 — 오늘의 핵심

### 기억 테스트

호출 1: “내 이름은 홍길동이야. 기억해 줘!”
→ “알겠어요, 홍길동님! 다음에도 기억할게요.”

호출 2(완전히 별도): “내 이름이 뭐라고 했지?”
→ “들은 적이 없어요.”

**“기억할게요”라고 말해 놓고 모른다.**

### 무상태(stateless)

왜 몰랐나: 두 호출은 **완전히 남남**이다. 서버 어디에도 우리 대화가 없다.

“기억할게요”는 약속이 아니다. **약속하는 문장을 생성한 것**이다. 그럴듯한 다음 토큰일 뿐이다.

ChatGPT가 기억하는 듯 보였던 것은 **앱이 뒤에서 일한 것**이다.
아침에 새 터미널에서 키가 사라졌던 것과 같다. 새로 열면 잊는다.

식당 종업원이 테이블을 비우면 주문을 전부 잊는다. “다음에 또 그걸로 드릴게요”는 인사치레다. **주문서를 손님이 들고 있어야** 다음에도 이어진다.

### 해결 — 앞 대화를 쌓아서 보낸다

1. user: 내 이름은 홍길동
2. 호출 → 답 받음
3. **그 답도** `assistant`로 append
4. user: 내 이름이 뭐라고 했지?
5. **배열 통째로** 다시 호출
6. → “홍길동님이요!”

비밀은 모델이 아니라 **내가 보낸 배열**에 있었다.

모델의 답도 append해야 한다. 안 하면 모델은 **자기가 한 말도 모른다.**

“왜 리스트인가”의 답: **대화의 과거 전체를 담아야 하니까.**

### 매 턴, 통째로 다시 간다

서버에 “이어서 붙여 줘”가 아니다.
갈수록 두꺼워지는 편지를 **매번 처음부터 다시 부친다.**

턴 1: user 1 (37토큰)
턴 2: user1 + assistant1 + user2 (125)
턴 3: … + user3 (207)
턴 4: … + user4 (310)

짐이 계속 커진다.

### 프레임워크가 감추던 일

Spring AI의 `MessageChatMemoryAdvisor`가 뒤에서 하던 일의 전부다.

파이썬으로는:

```text
append user → 호출 → append assistant
```

대화가 저절로 이어진 것은 마법이 아니라 **배열 관리**였다.

### 토큰이 자라는 표 (실측 예)

5턴, 두 문장씩 답하는 상담사:

| 턴 | 칸수 | 보낸 | 받은 | 누적 |
|---|---|---|---|---|
| 1 | 3 | 37 | 76 | 113 |
| 2 | 5 | 125 | 65 | 303 |
| 3 | 7 | 207 | 86 | 596 |
| 4 | 9 | 310 | 99 | 1005 |
| 5 | 11 | 432 | 41 | 1478 |

받은 토큰은 매번 비슷하다(두 문장).
보낸 토큰만 37 → 432. 질문은 한 줄인데 앞 대화가 실려 가서다.

마지막에 “딱 하나만 골라 줘” → 3턴째 추천을 골라냈다. **맥락이 실려 간 증거**다.

그래프: 회색(받은 것)은 평평, 파랑(보낸 것)만 자란다.
대화가 길수록 **한 마디의 값이 비싸진다.** 컨텍스트 윈도우 한계에 다가간다.

### 이 대화, 얼마였나

공식 단가(2026-08) 어림:

- 보낸 합 1111, 받은 합 367
- 약 $0.000681 ≈ 0.95원
- 1만 명 × 매일 × 30일 ≈ 28만 6천 원

5턴이 1원이 안 된다. **개인 실습에서 요금 걱정은 접는다.**
그런데 사용자 1만 명이면 나노급·두 문장·5턴인데도 월 29만 원이다.
프리미엄 모델은 단가가 수십 배. **모델 선택이 설계 문제**가 된다.

입력 단가와 출력 단가는 다르다. 멀티턴에서 폭주하는 쪽은 **하필 입력(보낸 토큰)** 이다.

### 대화를 파일로

`json.dump(messages)`로 저장.
`json.load`로 복원하면 커널을 꺼도 이어진다.

대화의 실체는 이 파일이 전부다.
ChatGPT 왼쪽 **대화 목록의 정체**가 이것이다. 앱이 배열을 파일/DB에 쌓아 둔 것이다.

## 5. 그릇 2 — 터미널 `chat.py`

새 줄은 사실상 **`while True` + `input()`** 뿐이다.

이미 친 줄:

- `client`, `API_MODEL`
- `messages = [{system}]`
- append user
- create
- append assistant
- usage 출력

돌아가는 모습:

```text
나 > 저녁 뭐 먹지
AI > ...
(배열 3칸 · 보낸 43 · 누적 149)
나 > 매운 게 당기는데
AI > 김치볶음밥, 마라탕...
(배열 5칸 · 보낸 162 · 누적 420)
```

2턴이 1턴을 이어받는다. 맥락이 산다.
각자 자기 주제로 몇 턴 해 보면 오후 메이킹 밑재료가 된다.

## 6. 그릇 3 — 브라우저 `app.py`

Streamlit은 화면이 바뀔 때마다 **파일을 처음부터 다시 실행**한다.
그래서 일반 변수 `messages`는 날아간다.

`st.session_state`는 **재실행에도 살아남는 보관함**이다. 옷장과 같다. 방이 리셋돼도 옷장 안은 그대로다.

| | chat.py | app.py |
|---|---|---|
| 배열 | `messages` | `st.session_state.messages` |
| 계속 도는 힘 | `while True` | Streamlit 재실행 루프 |
| 입력 | `input()` | `st.chat_input()` |
| 출력 | `print()` | `st.chat_message().write()` |

append user / create / append assistant **세 줄은 한 글자도 다르지 않다.**
새 위젯은 입력창·말풍선 둘뿐이다.

실측: 2턴째가 1턴의 《인턴》을 이어받는다. session_state 배열이 통째로 실려 갔기 때문이다.

## 7. 메이킹 타임 (1일차)

과제가 아니라 자유 제작이다.

- 주제·형태·도구 자유
- ChatGPT·Codex 마음껏 (실무의 방식)
- **조건 하나뿐:** `messages` 배열이 결과물 안에 있을 것

씨앗 예: 사극 상담봇, 점심 결정봇, 파일로 남는 일기봇, 끝말잇기봇.
막히면 `app.py` 복사 후 제목·지시문부터.
AI에게 “messages 배열에 system을 넣고…”처럼 **오늘 배운 말로** 물으면 답이 정확해진다.

## 8. 1일차 마무리

오늘 한 것은 하나다.

```text
messages = [ {system}, {user}, {assistant}, {user}, {assistant}, ... ]
```

새 개념은 하나: **배열을 내가 쌓는다.** 나머지는 전부 그릇.

용어:

- SDK: 창구를 편하게 쓰는 도구 상자
- 응답 객체: 칸이 여럿인 꾸러미 (`choices`, `usage`)
- `finish_reason`: `stop`(다 함) / `length`(토큰 한도)
- role: system / user / assistant
- **무상태:** 서버는 대화를 기억하지 않는다 — 오늘의 중심
- 멀티턴: 앞 대화를 쌓아 매번 통째로 다시 보냄

남기고 가는 질문: **5턴에 보낸 토큰이 10배. 아주 긴 대화는 어떻게 하나?**
이 질문을 들고 화요일에 만난다.

# 2일차 (8/18) — 모델의 답을 코드가 읽는다

금요일까지는 **사람이 읽는 글**이었다.
오늘부터는 **프로그램의 입력**이다.

금요일: 대화 = 내가 쌓는 배열 (`chat.py`, `app.py`)
오늘: 답 = 데이터, 모델이 내 함수를 호출
내일: 흘러나오는 답, 챗봇 키우기

저녁에 들고 나가는 것:

- 터미널 `tool_chat.py` — 함수를 실제로 부르는 챗봇
- 브라우저 `tool_app.py` — 말풍선에 **오늘의 실제 날씨**

금요일 챗봇의 **확장**이다. 새 프로젝트가 아니다.

새 주제가 둘이 아니다. **JSON 스키마로 약속을 적는 법 하나**다.

- 오전: 그 약속 → **답의 모양** (구조화 출력)
- 오후: 그 약속 → **내 함수 설명서** (도구 호출)

같은 문법이다. 오전 끝에 눈으로 확인한다.

연휴 복귀: `echo ${OPENAI_API_KEY:0:7}` 가 `sk-proj`처럼 나오면 키 생존.
`python chat.py` 한두 턴. 배열 N칸·보낸 토큰이 찍히면 금요일이 살아 있는 것이다.
오늘 이 배열에 **새 신분 조각 하나**를 추가한다.

## 답에서 데이터로 — 구조화 출력

### 막히는 지점 — 리뷰 1만 개

쇼핑몰 리뷰 하루 1만 개. 모델로 분석하고 코드로 평균 별점을 내고 싶다.

그냥 “이 리뷰를 분석해 줘”라고 하면 실측 답이 이런 식이다.

- 종합 평가…
- 평점으로 치면 중상~상(배송만 빼면 별 4~5 느낌)
- 핵심 불만은 배송 지연…

좋은 분석이다. **코드는 별점을 숫자로 못 꺼낸다.**

문자열 자르기? 다음 호출에 문장이 달라져 깨진다.
“별” 글자 찾기? 이번 답의 별점은 “4~5 느낌”이다.

**코드가 읽으려면 형식이 먼저 약속돼야 한다.**

이력서 만 장을 사람이 읽으면 된다. 컴퓨터로 평균 나이를 내려면 **생년월일 칸이 같은 자리**에 있어야 한다.

### 새 용어 — JSON 스키마

“이 데이터가 어떤 모양이어야 하는지를 JSON으로 적어 둔 설명서.”

오늘 하루 이것 하나. 오전엔 답의 모양, 오후엔 함수 설명서.

---

### 1단 — “JSON으로만 답해라”

`response_format={"type": "json_object"}`
프롬프트에 “JSON으로”를 넣는다.

`json.loads`로 문자열 → 딕셔너리. 통과한다.

실측 키: `language`, `review_text`, `sentiment_overall`, `aspects`, `summary`, `intent`

같은 요청을 **세 번**:

1. 키 5개: language, review_text, sentiment, aspects, summary
2. 키 6개: review_text, sentiment, topics, summary, intent, entities
3. 키 6개: language, review_text, sentiment, aspects, intents, summary

셋 다 유효한 JSON이다. **키 구성이 매번 다르다.**
`data["aspects"]`를 기대한 코드는 2회째에 `KeyError`.

1단이 보장하는 것은 **“유효한 JSON”까지**다.
“내가 원한 모양”은 보장하지 않는다.

공식 문서 원문:
JSON mode will not guarantee the output matches any specific schema, only that it is valid and parses without errors.

“서류는 JSON 봉투에 넣어라”만 시킨 것이다. 안에 sentiment인지 감정인지는 안 정했다.

### 함정 A — “JSON으로”를 뺀다

`json_object`인데 메시지에 JSON이라는 단어가 없으면:

- HTTP 400
- `'messages' must contain the word 'json' in some form`

**400은 친절한 쪽이다.**

| | 401 (금요일) | 400 (오늘 세 번) |
|---|---|---|
| 뜻 | 네가 누군지 모르겠다 | 요청서 양식이 틀렸다 |
| 할 일 | 키 확인 | 서버의 말 읽기 |

오류 처방 1순위: **소리 내어 읽어 보기.**

---

### 2단 — 모양을 손으로 적는다

스키마:

- 전체는 객체(딕셔너리)
- 칸 셋: `sentiment`(문자열), `rating`(정수), `summary`(문자열)
- `required`: 셋 다 필수
- `additionalProperties: False`: 여기 없는 칸은 만들지 말라
- `strict: True`는 `json_schema` 옆에

`description`은 장식이 아니다. 각 칸에 무엇을 넣을지 모델이 읽고 판단하는 **유일한 설명**이다.

이제 세 번 돌려도 키가 항상 `sentiment`, `rating`, `summary`다.
별점만 `data["rating"]`으로 꺼내면 4.

이것이 “유효한 JSON”과 “내가 원한 모양”의 차이다.
이력서 양식을 주고 **빈칸 이름까지 고정**한 것이다.

### 함정 B — strict = 계약서

`additionalProperties` 한 줄만 빼면 또 400.
서버 말: `'additionalProperties' is required to be supplied and to be false`

`strict`는 서버가 “이 모양을 보장하겠다”고 **서명하는 계약**이다.
계약엔 빈틈이 없어야 한다. 전 칸 required + 딴 칸 금지를 명시해야 성립한다.

---

### 3단 — 같은 스키마를 클래스로

```python
class ReviewAnalysis(BaseModel):
    sentiment: str
    rating: int
    summary: str

rp = client.chat.completions.parse(  # create가 아님
    ...,
    response_format=ReviewAnalysis,  # 스키마 대신 클래스
)
result = rp.choices[0].message.parsed  # 이미 파이썬 객체
result.rating  # 4
```

Pydantic: 데이터의 모양을 파이썬 클래스로 적는 도구. FastAPI 등 실무 어디에나 있다.

Spring AI의 `record InquiryResult(...)` + `.entity(...)`와 같은 자리다. **클래스가 곧 스키마.**

3단의 이득: 스키마 딕셔너리도 `json.loads`도 안 쓴다. `rating`은 이미 `int`(타입 검사까지).

### 함정 C — 최상위 클래스 이름은 영문

`class 리뷰분석(BaseModel)`을 `response_format`에 넘기면 400.
스키마 `name` 자리는 영문·숫자·`_`·`-`만.

**최상위만** 검사한다.
안에 품는 클래스 이름은 한글 OK. 필드명도 한글 허용. 그래도 영문 권장.

### 세 단계 표

| | 1단 json_object | 2단 json_schema+strict | 3단 parse+Pydantic |
|---|---|---|---|
| 유효한 JSON | O | O | O |
| 내가 원한 모양 | X | O | O |
| 파이썬 객체·타입 | X | json.loads 필요 | O |

오른쪽으로 갈수록 내가 쓰는 코드는 줄고, 서버가 지켜 주는 것은 늘어난다.
실무 기본값은 3단. 1·2단은 **왜 그런지를 알기 위해** 지나온 자리다.

`ReviewAnalysis.model_json_schema()`를 찍으면 2단에서 손으로 쓴 그 문법이 나온다.
손과 클래스는 **같은 약속의 두 표기법**이다. 이 화면을 기억한다. 오후에 정확히 이 모양을 다시 쓴다.

### 여러 건을 한 번에

안쪽 클래스 `리뷰`(한글 OK, 최상위가 아님): sentiment, rating, comment
최상위 `ReviewBatch`(영문): `results: List[리뷰]`

리뷰 4건 실측 후 평균 별점 2.5.
모델의 답으로 평균 계산. **리뷰 1만 개 문제가 원리상 해결**된다.

모양은 고정. 내용(별점·감정)은 모델의 판단이라 실행마다 다를 수 있다.

### 놀거리 — 퀴즈

`Question`: question, choices, answer(int), explanation
`answer`가 **데이터**라서 채점 프로그램이 성립한다.

답이 글이었다면 “몇 번이 정답인지”를 코드가 알 길이 없다.

시연은 한국사 퀴즈. 직접 푸는 것은 메이킹 타임.

### 실패 다루기

`parsed`가 None이면 원본부터 본다.

- `msg.content` — 거절 문구가 있거나
- `finish_reason` — `length`로 잘렸거나

금요일과 같은 순서. 비면 `finish_reason`부터. 버그라고 단정하기 전에 원본 응답부터.

오후 예고: `content`가 `None`인데 **정상인 경우**가 있다.

## 도구 호출 — 같은 약속으로 함수 설명

### 모델은 지금 날씨를 알까

“지금 서울 날씨, 우산 챙겨야 해?”
실측: “실시간은 직접 조회하지 못해요. 예보가 있으면 챙기세요…”

학습이 끝난 시점의 지식뿐이다. **‘지금’과 이어진 선이 없다.**
그 선을 이어 주는 것이 오후, 도구 호출이다.

백과사전은 서울이 어디인지는 안다. 창밖 기온은 모른다. **온도계는 내가 들고 재야** 한다.

### 걸음 1 — 함수 + 설명서

`get_weather(city, latitude, longitude)`
open-meteo에 HTTP. 키 없이 무료.

`tools` 배열 안에:

- name: 모델이 부를 이름
- description: 모델에게 주는 **유일한 힌트**. 아직 아무도 이 함수를 부르지 않음
- parameters: **오전의 그 JSON 스키마**

오전 `model_json_schema()`와 오후 `parameters`는 같은 문법이다.
약속을 적는 법 하나, 쓰는 자리 둘.

### 걸음 2 — 이상한 답

`tools=tools`를 싣고 같은 질문을 보낸다.

- 내용: `None`
- 멈춘 이유: `tool_calls` (금요일이 배운 `length`가 아님)

오류가 아니다.
**“말로 답하는 대신, 네 함수를 불러 달라”는 정상 응답**이다.

금요일에 빈 답이면 `finish_reason`부터 보라고 했다. 그대로다.

### 요청서 해부

- 부르라는 함수: `get_weather`
- 인자(JSON **문자열**): `{"city":"서울","latitude":37.5665,"longitude":126.978}`
- 꼬리표 `id`: `call_...`

우리는 좌표를 준 적이 없다. **모델이 채웠다.**

아는 것: 서울의 좌표 (학습된 지식, 참값과 소수 둘째 자리까지 일치)
모르는 것: 지금 기온 (어떤 학습으로도 알 수 없음) → 함수에 맡김

**이 경계선이 도구 호출의 전부다.**

### 걸음 3 — 실행은 내 코드

```python
args = json.loads(tc.function.arguments)  # 문자열 → 딕셔너리
result = get_weather(**args)  # 딕셔너리를 인자로 펼침
```

실측: `서울 기온 27.8도, 습도 70%, 강수 0.0mm, 바람 4.0m/s`

이 줄을 실행한 것은 **내 파이썬**이다. 모델은 서버 저편에서 요청서를 썼을 뿐이다.
창밖과 비교해 보라. 실행 시각마다 다르다.

### 걸음 4 — 결과를 배열에 넣고 다시 보내기

1. `messages.append(msg)` — 모델의 **요청서 자체**를 기록에
2. `role: "tool"`, `tool_call_id: tc.id`, `content: result`
3. 다시 `create`

실측 최종 답: 27.8도, 습도 70%, 강수 0, **우산은 굳이 안 챙겨도…**
멈춘 이유: `stop`

신분이 **넷**: system, user, assistant, **tool**

요청서를 먼저 붙이고 tool 조각을 붙인다. 순서가 빠지면 400(짝 없는 조각).
택배 송장 번호 없이 물건을 반송하면 물류센터가 거절하는 것과 같다.

### 네 걸음 한 바퀴

1. 함수 설명서를 실어 보낸다 (`tools`)
2. 모델의 요청서 (`content=None`, `finish_reason=tool_calls`)
3. 실행은 내 코드 (`get_weather(**args)`)
4. 결과를 배열에 넣어 다시 보낸다 (`role: tool`) → 최종 답, 실제 기온이 문장 속에

**모델은 함수를 실행하지 않는다. 부르라고 말할 뿐이다.**

### 누가 누구에게 말하나

화살표가 전부 **가운데 줄(내 파이썬)** 에 붙는다.

- 내 파이썬 ↔ 모델 (messages + tools / 요청서 / 최종 답)
- 내 파이썬 ↔ open-meteo (실제 HTTP)
- **모델 ↔ open-meteo 화살표 없음.** 둘은 서로 모르는 사이다.

키가 필요한 곳은 모델 쪽 하나뿐이다. open-meteo는 키 없이.

식당(모델)은 밖에 못 나간다. “시장에 가서 온도 재 와”라고 **쪽지만** 쓴다. 심부름은 내가 한다. 시장(open-meteo)은 식당을 모른다.

### 도구가 필요 없는 질문

“안녕! 넌 뭘 할 수 있어?” + 같은 `tools`

- `finish_reason: stop`
- 요청서: None
- 평범한 인사

도구를 실었다고 항상 부르는 것은 아니다. **고르는 건 모델**이다.
여러 도구를 등록해도 알아서 골라 쓰던 그 성질이다.

## 루프에 태우기 — tool_chat.py → tool_app.py

### 모델 ≠ 계산기

`739521468 * 8462137`

- 모델: 6256828708760116
- 파이썬: 6257931976657116

앞 세 자리만 같고 넷째부터 어긋난다.
자릿수는 그럴듯한데 값이 틀리다. **그럴듯한 다음 토큰을 만드는 기계**이므로.

아까는 모델이 **모르는 것**(실시간). 이번엔 **못 하는 것**(정밀 계산).
우연히 맞을 수도 있으니 숫자를 바꿔 몇 번 더 해 보라고 한다.

### calc — eval 앞에 검사

`expression`은 모델이 만든 문자열이다. 검사 없이 `eval`하면 모델(또는 모델을 속인 사용자)이 시키는 무엇이든 내 컴퓨터에서 돈다.

도구는 내 코드다. **무엇을 통과시킬지도 내가 정한다.**
숫자·사칙·괄호·공백·%만. `**` 금지. 길이 80 초과 거부.
`eval`은 `__builtins__`를 비운다.

실행이 내 코드라면 책임도 내 것이다. 검사 두 줄이 곧 **문**이다.
프레임워크에선 메서드 타입이 문 역할. 파이썬 `eval`은 문이 없어서 문은 우리 몫이다.

### 여러 장 오는 요청서

“부산 날씨 알려 주고, 저 곱셈도 계산해 줘.”

상한 5바퀴. 요청서가 없으면 말로 답한 것 → 끝.
`for tc in msg.tool_calls` — **여러 장이어도 전부**.

실측 1바퀴에 요청서 두 장: get_weather + calc. 최종 답에 둘 다.

`tool_calls[0]`만 집는 코드는 여기서 깨진다. `for`가 필수다.

모델이 결과를 보고 또 부를 수도 있어서 “요청서가 없을 때까지” 돈다.
아까 틀렸던 곱셈이 도구를 거치니 정확하다.

이 루프에 도구를 계속 더 얹으면 — **요즘 말하는 에이전트의 뼈대**다. 오늘은 여기까지.

### tool_chat.py

금요일 `chat.py`에서 달라지는 곳:

- 도구 둘
- ② 자리가 루프

① append user, ③ append assistant는 그대로다.

5바퀴를 다 돌면 `content`가 None일 수 있다. 빈 답 방지 문구를 넣는다. `None`이 배열에 실리면 다음 턴 400이다.

실측: “서울이랑 부산 날씨 비교” → 도구 로그 두 줄 → 비교 문장. 배열 14칸, 보낸 토큰 603.

한 문장에 요청서 두 장. 배열이 금요일보다 빨리 자란다. 요청서·tool 조각도 배열에 산다. 토큰도 같이.

각자 실행: 내 도시 날씨 + 아무 곱셈. “두 도시를 한 문장으로”까지 확인.

### 배열은 얼마나 빨리 자라나

금요일 chat.py는 턴마다 구조상 +2칸(user+assistant).
도구를 쓴 턴은 +4, +5.

늘어난 만큼 = 요청서 + tool 조각.
도구를 안 쓴 턴은 금요일과 똑같이 +2.

같은 4턴을 펼치면:

- 턴1: user, assistant (+2)
- 턴2: user, assistant, 요청서, tool, assistant (+4)
- 턴3: user, assistant, 요청서 2장, tool, tool, assistant (+5)
- 턴4: user, assistant (+2)

보낸 토큰도 239 → 670처럼 계단이 커진다. 값은 각자 다르다. **계단이 커지는 자리만 보라.**

### tool_app.py

달라지는 곳은 **그릇뿐**.

- 배열: `st.session_state.messages`
- 왕복 루프: `tool_chat.py`와 동일
- `print` 대신 `st.caption` — 도구 로그가 화면에
- 말풍선 = user·assistant만. 요청서·tool은 무대 뒤

금요일 챗봇은 대화만.
오늘 챗봇은 **진짜 세계의 값 + 정확한 계산**.

## 두 자리를 나란히

오늘 배운 것 = 하나.

| | 오전 구조화 출력 | 오후 도구 호출 |
|---|---|---|
| 스키마가 설명하는 것 | 모델 답의 모양 | 내 함수의 사용법 |
| 실리는 자리 | `response_format` | `tools[].function.parameters` |
| 모델이 돌려주는 것 | 그 모양의 JSON | “이걸 불러라”는 요청서 |
| 실행하는 자 | 없음 (데이터로 끝) | 내 코드 |
| 결과가 가는 곳 | 내 변수 | `role:tool` 조각 → 배열 → 다시 모델 |

오전엔 약속으로 답을 받았고, 오후엔 약속으로 함수를 맡겼다.

Spring AI `@Tool` 한 줄이 감추던 것: 설명서 작성, 요청서 받기, 실행, 재투입+루프.
이제 그 안이 보인다. 프레임워크를 다시 만나도 무섭지 않은 이유다.

공식 문서를 검색하면 예제가 `client.responses.create` 형태일 수 있다. 금요일에 이름만 짚은 최신 API다.
개념은 전부 같다. 스키마, strict, 요청서, 네 걸음.
우리가 쓰는 `chat.completions`도 계속 지원된다. 개념 설명은 그대로 읽고, 코드 모양만 오늘 배운 것으로.

## 2일차 마무리

모델의 답 → 프로그램의 입력.

약속(JSON 스키마) 하나 — 쓰는 자리 둘.

- 답의 모양: json_object → json_schema → parse. 유효한 JSON ≠ 내가 원한 모양
- 함수 설명: 설명서 → 요청서 → 내가 실행 → 재투입. 모델은 부르라고 말할 뿐

네 걸음 다시: 설명서 · 요청서 · 내 실행 · 재투입

용어:

- JSON 스키마: 모양을 JSON으로 적은 설명서 — 오늘의 중심
- 구조화 출력: 답을 약속된 모양의 데이터로
- strict: 모양을 계약으로 강제
- Pydantic: 모양을 클래스로. 클래스가 곧 스키마
- 도구 호출: 함수를 설명해 두면 모델이 “불러 달라”를 데이터로 답함
- `tool_calls`: 요청서 목록. `content=None`과 함께
- `role: "tool"`: 넷째 신분. 함수 실행 결과

남기고 가는 질문: **도구를 계속 더 얹고, 모델이 알아서 골라 부르게 두면 — 그건 뭐라고 부를까?**
답은 뒤 과목. 뼈대는 이미 손 안에.
