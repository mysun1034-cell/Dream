공개

지식 목표

응답을 완성 후 한 번에 받는 call().content()와 토큰이 오는 대로 흘려보내는 stream().content()(Flux<String>)의 차이와 사용자 체감(TTFT)을 설명할 수 있다. SSE(text/event-stream)와 브라우저 EventSource로 스트리밍을 소비하는 구조, 그리고 InMemory ChatMemory를 JDBC(PostgreSQL)로 바꾸면 대화가 앱·DB 재시작 후에도 영속된다는 것을 설명할 수 있다.

기능 목표

ChatClient의 stream().content()를 SSE 엔드포인트로 감싸고(공백 보존을 위한 JSON 청크, 무한 재연결 방지를 위한 done 이벤트+close), Docker로 PostgreSQL을 기동해 JdbcChatMemoryRepository로 대화를 영속시키며, ChatMemory.get()으로 history를 조회하고, CORS를 열어 React(EventSource) 프론트엔드와 연동된 하나의 완결 앱을 완성할 수 있다.

산출물 목표

day06-streaming-react-starter(Day5 헬프데스크 코어, 인메모리 memory) 위에 스트리밍 엔드포인트·JDBC ChatMemory·history·CORS를 얹고, npm create vite로 만든 React 채팅 화면과 연동해 front→back→ai→db가 이어진 완결 앱을 완성한다. 실제 문의로 로딩→스트리밍→완료와 새로고침 시 대화 복원을 확인하고 README·GitHub URL과 미니 프로젝트 2 주제 후보를 제출한다.
