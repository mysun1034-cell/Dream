공개

지식 목표

미니 프로젝트 2가 이번 파트에서 배운 Java·Spring Boot·Spring AI(백엔드)와 React(프론트)로 '무엇을 만들 수 있는지'의 범위를 설명하고, 좋은 팀 주제의 조건(스택으로 실현 가능·범위가 적당·AI가 곁다리가 아닌 핵심 가치)을 판단할 수 있다. 또한 팀이 한 레포에서 충돌 없이 함께 작업하기 위한 Git 협업 워크플로우(main+dev+feature 브랜치 전략·브랜치 최신화·PR 리뷰·Issue/Project Board)를 설명할 수 있다.

기능 목표

팀을 편성하고, 이번 파트 스택으로 실현 가능한 프로젝트 주제를 정해 기획서(project-brief)로 구체화하며, 팀 GitHub 레포를 main+dev+feature로 세팅(dev 생성·collaborator 초대·.gitignore·Project Board)하고 할 일을 Issue로 쪼개 담당을 배정할 수 있다. 오전에 익힌 브랜치 최신화(git merge origin/dev)·충돌 해결·PR 리뷰를 팀 레포에서 실제로 적용할 수 있다.

산출물 목표

팀 편성을 마치고, 확정한 주제와 기획서(project-brief.md), main+dev+feature로 세팅된 팀 GitHub 레포와 초기 Issue가 올라간 Project Board를 만든 뒤, 오늘 리뷰 세션에서 팀별로 '주제·핵심 기능·기획'을 발표한다.

Java 21 JDK
IntelliJ IDEA 또는 Visual Studio Code
Spring Boot 4.1.x
Spring AI 2.0.0 GA
Google GenAI / Gemini
Gradle
Node.js / npm
Vite + React (JS)
GitHub (Issues · Projects · Pull requests)

팀 편성 & 팀 레포 세팅

팀을 꾸리고, 함께 작업할 GitHub 레포를 main+dev+feature 기준으로 세팅한다.

왜 main이 아니라 dev에서 작업하는지 설명할 수 있는가?
브랜치 최신화(git merge origin/dev)를 언제 하는지 말할 수 있는가?

주제 확정 & 기획서

이번 파트 스택으로 실현 가능한 주제를 정하고 기획서로 구체화한 뒤, 할 일을 Issue로 쪼갠다.

이 주제에서 AI(Spring AI)가 없으면 안 되는 이유를 한 문장으로 말할 수 있는가?
이번 주에 '되는 최소'가 무엇인지 팀이 합의했는가?

주제·기획 발표 (리뷰 세션)

리뷰 세션에서 팀 주제·기획을 발표하고 피드백을 받아 반영한다.

발표 후 우리 팀이 내일 가장 먼저 착수할 Issue는 무엇인가?
제출 안내

팀 단위로 제출한다: (1) 팀 GitHub 레포 URL(dev 브랜치·collaborator·.gitignore 포함), (2) project-brief.md(주제·문제·타깃·핵심 기능·화면/API 개요·역할·이번 주 마일스톤), (3) 초기 Issue가 올라간 Project Board, (4) 발표 자료(슬라이드 또는 보드 화면). 실제 API Key가 코드·설정에 하드코딩되지 않았는지 점검한다.

다음 수업 연결

내일부터 본격 개발이다. 오늘 세운 브랜치 전략(main+dev+feature)과 Issue/Project Board 위에서 각자 feature 브랜치로 담당 Issue를 진행하고, 최신화→PR→리뷰→merge를 반복한다. 기획서와 보드가 매일의 나침반이 된다.
