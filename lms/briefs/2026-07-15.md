지식 목표

Day3가 구현한 동작하는 백엔드 API 위에서 React가 그대로 fetch해야 프론트·백이 한 서비스로 이어짐을 이해하고, CORS(5173↔8080이 다른 출처), fetch 요청/응답의 필드명·타입이 계약과 100% 일치해야 하는 이유, 구조화 응답을 화면에 나눠 렌더링하는 것과 로딩/에러 상태 처리, Spring AI 기능을 최소 2개 매핑하는 것과 README(실행 방법)의 필요성, 키는 백엔드 전용이라는 원칙을 설명할 수 있다.

기능 목표

백엔드에 CORS를 설정하고 React에서 fetch POST로 계약(URL·Method·요청/응답 필드)을 그대로 호출해 5173→8080 호출을 성공시키며, 단건 구조화 응답(category·answer)을 화면에 나눠 렌더링하고 로딩/에러 상태를 처리해 MVP 한 흐름이 화면에서 동작하게(보이는 데모) 만들 수 있다. 데모가 서면 2번째 기능을 풀스택(Controller→Service→저장 + 화면)으로 지어 Spring AI 기능을 최소 2개 매핑하고, README(실행 방법) 초안을 착수하며 동결할 데모 경로를 지정할 수 있다(2번째 기능은 오후 리프트라 미완 시 Day5 오전에 마무리).

산출물 목표

버튼 클릭 → AI 결과가 화면에 뜨는 동작 화면(데모 캡처 1장), 계약대로 호출하는 React 코드와 백엔드 CORS 설정, 구조화 응답을 나눠 렌더링한 UI, 통합된 남은 기능·Spring AI ≥2개 매핑, README 초안, 동결 대상 데모 경로, 오늘 작업이 반영된 PR·Project Board.
