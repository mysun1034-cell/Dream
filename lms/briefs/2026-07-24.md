공개

지식 목표

RNN이 긴 문장의 앞부분을 잊는 이유를 '같은 가중치를 거리만큼 반복해서 곱한다'는 구조로 설명하고, 1보다 조금 작은 배율도 반복하면 사라지고 조금 큰 배율은 폭발한다는 것을 수치로 말할 수 있다. 셀 상태(c_t)와 은닉 상태(h_t)가 어떻게 다른지, 게이트가 왜 sigmoid이고 후보 셀 상태만 tanh인지 구분해 설명할 수 있다. c_t = f_t⊙c_{t-1} + i_t⊙c̃_t 에서 가운데 덧셈이 왜 결정적인지, 그리고 LSTM이 기울기 소실을 없애는 것이 아니라 완화한다는 것을 말할 수 있다. GRU가 게이트 2개와 셀 상태 없음으로 같은 아이디어를 더 적은 부품으로 구현한다는 것을 설명할 수 있다.

기능 목표

nn.RNN 자리에 nn.LSTM·nn.GRU를 갈아 끼우고, LSTM만 (h_n, c_n) 짝으로 반환된다는 것을 알고 풀어서 받을 수 있다. RnnClassifier·LstmClassifier·GruClassifier 세 클래스를 나란히 읽고 어디가 다른지 짚을 수 있으며, GRU 분류기와 훈련 루프를 처음부터 직접 작성할 수 있다. num_layers로 층을 쌓고 순환 dropout을 걸 수 있으며, hidden[-1]과 hidden[0]이 층수에 따라 무엇을 가리키는지 torch.equal로 직접 검증할 수 있다. 같은 설정을 시드만 바꿔 여러 번 돌려 흔들림 폭을 재고, 모델 간 차이가 그 폭보다 클 때만 우열을 말하는 절차를 실행할 수 있다.

산출물 목표

RNN·LSTM·GRU를 같은 데이터·같은 설정에서 시드 3개로 각각 훈련해 평균과 흔들림 폭을 담은 비교표 한 장을 만들고, 각 쌍에 대해 '낫다고 말해도 된다 / 차이를 확인하지 못했다' 중 하나로 판정을 적는다. 미션 B-1에서 GRU 분류기와 훈련 루프를 TODO 6개를 채워 완성하고 검증 정확도를 출력한다. 미션 A-2에서 RNN이 틀린 리뷰를 LSTM이 구제한 건수와 반대로 놓친 건수를 함께 세어, 게이트의 이득을 한쪽만 세지 않고 정직하게 기록한다.

관찰 — 세 모델을 비교하고, 그 비교를 믿어도 되는지 판정하기

RNN·LSTM·GRU를 같은 조건에서 여러 번 훈련해 평균과 흔들림 폭을 재고, 모델 간 차이가 그 폭보다 큰지로 우열을 판정한다. 이어서 RNN이 틀리던 실제 리뷰를 LSTM에 그대로 넣어 게이트가 무엇을 구해 냈고 무엇을 놓쳤는지 함께 센다.

표에 시드와 설정이 함께 적혀 있는가
'LSTM이 GRU보다 낫다'처럼 근거 없는 단정을 쓰지 않았는가
짧은 문장 실험 결과를 증거로 쓰지 않았는가 (모델은 긴 리뷰로 훈련됐다)

응용 — GRU를 처음부터 직접 만들고, 층을 쌓아 hidden을 뜯어보기

지금까지 가져다 쓰던 클래스를 손으로 만들어 본다. GRU 분류기와 훈련 루프를 빈칸부터 채워 완성하고, 이어서 층을 쌓았을 때 hidden의 무엇이 달라지고 무엇이 그대로인지 직접 재서 확인한다.

훈련 5단계에서 zero_grad()를 backward() 앞에 두었는가

평가 전에 model.eval()을 호출했는가

도전 — LSTM 내부 계산을 손으로 검증하고, 게이트 값을 관찰하기

nn.LSTM이 내부에서 하는 계산을 직접 재현해 라이브러리 결과와 일치시킨다. 이어서 훈련된 모델에서 단어별 게이트 값을 꺼내 보되, 근거가 약한 해석을 지어내지 않는 태도까지 함께 연습한다.

게이트 네 벌의 순서를 i·f·g·o로 맞췄는가 (순서를 바꾸면 절대 일치하지 않는다)
은닉 32칸의 평균 하나로 특정 단어에 대한 이야기를 지어내지 않았는가

1. 출발점 — 계산기로 확인되는 사실 하나

거창한 이론이 아닙니다. 같은 수를 계속 곱하면 어떻게 되는가에서 시작합니다.

계산기를 꺼내서 직접 해 보세요. 먼저 짐작해 보고 답을 확인하면 더 좋습니다.

배율	10번 곱	20번 곱	30번 곱
0.9	0.349	0.122	0.042
1.0	1	1	1
1.1	2.59	6.73	17.4

0.9는 1에서 겨우 0.1 모자랄 뿐인데 30번 곱하면 0.04까지 떨어집니다. 1.1은 1보다 겨우 0.1 클 뿐인데 30번이면 17을 넘습니다.

1보다 조금만 작으면 사라지고, 조금만 크면 폭발합니다. 딱 1인 지점은 칼날처럼 좁고, 훈련하는 동안 그 자리에 머물러 주지도 않습니다.

RNN이 하는 일이 정확히 이것입니다
h_t = tanh( W_x·x_t + W_h·h_{t-1} + b )
                      └──────┘
                   매 스텝 같은 W_h 를 곱한다


훈련할 때는 반대 방향으로, 마지막에서 앞쪽 단어까지 신호를 되돌려 보내야 합니다. 그러려면 두 단어 사이 거리만큼 같은 W_h 를 반복해 통과해야 합니다. 위의 그 반복 곱입니다.

그래서 앞쪽 단어에 도달하는 기울기(학습 신호)는 거리에 대해 (배율)^거리 로 변합니다. 배율이 1보다 작으면 기울기 소실, 크면 기울기 폭발입니다.

실전은 거의 항상 소실 쪽입니다. tanh 의 기울기가 1을 넘지 않아 곱해질수록 더 눌러 주거든요.

📌 100단어 문장이면 맨 앞 단어까지 거리가 99입니다. 0.9^99 는 사실상 0입니다. 모델이 게을러서가 아니라, 학습 신호가 앞쪽에 아예 도착하지 않는 것입니다.

오늘의 답 — 곱하지 말고 더하자

곱해서 눌리는 길 말고, 더해서 흘러가는 길을 하나 냅니다. 그리고 그 길에 문(gate)을 달아 무엇을 얼마나 통과시킬지 정합니다.

이 한 문장이 오늘 배울 전부입니다. LSTM도 GRU도 이 아이디어의 서로 다른 구현입니다.

2. 게이트란 무엇인가 — 01_gate_intuition.py ★

오늘 이론의 심장입니다. 훈련이 없어 금방 끝나지만, 여기를 이해하면 나머지는 코드 문제입니다.

하나가 늘었습니다

RNN이 나르던 것은 은닉 상태 h 하나였습니다. LSTM은 하나를 더 나릅니다.

기호	이름	무엇인가	비유
h_t	은닉 상태 (hidden state)	지금 이 순간의 요약. 밖으로 내보내는 값	말하는 내용
c_t	셀 상태 (cell state)	장기 기억. 밖으로 안 나가고 안에서만 흐릅니다	속으로 기억하는 것

회의록을 쓴다고 해 봅시다. c 는 머릿속에 계속 담고 있는 전체 맥락이고, h 는 지금 말로 꺼내는 요약입니다. 둘은 다릅니다. 다 기억하지만 다 말하지는 않습니다.

게이트는 sigmoid로 만든 '수도꼭지'입니다

게이트의 정체는 단순합니다 — sigmoid를 통과시킨 숫자입니다. sigmoid는 어떤 실수든 0~1 사이로 눌러 주니, "얼마나 통과시킬까"의 비율로 쓰기 딱 맞습니다.

  -6.0      →  0.002
  -2.0      →  0.119  ██
  +0.0      →  0.500  ██████████
  +2.0      →  0.881  █████████████████
  +6.0      →  0.998  ███████████████████

0에 가까우면 → 거의 막습니다 (잊습니다)
1에 가까우면 → 거의 다 통과합니다 (기억합니다)

값 × 0.02 = 거의 사라짐 · 값 × 0.98 = 거의 그대로 남음. 게이트는 곱해지는 숫자라는 걸 여기서 잡고 갑니다.

forget 게이트 한 스텝을 손으로 계산해 봅시다

LSTM에는 게이트가 3개지만 모양은 셋 다 같습니다. 가중치만 다릅니다. 그러니 하나만 손으로 굴려 보면 나머지도 압니다.

RNN 셀:        h_t = tanh   ( W_x·x_t  + W_h·h_{t-1} + b )
오늘 (forget): f_t = sigmoid( W_xf·x_t + W_hf·h_{t-1} + b_f )
                     ↑ tanh 대신 sigmoid — '값'이 아니라 '비율'을 만들기 때문


식의 생김새는 RNN 셀과 똑같습니다. 활성함수만 바뀝니다.

h_prev = 0.5      # 직전 은닉 상태
c_prev = 2.0      # 오늘 새로 등장: 직전 셀 상태 = 장기 기억
x_t = 1.0         # 지금 단어

W_xf, W_hf, b_f = 0.6, 0.8, 0.0     # forget 게이트의 가중치

z    = 0.6×1.0 + 0.8×0.5 + 0.0 = 1.0
f_t  = sigmoid(1.0) = 0.731

→ forget 게이트가 73% 만큼 열렸습니다.
  이전 기억 c_{t-1}=2.0 중 1.462 를 남기고 나머지는 잊습니다.


✅ 이 값은 누구 화면에서나 똑같이 나옵니다. 직접 검산해 보세요.

⚠️ 헷갈리기 쉬운 곳 — tanh와 sigmoid
  tanh(1.0)    = 0.762   ← 값 (−1~1)
  sigmoid(1.0) = 0.731   ← 비율 (0~1)


같은 z=1.0 인데 결과가 0.762와 0.731입니다. 두 숫자가 비슷해서 반드시 섞습니다.

📌 문(01)과 내용물(−11)은 다른 것입니다. 문은 "얼마나"라서 0~1이면 되고, 내용물은 "무엇을"이라서 음수도 있어야 합니다.

★ 왜 이게 기울기 소실을 완화하나 — 덧셈 경로

셀 상태는 이렇게 갱신됩니다.

c_t = f_t ⊙ c_{t-1}  +  i_t ⊙ c̃_t
      └── 이전 기억을 얼마나 남길지    └── 새 정보를 얼마나 넣을지


핵심은 가운데 + 입니다.

RNN은 h 가 매 스텝 행렬을 곱해 통째로 새로 만들어졌습니다. LSTM의 c 는 이전 값이 그대로 이어지고 거기에 더해집니다. 행렬 곱이 반복되지 않으니 §1에서 본 지수적 붕괴가 없습니다.

 스텝 | RNN 방식 (행렬 곱 반복) | LSTM 셀 상태 (게이트+덧셈)
------+-------------------------+---------------------------
   1  |                    0.9  |                     0.950
  10  |                  0.349  |                     0.599
  30  |                 0.0424  |                     0.215


⚠️ 과장하지 마세요. "게이트를 열면 기억이 그대로 흘러간다"는 틀린 말입니다. 0.95^30 = 0.215 — 게이트가 꽤 열려 있어도 줄긴 줍니다. LSTM은 기울기 소실을 없애는 게 아니라 완화합니다.

★★ 그럼 무엇이 결정적인가 — 고를 수 있게 되었다는 것
    f=0.90 → 0.042
    f=0.95 → 0.215
    f=0.99 → 0.740
    f=1.00 → 1.000     ← 그대로 보존


오늘 가장 중요한 문장입니다.

RNN은 W_h 가 고정이라 모든 단어·모든 스텝에 똑같이 적용됩니다 — 선택의 여지가 없습니다. LSTM은 f 를 데이터로 배웁니다. 중요한 기억이면 문을 1에 가깝게 열 수 있습니다.

게이트의 본질은 "잘 잊는 것"이 아니라 "무엇을 남길지 고를 수 있게 된 것"입니다.

게이트 3개 — 각각 무엇을 정하나

손계산은 forget 하나만 했습니다. 나머지 둘은 하는 일만 잡으면 됩니다.

게이트	기호	무엇을 정하나	한 마디
forget	f_t	지난 기억 c_{t-1} 중 얼마나 남길까	"이거 계속 들고 갈까?"
input	i_t	지금 만든 후보 c̃_t 를 얼마나 넣을까	"이건 받아 적을까?"
output	o_t	셀 상태 중 얼마나 밖으로 내보낼까	"지금 이 말을 꺼낼까?"

그리고 게이트가 아닌 것이 하나 더 있습니다.

	기호	활성함수	왜
후보 셀 상태	c̃_t	tanh (−1~1)	게이트가 아니라 넣을 값 자체라서 음수도 필요합니다
c_t = f_t ⊙ c_{t-1} + i_t ⊙ c̃_t        ← 기억 갱신 (덧셈 경로)
h_t = o_t ⊙ tanh(c_t)                   ← 그중 얼마를 말할지


문 세 개가 다 sigmoid고, 내용물 하나만 tanh입니다. 왜? 문은 '얼마나'라서 0~1이면 되고, 내용물은 '무엇을'이라서 음수도 있어야 하니까요.

3. 코드로 옮기기 — 02_lstm_swap.py

개념은 끝났습니다. 이제 파이토치가 이걸 어떻게 담아 두었는지 봅니다.

결론부터 말하면 RNN을 쓸 줄 알면 LSTM도 쓸 줄 압니다. 딱 한 가지, 결과를 받는 모양만 다릅니다.

먼저 RNN — 받는 모양을 확인해 둡니다
B, L, E, H = 2, 5, 8, 4     # 배치 2 · 길이 5 · 임베딩 8 · 은닉 4
x = torch.randn(B, L, E)    # 임베딩까지 끝난 상태라고 칩시다

rnn = nn.RNN(E, H, batch_first=True)
out, h_n = rnn(x)

nn.RNN  → output: (2, 5, 4) · hidden: (1, 2, 4)
  hidden[-1]: (2, 4)  ← 문장 전체의 요약. 이걸 분류기에 넣습니다

LSTM은 하나를 더 나릅니다 — 그래서 받는 모양이 다릅니다

앞에서 배운 그대로입니다. LSTM은 은닉 상태 h 말고 셀 상태 c 도 함께 나릅니다. 나르는 게 둘이니, 돌려주는 것도 둘입니다. 그래서 짝으로 묶어서 줍니다.

output, h_n        = nn.RNN(...)(x)      ← 은닉 하나
output, (h_n, c_n) = nn.LSTM(...)(x)     ← 은닉 + 셀, 짝으로 묶여서 옵니다
output, h_n        = nn.GRU(...)(x)      ← 은닉 하나 (RNN과 같음)

lstm = nn.LSTM(E, H, batch_first=True)
output, (h_n, c_n) = lstm(x)        # 이렇게 풀어서 받습니다

output: (2, 5, 4)  (배치, 길이, 은닉)
h_n   : (1, 2, 4)  (층수, 배치, 은닉)  ← 마지막 은닉 상태
c_n   : (1, 2, 4)  (층수, 배치, 은닉)  ← 마지막 셀 상태(장기 기억)

h_n[-1]: (2, 4)  ← RNN 때와 똑같은 모양. 그대로 분류기에 넣으면 됩니다


💡 분류에는 h_n 만 씁니다. c_n 은 LSTM이 내부에서 기억을 나르는 용도입니다. 직접 꺼내 쓸 일은 거의 없지만, "그런 게 하나 더 있다"는 걸 알아야 짝을 풀 수 있습니다.

꼭 외울 표
	두 번째 반환값	셀 상태
nn.RNN	h_n	없음
nn.LSTM	(h_n, c_n) 짝	있음
nn.GRU	h_n	없음

⚠️ 짝을 안 풀면 조용히 틀립니다. output, hidden = lstm(x) 로 받고 hidden[-1] 을 쓰면, 그건 h_n 이 아니라 c_n 입니다. 그 자리에서 터지지 않고 한참 뒤 BCELoss 에서 shape 오류로 나타나서 원인을 찾기 어렵습니다. 오늘 코드는 처음부터 풀어서 받게 써 두었으니, 정상 경로만 따라가면 만날 일이 없습니다.

모델 세 개를 따로 만들어 두었습니다

model.py 에 RnnClassifier · LstmClassifier · GruClassifier 가 각각 있습니다. 하나로 합쳐 놓고 인자로 종류를 고르게 할 수도 있지만, 그러면 코드를 봐도 지금 어느 모델을 보고 있는지 드러나지 않습니다. LSTM이 궁금하면 LstmClassifier 하나만 읽으면 되게 했습니다.

# 📁 day04/model.py
class RnnClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim=32, hidden_size=32,
                 num_layers=1, dropout=0.0):
        super().__init__()
        # <pad>(0번)는 빈칸이라 학습하지 않습니다
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.rnn = nn.RNN(
            embed_dim, hidden_size,
            batch_first=True,
            num_layers=num_layers,
            # dropout은 층과 층 '사이'에 걸립니다 → 1층이면 걸 자리가 없습니다
            dropout=(dropout if num_layers > 1 else 0.0),
        )
        self.fc = nn.Linear(hidden_size, 1)

    def forward(self, x):
        x = self.embedding(x)              # (배치, 길이) → (배치, 길이, 임베딩차원)

        # RNN은 두 개를 돌려줍니다: 모든 스텝의 출력, 그리고 마지막 은닉 상태
        output, h_n = self.rnn(x)

        last = h_n[-1]                     # (배치, 은닉차원) — 맨 위 층의 마지막 은닉
        return torch.sigmoid(self.fc(last)).squeeze(-1)


LstmClassifier 는 위와 나란히 놓고 보면 다른 곳이 딱 두 군데입니다.

class LstmClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim=32, hidden_size=32,
                 num_layers=1, dropout=0.0):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.rnn = nn.LSTM(                # ① 여기가 nn.RNN → nn.LSTM
            embed_dim, hidden_size,
            batch_first=True,
            num_layers=num_layers,
            dropout=(dropout if num_layers > 1 else 0.0),
        )
        self.fc = nn.Linear(hidden_size, 1)

    def forward(self, x):
        x = self.embedding(x)

        # ② LSTM은 셀 상태 c 도 함께 나릅니다 → (h_n, c_n) 짝으로 옵니다
        output, (h_n, c_n) = self.rnn(x)

        last = h_n[-1]                     # 분류에 쓰는 건 은닉 상태 h 쪽입니다
        return torch.sigmoid(self.fc(last)).squeeze(-1)


GruClassifier 는 nn.GRU 를 쓰고, forward 는 RnnClassifier 와 글자 하나 다르지 않습니다. 셀 상태가 없으니 나르는 것도 은닉 상태 하나뿐이기 때문입니다.

세 파일을 나란히 띄워 놓고 비교해 보세요. 거의 다 같습니다. 다른 건 층 만드는 줄 하나, 그리고 LSTM만 받는 모양 하나예요. 새로 외울 게 없습니다.

4. 훈련하고 비교하기 — 03_train_lstm.py

이 파일은 RNN과 LSTM을 둘 다 훈련합니다. 예전에 본 값을 기억해 두었다가 비교하는 게 아니라, 지금 이 컴퓨터에서 기준선을 새로 만듭니다. 이유는 둘입니다.

사람마다 환경이 다릅니다. 다른 날 값과 오늘 값을 섞으면 무엇 때문에 달라졌는지 알 수 없습니다.
비교는 같은 자리에서 해야 합니다.

그래서 두 모델에 똑같은 조건을 줍니다.

VOCAB_SIZE, MAX_LEN = 2000, 100
EMBED, HIDDEN = 32, 32
BATCH, LR, EPOCHS = 64, 1e-3, 12


조건이 하나라도 달라지면 "게이트 덕분에 올랐다"는 말 자체가 성립하지 않습니다.

훈련 루프는 지금까지 쓰던 것과 완전히 같습니다
def train_model(ModelClass, seed=42, epochs=EPOCHS, verbose=True):
    torch.manual_seed(seed)                      # 같은 출발점에서 비교하려고 시드 고정
    loader = DataLoader(TensorDataset(X_train, y_train), batch_size=BATCH, shuffle=True)

    model = ModelClass(len(word2idx), EMBED, HIDDEN)   # 넘겨받은 클래스로 만듭니다
    optimizer = torch.optim.Adam(model.parameters(), lr=LR)
    criterion = nn.BCELoss()

    for epoch in range(epochs):
        model.train()
        for xb, yb in loader:
            optimizer.zero_grad()                   # ③ 지난 기울기 지우기
            loss = criterion(model(xb), yb)         # ①② 예측하고 손실 재기
            loss.backward()                         # ④ 기울기 계산
            optimizer.step()                        # ⑤ 가중치 수정


앞서 배운 학습 5단계가 그대로 있습니다. 새로 배울 건 하나도 없습니다 — 루프는 손대지 않았고, 훈련할 모델을 인자로 받게만 했습니다.

여기서 ModelClass 는 RnnClassifier 같은 클래스 자체입니다. 파이썬에서는 클래스도 값처럼 넘길 수 있어서, 함수 안에서 ModelClass(...) 로 부르면 넘겨받은 그 클래스의 모델이 만들어집니다.

6. GRU — 더 가벼운 문 · 04_gru.py

LSTM은 문 3개에 기억 통로를 따로 냈습니다. 잘 되는데 무겁습니다.

"문을 3개나 달아야 하나? 2개면 안 되나? 기억 통로도 은닉 상태 하나로 합치면 안 되나?"

그렇게 줄여 본 것이 GRU(2014)입니다. LSTM(1997)보다 17년 늦은 대신 훨씬 단순합니다.

반환 형태부터 — 말로 믿지 말고 찍어 봅니다
  RNN   output (4, 10, 16) · hidden: 텐서 하나 → h_n (1, 4, 16)
  LSTM  output (4, 10, 16) · hidden: 튜플 2개 → h_n (1, 4, 16) · c_n (1, 4, 16)
  GRU   output (4, 10, 16) · hidden: 텐서 하나 → h_n (1, 4, 16)


LSTM만 짝으로 옵니다. GRU는 RNN과 똑같이 텐서 하나입니다. 그래서 RNN을 쓰던 코드라면 nn.GRU 로 바꿔도 받는 쪽은 손댈 필요가 없습니다.

게이트 2개 — 무엇이 줄었나
GRU 게이트	하는 일	LSTM에서 대응되는 것
reset (r)	과거 은닉 상태를 얼마나 참고해 새 후보를 만들지	(없음 — GRU 고유)
update (z)	과거를 얼마나 유지하고 새것을 얼마나 넣을지	forget + input 을 하나로 합침
LSTM:  c_t = f_t ⊙ c_{t-1}  +  i_t ⊙ c̃_t         ← f 와 i 가 독립
GRU :  h_t = z_t ⊙ h_{t-1}  +  (1 - z_t) ⊙ h̃_t   ← 하나의 z 가 양쪽을 결정
             └ 유지 ┘           └── 새것 ──┘


z 와 1-z 로 나눠 갖기 때문에 합이 항상 1입니다. "과거 70%, 새것 30%" 처럼 저울로 섞는 것이라고 보면 됩니다.

  z=0.0    0.0×2.0 + 1.0×10.0  = 10.00   ← 과거를 전부 버림 (RNN에 가깝습니다)
  z=0.3    0.3×2.0 + 0.7×10.0  =  7.60
  z=0.5    0.5×2.0 + 0.5×10.0  =  6.00
  z=0.9    0.9×2.0 + 0.1×10.0  =  2.80
  z=1.0    1.0×2.0 + 0.0×10.0  =  2.00   ← 새것을 무시하고 기억을 그대로 통과


📌 z=1 이면 h_t = h_{t-1} — 값이 그대로 흘러갑니다. §2에서 본 '곱셈 대신 덧셈 경로'가 GRU에서는 이 z 로 만들어집니다. LSTM의 셀 상태와 이름만 다를 뿐, 노리는 것은 같습니다.

파라미터 수 — 게이트를 줄이면 가중치도 줍니다
  모델   게이트     전체 파라미터    순환층만
  RNN    0개              66,145       2,112   (RNN의 1배)
  GRU    2개              70,369       6,336   (RNN의 3배)
  LSTM   3개              72,481       8,448   (RNN의 4배)

LSTM = 게이트 3개 + 후보값 1개 = 가중치 4벌
GRU = 게이트 2개 + 후보값 1개 = 3벌

✅ 이 값은 계산으로 정해지므로 누구 화면에서나 같습니다.

⚠️ 어디를 보고 말하느냐로 이야기가 달라집니다. 전체로 보면 차이가 작아 보입니다 — 임베딩(2000×32 = 64,000)이 워낙 커서 순환층 차이를 덮기 때문입니다. "4배 무겁다"도 맞고 "몇 % 차이"도 맞습니다. 비교할 때는 늘 '무엇을 세고 있는지' 확인하세요.

그래서 뭘 써야 하나?

여기서 정답을 외우려 하지 마세요. 자주 듣는 말은 이렇습니다.

"GRU가 더 가볍고 빠르다" → 파라미터 수로는 맞습니다. 속도는 데이터·환경마다 다릅니다.
"LSTM이 더 강력하다" → 표현력은 더 크지만, 더 좋은 결과를 보장하지 않습니다.

실제 현장의 답은 하나입니다.

둘 다 돌려 보고, 내 데이터에서 나은 쪽을 씁니다. 단, "돌려 보고 나은 쪽"을 정할 때 한 번 돌린 숫자로 정하면 안 됩니다 — §5 이야기입니다.

7. 층 쌓기와 hidden — 06_stacked_dropout.py
입력 문장 → [1층 RNN] → 1층의 은닉 상태 줄 → [2층 RNN] → 2층의 은닉 상태 줄
                        (길이는 그대로)                    └ 여기서 마지막을 씁니다


2층 = 1층이 만든 요약들의 줄을, 2층이 다시 처음부터 읽는 것. 인자 하나면 됩니다.

nn.LSTM(..., num_layers=2, dropout=0.3)

  num_layers=1:  output (4, 30, 16)   hidden (1, 4, 16)
  num_layers=2:  output (4, 30, 16)   hidden (2, 4, 16)
  num_layers=3:  output (4, 30, 16)   hidden (3, 4, 16)

output — (배치, 길이, 은닉). 층을 쌓아도 모양이 변하지 않습니다. 언제나 맨 위 층이 각 시간마다 낸 은닉 상태만 담깁니다. 중간 층 출력은 여기 없습니다.
hidden — (층수, 배치, 은닉). 여기만 늘어납니다. 각 층이 마지막 시간에 낸 은닉 상태를 층별로 모아 둔 것입니다.
짐작하지 말고 직접 재 봅시다
for L in [1, 2, 3]:
    layer = nn.RNN(8, 16, num_layers=L, batch_first=True)
    layer.eval()
    with torch.no_grad():
        output, hidden = layer(x)
    print(L, torch.equal(hidden[-1], output[:, -1, :]),
             torch.equal(hidden[0],  output[:, -1, :]))

  층수    hidden[-1] == output[:,-1,:]     hidden[0] == output[:,-1,:]
  1층    True                             True
  2층    True                             False
  3층    True                             False


✅ hidden[-1] == output[:, -1, :] 는 몇 층을 쌓아도 계속 True 입니다.

이유를 알고 나면 당연합니다.

output 에는 애초에 맨 위 층의 은닉 상태만 담깁니다 → output[:, -1, :] = 맨 위 층의 마지막
hidden 은 아래 층부터 쌓여 있습니다 → hidden[-1] = 맨 위 층의 마지막
둘 다 "맨 위 층의 마지막"이니 같을 수밖에 없습니다.

진짜로 달라지는 건 hidden[0] 입니다.

	hidden[0] 이 가리키는 것
1층	유일한 층 = 맨 위 층 → output 마지막과 같습니다
2층 이상	맨 아래 층 → 다릅니다

"층 하나 늘렸더니 갑자기 정확도가 이상해요"의 흔한 범인이 이것입니다. hidden[0] 이나 hidden.squeeze(0) 을 습관적으로 쓰다가 아래 층 요약으로 분류하게 됩니다. 그래서 우리는 처음부터 hidden[-1] 을 썼습니다. 층수와 무관하게 안전합니다.

헷갈릴 땐 오늘처럼 torch.equal 로 직접 재 보면 금방 끝납니다.

dropout — 어디에 걸리나

층과 층 사이 에만 걸립니다. 마지막 층의 출력에는 걸리지 않습니다.

그래서 1층에 dropout을 주면 아무 일도 일어나지 않습니다. 파이토치가 경고까지 냅니다.

  ⚠️ dropout option adds dropout after all but last recurrent layer,
     so non-zero dropout expects num_layers greater than 1…


그래서 model.py 에서 막아 두었습니다 — dropout=(dropout if num_layers > 1 else 0.0).

dropout은 훈련할 때만 켜집니다
  eval  두 번 실행이 같은가 : True    ← 항상 같아야 합니다
  train 두 번 실행이 같은가 : False   ← 매번 다른 자리를 끄니 다릅니다


⚠️ eval() 을 빼먹으면 평가할 때도 dropout이 켜진 채 채점하게 됩니다. 같은 모델·같은 데이터인데 정확도가 매번 흔들린다면 이걸 먼저 의심하세요.

2층이 실제로 나은가?

§5의 절차를 그대로 적용합니다. 잡음부터 잽니다.

  LSTM 1층                평균 0.753
  LSTM 2층 dropout 0.3    평균 0.743

  같은 설정 재실행 흔들림(잡음) : 0.012
  1층 ↔ 2층 평균 차이(신호)     : 0.010
  → 신호가 잡음에 묻힙니다. 이 조건에서는 차이가 있다고 말할 수 없습니다.


📌 "2층이 나쁘다"가 아니라 "2층이 낫다는 증거를 얻지 못했다" 가 정확한 표현입니다.

왜 2층이 힘을 못 쓸까요? 생각해 볼 거리입니다.

데이터가 5,000편뿐입니다. 층을 쌓으면 배울 파라미터가 늘어나는데 배울 재료는 그대로입니다.
MAX_LEN=100 이라 문장이 짧게 잘립니다. 층을 쌓는 건 보통 데이터가 크고 문장이 길 때 값을 합니다.

오늘 배운 것
RNN의 한계는 같은 가중치를 반복해 곱하는 구조 때문이었습니다.
LSTM은 셀 상태를 두고 c_t = f⊙c_{t-1} + i⊙c̃_t 로 더해서 잇습니다. 게이트는 그 문입니다.
결정적인 건 성능이 아니라 "무엇을 남길지 모델이 고를 수 있게 된 것" 입니다.
nn.LSTM 은 (h_n, c_n) 짝을 돌려줍니다. 셀 상태를 함께 나르기 때문입니다. 풀어서 받으면 됩니다.
GRU는 같은 아이디어를 더 적은 부품으로 구현합니다. 반환은 RNN과 같습니다.
숫자 하나로 결론 내리지 않습니다. 잡음을 먼저 재고, 신호가 그보다 클 때만 말합니다.
헷갈리면 재 봅니다. torch.equal 한 줄이면 확인됩니다.
