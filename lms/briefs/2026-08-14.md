공개

지식 목표

OpenAI API 서버가 대화를 저장하지 않는 무상태라는 것, 따라서 대화가 되려면 앞 대화 전체를 messages 배열에 쌓아 매번 통째로 다시 보내야 한다는 것을 이해한다. 응답이 문자열이 아니라 choices·finish_reason·usage 칸을 가진 객체이며, 빈 응답이 와도 finish_reason과 completion_tokens_details를 읽으면 원인을 찾을 수 있음을 안다. 배열 속 조각의 역할이 system(지시)·user(나)·assistant(모델의 답) 셋뿐이고 system 조각 하나가 답의 성격을 바꾼다는 것, create() 한 줄의 실체가 api.openai.com으로 가는 HTTP POST라는 것, 요금의 단위인 토큰이 서브워드 조각이라 같은 뜻도 한글이 영어보다 조각이 많다는 것을 설명할 수 있다.

기능 목표

환경변수로 키를 안전하게 읽어 OpenAI 클라이언트를 만들고, 응답 객체를 model_dump_json으로 펼쳐 choices·finish_reason·usage를 읽는다. 잘못된 키로 일부러 401을 내고 try/except로 받아 본다. messages 배열에 user·assistant 조각을 직접 append하며 멀티턴을 만들고, 턴마다 prompt_tokens가 자라는 것을 표로 확인한다. usage 누계와 공식 단가로 대화 비용을 어림하고, json.dump/load로 대화를 파일에 저장했다가 되살려 이어 간다. 같은 배열을 while 루프에 담아 터미널 프로그램(chat.py)을, st.session_state에 담아 브라우저 챗봇(app.py)을 완성한다.

산출물 목표

메이킹 타임의 결과물 — 오늘 배운 messages 배열이 들어 있는, 학습자가 만들고 싶어서 만든 챗봇(또는 대화 프로그램) 하나. 화면 캡처와 함께 무엇을 만들었는지, 오늘 배운 것 중 어디에 썼는지 각 한 줄을 공유한다. 수업 블록에서는 터미널 멀티턴 프로그램 chat.py와 브라우저 챗봇 app.py를 전원이 완성한다.

Python 3.12 (기존 가상환경 .venv 그대로)
openai 3.0.0 (chat.completions.create · with_raw_response · usage · AuthenticationError)
Streamlit 1.61.1 (st.chat_input · st.chat_message · st.session_state — 수업 첫 블록에서 uv pip install)
json 표준 라이브러리 (대화 저장/복원)
ChatGPT Plus · Codex (메이킹 타임의 도구 — 물어 가며 만들기)
VSCode 대화형 창 (# %% 셀 단위 실행) + 터미널 + 브라우저
외부 데이터셋 없음. 호출 대상은 OpenAI gpt-5.4-nano(효율 나노급 — 실측 응답 1.9초, temperature 지원)이며, 빈 응답 교보재로 gpt-5-nano를 한 번 호출한다. 대화에 넣는 문장은 전부 학습자가 직접 쓴 자기 문장이다. GPU 불필요 — 오늘은 전부 원격 호출이다.

메이킹 — 내 결과물 하나 완성

오늘 배운 messages 배열로, 만들고 싶은 챗봇(또는 대화 프로그램) 하나를 완성해 공유한다. 주제·형태·도구는 자유이며 ChatGPT·Codex를 마음껏 쓴다.

오늘 배운 것 두 가지 이상 엮기

같은 결과물에 오늘 배운 요소를 두 가지 이상 결합해 깊이를 더한다 — 멀티턴, 지시문(system), 대화 저장/복원, 화면(session_state), 토큰 표시 중에서.

남에게 보여줄 완성도

내 결과물을 남에게 바로 보여줄 수 있는 상태로 다듬고, 셋째 날 캡스톤에서 이어 키울 내 주제로 삼는다.

제출 안내

메이킹 타임의 공유물 하나면 된다 — 내가 만든 결과물의 화면 캡처와 함께, 무엇을 만들었는지 한 줄과 오늘 배운 것 중 어디에 썼는지 한 줄. 결과물 안에 messages 배열이 있어야 한다. 마무리 자랑 타임의 시연은 자원이며 강제하지 않는다. 수업 블록의 chat.py·app.py 완성 여부는 수업 중에 그 자리에서 확인한다.

다음 수업 연결

다음 수업(연휴 뒤 화요일)은 오늘 만든 파일들을 다시 열며 시작한다 — 키는 ~/.bashrc에 그대로 있고, 첫 셀로 재확인부터 한다. 오늘 손으로 쌓은 messages 배열 위에 구조화 출력과 도구 호출을 얹는다 — 모델이 함수를 부른다는 예고의 정체가 거기서 풀린다. 메이킹 타임의 결과물은 셋째 날 캡스톤이 이어받아 키운다.
