01Controller — 계약대로 받기 (com.study)

@PostMapping("/api/inquiries")
public InquiryResponse create(@RequestBody InquiryRequest req) {
if (req.content() == null || req.content().isBlank())
throw new IllegalArgumentException("문의 내용을 입력해 주세요."); // → 400
return service.handle(req.content());
}
record InquiryRequest(String content) {}
record InquiryResponse(Long id, String category, String answer, String createdAt) {}

02Service — 프롬프트 + 구조화 파싱 + 저장

@Transactional
public InquiryResponse handle(String content) {
InquiryResult ai = chatClient.prompt() // AI 먼저 (실패 시 저장 안 함)
.user(u -> u.text(TEMPLATE).param("content", content))
.call().entity(InquiryResult.class); // 구조화 파싱
Inquiry saved = repository.save(
new Inquiry(content, ai.category(), ai.answer(), Instant.now())); // urgency 저장 안 함
return new InquiryResponse(saved.getId(), saved.getCategory(),
saved.getAnswer(), saved.getCreatedAt().toString());
}
record InquiryResult(String category, String urgency, String answer) {} // urgency = 계약 밖

03검증 — curl 한 방

curl -X POST http://localhost:8080/api/inquiries \
-H "Content-Type: application/json" \
-d '{"content":"배송이 늦어지는데 언제 받나요?"}'
# 기대: {"id":1,"category":"배송 문의","answer":"...","createdAt":"..."}

▸ 막힐 때 빠른 점검

- .entity()가 비어요 → 버그 단정 전 .content()로 모델 원본 확인, 출력형식 프롬프트 강화

- AI 실패인데 반쪽 저장 → AI 호출을 save 앞에 두고 @Transactional로 묶기

- 테이블 없음 → ddl-auto: update 명시

- DB 연결 실패 → Postgres docker compose up, 없으면 H2 파일 DB 폴백

- 키 401 → AIza… 형식 확인, ${GOOGLE_API_KEY} 환경변수 (하드코딩 ❌)

오늘 curl로 선 그 응답이, 내일 React 화면에서 그대로 뜬다. 응답 필드명을 계약 그대로 맞춰두자.
