## 어제와 오늘

어제 텐서·Dataset·DataLoader까지 다 만들었습니다. 그런데 거기 넣은 건
꽃잎 길이 같은 이미 숫자였던 데이터였죠. 우리가 다뤄야 할 건 문장입니다.

문장은 숫자가 아닙니다. 오늘은 그 사이를 잇습니다.

## 오늘의 지도 — 계속 되돌아올 그림

원문 → 토큰화 → 어휘 사전 → 정수 인코딩 → 패딩·배치 → 임베딩
학교에서는 자르기 번호 붙이기 숫자로 길이 맞추기 벡터로

마지막에 나오는 (batch, seq_len, embed_dim) 모양을 꼭 기억하세요.
내일 RNN이 정확히 이 모양을 입력으로 받습니다.

## 오늘 알아야 할 것

- 텍스트가 모델 입력이 되는 파이프라인 5단계를 순서대로 말할 수 있다

- 한국어를 split()으로 자르면 왜 깨지는지 설명할 수 있다

- <pad>·<unk>를 포함한 어휘 사전을 만들고 OOV를 처리할 수 있다

- collate_fn으로 길이가 다른 문장을 배치 텐서로 만들 수 있다

- one-hot의 두 한계를 말하고 nn.Embedding이 룩업 테이블임을 설명할 수 있다

## 1. 토큰화 — 문장을 무엇으로 자를까

모델은 문장을 통째로 이해하지 못합니다. 텐서에 넣으려면 숫자가 되어야 하고,
숫자를 붙이려면 먼저 단위를 정해야 합니다. 그 단위로 쪼개는 게 토큰화입니다.

### 일단 split()으로 잘라보면

"I don't like cats. They cost $3.14".split()
# ['I', "don't", 'like', 'cats.', 'They', 'cost', '$3.14']

don't는 한 덩어리가 되고, cats.는 마침표가 붙어 cats와 다른 단어가 됩니다.
같은 단어를 두 번 배우게 되니 낭비죠. 영어는 NLTK 같은 도구가 이 규칙을 처리합니다.

### ★ 한국어는 다릅니다 — 오늘의 핵심

코퍼스에서 '학교'가 든 문장들을 띄어쓰기로 자르면:

['학교를', '학교에', '학교에서', '학교에서는'] ← 전부 '학교'인데 4개!

한국어는 교착어라 뜻을 가진 말에 조사·어미가 줄줄이 붙습니다.
영어 at school은 띄어져 있지만 한국어 학교에서는 붙어 있어 split()이 실패합니다.

형태소 분석(kiwipiepy)으로 자르면:

from kiwipiepy import Kiwi
kiwi = Kiwi()
[t.form for t in kiwi.tokenize("학교에서는 파이썬을 배웁니다")]
# ['학교', '에서', '는', '파이썬', '을', '배우', 'ᆸ니다']

'학교' 계열 4개가 1개로 합쳐집니다. 이게 형태소 분석을 쓰는 이유입니다.

배웁니다 → 배우 + ᆸ니다 에서 ᆸ이 홀로 나오는 건 받침이 분해된 것이지 오류가 아닙니다.

KoNLPy라는 이름을 인터넷 예제에서 만날 겁니다. 여러 분석기를 묶은 꾸러미인데
대부분 자바가 필요합니다. 우리는 자바 없이 되는 Kiwi를 씁니다 — 하는 일은 같습니다.

## 2. 어휘 사전 — 번호를 붙입니다

텐서에는 숫자만 들어갑니다. '학교'라는 글자를 넣을 수 없으니 단어마다 번호표를 줍니다.

word2idx = {"<pad>": 0, "<unk>": 1} # 자리를 먼저 예약!
for word, freq in counter.most_common(): # 빈도 순으로
word2idx[word] = len(word2idx)

- <pad>(0) — 빈 자리. 길이를 맞출 때 채워 넣습니다 (다음 절에서 씀).

- <unk>(1) — 모르는 단어. 사전에 없는 단어가 오면 여기로.

- 번호 자체엔 의미가 없습니다. 5번이 3번보다 크다고 중요한 게 아니에요. 그냥 이름표입니다.

### 처음 보는 단어 — OOV

새 문장: 학교에서 텐서플로우를 배웠다
되돌리면: ['학교', '에서', '<unk>', '를', '배우', '었', '다']

텐서플로우가 사전에 없으면 <unk>가 되고 그 자리에 무슨 말이 있었는지 모릅니다.
이걸 OOV(Out-Of-Vocabulary)라고 합니다. 나중에 subword가 이 문제를 풉니다.

놀라운 사실: 형태소로 자른다고 사전이 작아지지는 않습니다(오늘 코퍼스에선 오히려 조금 큼).
조사·어미가 새 토큰으로 들어오기 때문이죠. 진짜 이득은 재사용성입니다 —
같은 토큰이 여러 문장에 다시 나와 모델이 배울 기회가 생깁니다.

## 3. 패딩 — 길이를 맞춥니다

문장마다 길이가 다릅니다. 그런데 텐서는 직사각형이라 그대로 쌓을 수 없습니다.

torch.tensor([[1,2,3], [4,5]])
# ValueError: expected sequence of length 3 at dim 1 (got 2)

이 오류를 꼭 기억하세요 — 텍스트를 다루면 반드시 한 번은 만납니다.
해결은 짧은 문장 뒤에 <pad>(0)를 채우는 것입니다.

from torch.nn.utils.rnn import pad_sequence
pad_sequence(문장들, batch_first=True, padding_value=0)
# [[1, 2, 3], [4, 5, 0]] ← 뒤를 0으로 채워 (2, 3) 텐서

batch_first=True는 (문장 수, 길이) 순서입니다. max_len으로 너무 긴 문장을 자를 때는
무엇을 버리는지 확인하세요 — 리뷰의 결론이 문장 끝에 있는데 앞만 남기면 정답을 버립니다.

## 4. 배치 만들기 — 어제의 DataLoader로

어제 DataLoader에 텍스트를 그대로 넣으면 실패합니다:

# RuntimeError: stack expects each tensor to be equal size

DataLoader는 샘플들을 하나의 텐서로 쌓는데(torch.stack), 길이가 달라 못 쌓는 거죠.
이 '쌓는 방법'을 우리가 직접 정하는 게 **collate_fn**입니다:

def collate_fn(batch):
return pad_sequence(batch, batch_first=True, padding_value=0)

loader = DataLoader(dataset, batch_size=4, collate_fn=collate_fn)

배치 안에서 가장 긴 문장에 맞춰 패딩하므로 빈칸 낭비가 적습니다.
배치마다 길이가 달라도 괜찮습니다 — 모델은 한 배치 안에서만 모양이 맞으면 됩니다.

Dataset의 __getitem__에서는 패딩하지 않습니다. 한 문장만 보고는 '가장 긴 길이'를
알 수 없으니까요. 길이 맞추기는 여러 개를 모으는 collate_fn에서 합니다.

## 5. one-hot의 한계

'학교'를 15번으로 바꿨지만 15는 그냥 이름표입니다. 의미를 담은 숫자가 필요합니다.
가장 단순한 방법이 one-hot — 자기 자리만 1, 나머지는 0입니다. 그런데 두 가지 문제가 있습니다.

① 차원 폭발 — 어휘가 5만 개면 단어 하나가 길이 5만짜리 벡터가 됩니다. 그중 99.99%가 0이죠.

② 유사도가 언제나 0 — 어떤 두 단어를 골라도 코사인 유사도가 정확히 0입니다.

학교 ~ 공부 : 0.000 학교 ~ 커피 : 0.000 친구 ~ 공부 : 0.000

'학교'와 '공부'는 사람 눈엔 가까운데 one-hot에겐 '학교'와 '커피'만큼이나 남남입니다.
모든 단어가 서로 직각으로 서 있어서, 단어 사이 관계를 처음부터 표현할 수 없습니다.

## 6. 단어 임베딩 — 오늘의 목적지

임베딩은 어렵지 않습니다. 표(table) 하나예요.

embedding = nn.Embedding(num_embeddings=177, embedding_dim=8, padding_idx=0)

embedding(torch.tensor(15)) # 15번 행
embedding.weight[15] # ← 완전히 같다!

nn.Embedding은 **계산이 아니라 조회(lookup)**입니다. 15번 단어를 달라고 하면 15번 행을 꺼내줄 뿐이죠.
padding_idx=0은 <pad>의 벡터를 0으로 고정합니다(빈칸에서 뭘 배우지 않게).

정수 하나가 벡터로 부풀면서 차원이 하나 늘어납니다:

(batch, seq_len) → (batch, seq_len, embed_dim)

### 코사인 유사도 — 두 벡터가 얼마나 닮았나

두 벡터의 각도로 잽니다. 같은 방향이면 1, 직각이면 0, 반대면 -1.

### 학습이 의미를 만듭니다

같은 영어 단어로 랜덤 임베딩과 학습된 임베딩(GloVe)을 비교하면:

|

| 단어 쌍
| 랜덤
| GloVe

| dog ~ cat
| -0.150
| 0.922

| king ~ queen
| 0.116
| 0.784

| dog ~ banana
| 0.017
| 0.333

GloVe 쪽만 사람의 직관과 순서가 맞습니다. 랜덤은 시드를 바꾸면 순서가 뒤바뀝니다 —
재현되지 않으면 의미가 아니죠. 아무도 "dog와 cat이 비슷하다"고 가르치지 않았는데,
같이 나오는 단어들이 비슷해서 벡터가 가까워진 겁니다(분포 가설).

우리가 오늘 만든 nn.Embedding 표는 아직 난수입니다. 왜 만들었냐고요?
이 표는 학습되는 파라미터라서, 내일 RNN을 붙여 학습시키면 저절로 '의미 공간'이 됩니다.

## 7. 현대는 이렇게 자릅니다 — subword 맛보기

사전을 아무리 키워도 새 단어는 계속 나옵니다(OOV). 요즘 LLM은 다르게 접근합니다 —
단어를 조각으로 쪼갭니다. 텐서플로우 → 텐서 + 플로우처럼요. 모르는 단어가 없어집니다.

같은 뜻의 문장을 잘라 토큰 수를 세면:

"학교에서는 파이썬을 배웁니다" vs "We learn Python at school"
gpt2 : 한국어 36토큰 / 영어 6토큰 (6.0배!)
Qwen3 : 한국어 10토큰 / 영어 6토큰 (1.7배)

한국어가 토큰을 몇 배씩 먹습니다. LLM API 요금은 토큰 수로 매기니까, 이건 곧 비용입니다.
한국어 서비스를 만들 때 토크나이저 선택이 중요한 이유죠. (자세한 건 Day 8)

## 막혔을 때

- 오류 메시지 마지막 줄을 먼저 읽었나요?

- stack expects each tensor to be equal size → collate_fn을 안 넘겼습니다

- expected sequence of length N → 길이가 다른 리스트를 텐서로 만들려 했습니다

- KeyError → word2idx[tok] 대신 word2idx.get(tok, 1)

- 인코딩 결과가 이상하면 되돌려서(decode) 확인했나요?

- print(x.shape)로 모양을 확인했나요?
