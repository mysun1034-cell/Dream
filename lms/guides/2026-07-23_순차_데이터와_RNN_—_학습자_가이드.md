## 1. 순서는 어디에 있나

문장을 벡터 하나로 요약하는 가장 단순한 방법은 단어 벡터를 다 더하는 것입니다. 이런 걸 가방(bag) 모델이라 부릅니다 — 단어를 가방에 쏟아 넣고 순서는 잊는다는 뜻입니다.

문제는 더하기가 순서를 무시한다는 것입니다. a + b + c 와 c + b + a 는 같으니까요.

sum_x = embedding(bag_x).sum(dim=0) # "개가 물었다 사람을"
sum_y = embedding(bag_y).sum(dim=0) # "사람을 개가 물었다"

torch.allclose(sum_x, sum_y) # → True 😱

실측: 두 요약의 차이 ≈ 2.98e-08 (사실상 0). 순서 정보가 사라졌습니다.

### 순차 데이터란

순서가 의미를 갖는, 하나씩 이어지는 데이터입니다. 문장·음성·주가가 그렇습니다.

|

|
| 이미지
| 문장

| 크기
| 고정 (예: 28×28)
| 제각각 (3단어 ~ 수백 단어)

| 순서
| "읽는 순서"는 없음
| 읽는 순서가 뜻을 바꾼다

| 처리
| 한 번에 통째로
| 앞에서 뒤로, 앞을 기억하며

그래서 필요한 장치는 이렇습니다.

단어를 하나씩 받으면서, 지금까지 읽은 것을 요약해 기억하고,
다음 단어를 그 기억과 함께 처리한다.

이 "기억"을 은닉 상태(hidden state) 라 하고, 이걸 갖춘 모델이 RNN(Recurrent Neural Network, 순환 신경망)입니다.

📖 책을 읽으며 매 문장 끝에 "여기까지 줄거리"를 머릿속으로 갱신하는 것과 같습니다.

## 2. RNN 셀 — 딱 하나의 식 ★★★

RNN은 복잡해 보이지만 핵심은 식 하나입니다. 단어를 하나 읽을 때마다 이걸 계산합니다.

h_t = tanh( W_x · x_t + W_h · h_{t-1} + b )

기호를 하나씩 풀면:

|

| 기호
| 읽는 법
| 뜻

| x_t
| "엑스 티"
| 지금 읽는 t번째 단어의 벡터

| h_{t-1}
| "에이치 티 마이너스 원"
| 바로 전까지 읽은 것의 요약

| h_t
| "에이치 티"
| 지금 단어까지 반영한 새 요약

| W_x, W_h
| 가중치(weight)
| 입력과 이전 요약을 각각 얼마나 섞을지 (학습으로 정해짐)

| b
| 바이어스(bias)
| 편향 항 — 결과를 위아래로 옮기는 상수

| tanh
| "탄에이치"
| 값을 −1~1 사이로 눌러 주는 함수 (너무 커지지 않게)

핵심은 h_{t-1} 이 식 안에 들어간다는 것입니다. 이전 결과가 다음 계산에 섞입니다.

### 손으로 한 스텝 계산해 봅시다

가장 작게, 요약이 숫자 하나(1차원)라고 칩시다.
직전 요약 h_{t-1}=0.5, 지금 단어 x_t=1.0, W_x=0.6, W_h=0.8, b=0 이라면

0.6 × 1.0 + 0.8 × 0.5 + 0 = 0.6 + 0.4 = 1.0
h_t = tanh(1.0) = 0.76

새 요약이 0.76이 됐습니다. 다음 단어를 읽을 땐 이 0.76이 h_{t-1} 자리로 들어갑니다.
실제 모델은 이 계산을 은닉 차원(32)개만큼 한꺼번에 할 뿐, 원리는 똑같습니다.

### for 문으로 한 단어씩

은닉 상태 h 는 0에서 시작합니다(아직 아무것도 안 읽었으니 빈 요약).

h = torch.zeros(H) # 시작 요약: 텅 빈 상태
for t in range(L):
h = torch.tanh(Wx @ x[t] + Wh @ h + b) # ← 그 식 그대로 (@는 행렬곱)

실행하면 매 스텝 h 가 바뀝니다. 각 h 는 "그 단어까지 읽은 요약"이고, 마지막 h 가 문장 전체의 요약입니다.

### 같은 가중치를 매번 다시 씁니다 — 가중치 공유

위 for 문에서 W_x·W_h·b 는 매번 똑같은 것을 씁니다. 단어 1을 읽을 때나 단어 100을 읽을 때나 같은 규칙입니다. 덕분에 문장이 3단어든 300단어든 파라미터 개수는 같습니다.

### 손 구현이 nn.RNN 과 정말 같은가

파이토치의 nn.RNN 도 안에서 똑같은 식을 돕니다. 딱 하나 다른 점은 편향을 둘로 나눠 가진다는 것(b_ih, b_hh)입니다. 그 둘의 합을 우리 b 자리에 넣으면 완전히 같아집니다.

실측: 손 구현의 마지막 은닉 == nn.RNN 의 마지막 은닉 → True (최대 오차 2.98e-08)

nn.RNN 은 이 for 문을 빠르게(그리고 미분 가능하게) 돌려 줄 뿐입니다. 마법이 아닙니다.

### 문장 하나가 요약이 되기까지

h_0(빈 요약) --this--> h_1 --movie--> h_2 --is--> h_3 --great--> h_4 --> 분류기(긍정/부정)

단어를 하나 읽을 때마다 요약이 갱신됩니다. ★ 분류기로 가는 건 마지막 요약 h_4 하나뿐입니다 — 앞쪽 내용도 여기 녹아 있어야 합니다. (이 "마지막 하나만 쓴다"가 뒤에서 문제를 일으킵니다.)

💡 다른 자료를 볼 때: 교재·논문은 보통 U(입력→은닉), V(은닉→은닉), W(은닉→출력)로 씁니다.
우리 표기로는 U=W_x, V=W_h, W=nn.Linear 입니다. 기호만 다르고 구조는 같습니다.

## 3. IMDB 데이터 — 어제 파이프라인 그대로

IMDB는 영화 리뷰 5만 개에 긍정(1)/부정(0) 딱지가 붙은 데이터셋입니다. 수업에선 CPU로도 몇 분에 끝나도록 train 5,000 · val 2,000만 뽑아 씁니다.

⚠️ 원본 train은 부정이 앞, 긍정이 뒤로 정렬돼 있습니다. 그냥 앞 5,000개를 뽑으면 전부 부정만 걸립니다. 그래서 반드시 먼저 섞은 뒤 잘라냅니다.

from textutils import tokenize_en, build_vocab, encode, pad_and_tensor

train_toks = [tokenize_en(t) for t in train["text"]] # 영어 토큰화
word2idx, _ = build_vocab(train_toks, max_size=2000) # 어제 build_vocab 그대로
X_train = pad_and_tensor(train_toks, word2idx, max_len=100) # (5000, 100)

토큰화 방법만 언어에 맞춰 바꾸고, 그 뒤는 어제 함수 그대로입니다.

실측:

리뷰 길이(토큰): 최소 12 · 중앙값 179 · 최대 1646 ← 중앙값이 100을 훌쩍 넘습니다
사전 크기: 2002 (특수토큰 <pad>·<unk> 포함)
<unk> 비율: 16.0%
가장 흔한 단어: the, and, a, of, to, is, br, it, in, i

br 이 왜 상위에? 원문에 <br />(HTML 줄바꿈)이 섞여 있어서입니다. 실데이터는 지저분합니다.

### ★ 왜 '앞쪽'에 패딩하나

RNN은 문장을 앞에서 뒤로 읽고 마지막 은닉 상태로 판단합니다. 뒤쪽에 <pad>를 잔뜩 붙이면, 볼 내용을 다 읽은 뒤 빈칸만 계속 읽다 끝나서 마지막 요약이 흐려집니다.

|

| 패딩 위치
| 최고 검증 정확도

| 뒤쪽(post-pad)
| ≈ 0.54 (거의 못 배움)

| 앞쪽(pre-pad)
| ≈ 0.68

그래서 실제 내용이 맨 뒤에 오도록 앞쪽을 채웁니다.

## 4. 모델 조립

class IMDBRnn(nn.Module):
def __init__(self, vocab_size, embed_dim=32, hidden_size=32):
super().__init__()
# padding_idx=0: <pad>의 임베딩은 항상 0으로 두고 학습하지 않는다
self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
# batch_first=True: 입력을 (배치, 길이, 차원) 순서로 받겠다는 뜻
self.rnn = nn.RNN(embed_dim, hidden_size, batch_first=True)
self.fc = nn.Linear(hidden_size, 1) # 은닉 벡터 → 점수 하나

def forward(self, x):
x = self.embedding(x) # (배치,길이) → (배치,길이,임베딩차원)
output, hidden = self.rnn(x)
last = hidden[-1] # (배치, 은닉차원) — "끝까지 읽은 요약"
score = self.fc(last) # (배치, 1)
return torch.sigmoid(score).squeeze(-1) # (배치,) — 긍정일 확률

- output vs hidden: output 은 매 단어 위치의 은닉 전부 (배치, 길이, 은닉), hidden 은 마지막 은닉 (층수, 배치, 은닉). 1층에서는 hidden[-1] == output[:, -1, :] 입니다(실측 True).

- sigmoid: 실수 하나를 0~1 확률로 눌러 줍니다. 0.5 넘으면 긍정.

- squeeze(-1): (배치, 1) → (배치,). 군더더기 차원 하나를 뗍니다.

실측: 학습 파라미터 66,209개. 훈련 전엔 예측 확률이 0.5 근처 — 찍는 수준입니다.

## 5. 훈련시키기

학습 5단계는 Day 1과 똑같습니다. 모델만 RNN으로 바뀌었을 뿐입니다.

optimizer.zero_grad() # ① 지난 배치의 기울기를 지운다
pred = model(xb) # ② 순전파: 리뷰 → 긍정일 확률
loss = criterion(pred, yb) # ③ 손실: 예측이 정답에서 얼마나 먼가 (BCELoss)
loss.backward() # ④ 역전파: 파라미터마다 기울기를 계산
optimizer.step() # ⑤ 갱신: 기울기 방향으로 조금 이동 (Adam)

- BCELoss: Binary Cross Entropy("이진 교차 엔트로피"). 이진 분류의 표준 손실.

- torch.no_grad(): 검증은 학습이 아니니 기울기 계산을 꺼서 빠르게 합니다.

### 조기 종료(early stopping)

검증 손실이 정해진 횟수(patience)만큼 연속 나빠지면 훈련을 멈춥니다. 계속 돌리면 훈련 데이터에만 맞춰져(과적합) 새 데이터 성능이 오히려 떨어지기 때문입니다. 가장 좋았던 순간의 가중치를 저장해 두었다가 마지막에 되돌립니다.

실측:

에포크 1: 훈련손실 0.6949 · 검증손실 0.6921 · 검증정확도 0.5230
에포크 5: 훈련손실 0.6308 · 검증손실 0.6639 · 검증정확도 0.6320
에포크 9: 훈련손실 0.5559 · 검증손실 0.6208 · 검증정확도 0.6825 ← 최고
에포크 12: 훈련손실 0.5460 · 검증손실 0.6351 · 검증정확도 0.6560
→ 검증손실이 3번 연속 나빠져 조기 종료

정확도가 0.52(거의 찍기)에서 0.68까지 올랐습니다. RNN이 실제로 뭔가 배운 것입니다.

⚠️ 훈련은 실행마다 값이 조금씩 흔들립니다(시드·셔플). 0.66~0.70이면 정상입니다.
검증 2000건 기준 2%p 안팎 차이는 노이즈로 읽으세요.

### ★ 어제의 난수 임베딩이 정말 학습됐나

훈련 전에 great 의 임베딩을 저장해 두고, 훈련 후와 비교하면:

'great' 임베딩이 훈련으로 움직인 거리(L2): 1.457

0이 아닙니다. 어제 "룩업 테이블"이라고 했던 임베딩이, 오늘 역전파로 갱신되는 파라미터였다는 증거입니다. 어제 남긴 예고가 지금 일어난 것입니다.

## 6. 왜 0.68에서 막히나

### 실험 1 — 길게 보여주면 나아질까?

직관적으로는 "리뷰를 더 많이 보여주면 더 잘 맞히겠지" 싶습니다. 예상해 보고 실행해 보세요.

MAX_LEN= 50 → 0.70 MAX_LEN=100 → 0.68 MAX_LEN=200 → 0.69

평평합니다. 길게 살려도 나아지지 않습니다. 왜일까요?

### 실험 2 — 앞쪽 단어의 신호가 끝까지 가나

기울기(gradient)란? "이 입력을 조금 바꾸면 결과가 얼마나 바뀌는가"를 재는 값입니다.
앞쪽 단어의 기울기가 0에 가깝다면 — 그 단어는 결과에 영향을 거의 못 준다는 뜻입니다.

길이 100짜리 문장을 넣고 마지막 은닉으로 역전파해 위치별 기울기를 재면:

0번째 단어: 0.00e+00 ← 앞쪽: 사실상 0
50번째 단어: 2.41e-16
75번째 단어: 5.10e-08
99번째 단어: 1.95e+00 ← 맨 뒤: 살아 있다

앞쪽 단어의 신호가 마지막까지 도달하지 못합니다. 이것이 기울기 소실(vanishing gradient) 입니다.

### 실험 3 — 왜 하필 '지수적으로'

앞쪽까지 신호를 보내려면 은닉 상태를 잇는 같은 W_h 를 (거리)번 반복해 곱해야 합니다(가중치 공유의 대가). 같은 행렬을 여러 번 곱하면:

β=0.5 : 10번 5e-07 · 20번 4e-13 · 30번 5e-19 → 지수적으로 0 (소실)
β=1.5 : 10번 3e-02 · 20번 2e-03 · 30번 1e-04 → 훨씬 큼 (폭발 위험)

(β는 W_h 가 벡터를 최대 몇 배로 늘리는가 = 스펙트럴 노름)

거리에 대해 (β)^거리. 그래서 지수적으로 사라집니다. tanh 의 기울기(≤1)까지 곱해지니 실전에서는 거의 항상 소실 쪽입니다.

정확도가 0.68에서 막힌 것도, 길게 해도 안 나아진 것도 같은 뿌리입니다 —
RNN은 먼 과거를 기억하지 못합니다.

내일(Day 4) 이걸 고치는 LSTM·GRU를 배웁니다. "기억을 지키는 문(gate)"을 단 RNN입니다.
