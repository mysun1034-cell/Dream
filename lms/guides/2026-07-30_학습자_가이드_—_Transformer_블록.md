## 3. 위치 인코딩 — 논문 §3.5

### 먼저 후보를 생각해 봅니다

가장 먼저 떠오르는 답은 자리 번호를 그냥 더한다 (0, 1, 2, …) 입니다. 왜 안 될까요?

문장이 500 단어면 뒤쪽에 500 이 더해집니다. 단어의 뜻을 담은 숫자는 −1 ~ 1 근처인데,
그러면 뜻이 위치에 파묻힙니다.

### 그래서 성질부터 정합니다

|

|
| 위치를 나타내는 숫자가 만족해야 할 것

| 1
| 값이 너무 커지지 않을 것

| 2
| 위치마다 다를 것

| 3 ★
| 가까운 위치끼리는 비슷할 것

3번이 핵심입니다. 이걸 기억해 두세요 — 오늘 두 번 쓰입니다.

### 논문의 답 — 사인·코사인

PE(pos, 2i ) = sin( pos / 10000^(2i/d) ) ← 짝수 차원
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) ) ← 홀수 차원

차원마다 파장이 다른 파도를 하나씩 그리는 것입니다. 앞쪽 차원은 빠르게 출렁이고
뒤쪽 차원은 느리게 움직입니다. 그래서 위치마다 고유한 무늬가 생깁니다.

사인·코사인 위치 인코딩: (512, 768)
값의 범위 [-1.000, 1.000] ← 성질 1 만족

공식이라 길이 제한이 없습니다.

### ★ 그런데 BERT 는 실제로 뭘 쓸까요?

모델.embeddings.position_embeddings.weight

BERT 의 position_embeddings: (512, 768)
값의 범위 [-0.515, 0.246]

공식이 아닙니다. 512개 자리마다 768개 숫자를 데이터에서 그저 배웠습니다.

## 4. ✍️ ## 3 — 잔차 연결

### 먼저 문제를 봅니다

어제 만든 것을 그냥 12겹 쌓으면 어떻게 될까요? 예상해 보세요.

잔차 없이 그냥 쌓았을 때, 층을 지날수록 신호 크기:
1층 : 7.5e-01
6층 : 3.1e-03
12층 : 2.7e-06

사그라듭니다. 100층을 쌓으면 아무것도 안 남습니다.

⚠️ 이 숫자들은 무작위 가중치로 잰 것이라 돌릴 때마 달라집니다.
봐야 할 것은 값이 아니라 사라진다는 것입니다.

더 심각한 이유가 있습니다. 학습할 때 되돌아오는 신호도 같은 길을 거꾸로 지납니다.
앞쪽 층은 "너 이렇게 고쳐" 라는 말을 아예 못 듣게 됩니다.
깊게 쌓고 싶은데 깊게 쌓을 수가 없습니다.

### 해결 — 지나간 것을 다시 더해 줍니다

갈아치우기 : x ← Sublayer(x)
더하기 : x ← x + Sublayer(x) ← 잔차 연결

층이 하는 일이 "새로 만들기" 가 아니라 "조금 고치기" 가 됩니다.
원래 값은 항상 그대로 통과합니다.

## 6. ✍️ ## 5 — FFN (논문 §3.3)

### 어제 어텐션이 한 일이 정확히 뭐였죠?

가중치 @ V — 다른 자리의 값을 섞었습니다. 그게 전부입니다.

그런데 섞기만 해서는 각 자리를 자기 자리에서 따로 가공할 곳이 없습니다.
"이 자리에 모인 정보로 무엇을 판단할까" 를 할 자리가 필요합니다.

### 자리마다 작은 신경망을 하나씩

FFN(x) = max(0, xW₁ + b₁) W₂ + b₂
└─ 넓히고 ─┘ └활성┘ └─ 접고 ─┘

768 → 3072 → 768.

# ✍️ nn.Sequential 로 세 층을 잇는다: Linear → GELU → Linear
내FFN = None # TODO

⚠️ 논문은 ReLU, BERT 는 GELU 입니다. 설정.hidden_act 를 찍으면 gelu 가 나옵니다.
논문 이후에 GELU 가 더 잘 된다고 알려져서 바뀐 것이고, 넓혔다 접는 구조는 그대로입니다.

### 왜 4배로 넓혔다 줄이나

좁은 데서 바로 판단하면 표현할 수 있는 게 적습니다.
일단 넓은 곳에 펼쳐 놓고 고른 뒤, 다시 원래 크기로 접습니다.

논문도 d_model = 512 · d_ff = 2048 로 4배였습니다. 우리 모델도 768 · 3072 — 4배입니다.

### "position-wise" 의 뜻

논문 제목이 Position-wise Feed-Forward Networks 입니다. 자리마다 따로 통과시킨다는 뜻입니다.
단 가중치는 모든 자리가 같은 것을 씁니다 — 자리마다 다른 신경망을 두는 게 아닙니다.

자리마다 하나씩 넣은 결과 == 통째로 넣은 결과 : True
→ 자리끼리 섞이지 않는다. 섞는 일은 어텐션이 이미 했다.

어텐션은 섞고, FFN 은 각자 가공합니다. 블록 하나가 그 둘을 번갈아 합니다.

✅ 경계 ② 지웠습니다.

## 7. ★★★ 진짜 BERT 와 같을까

블록이 완성됐습니다. forward 가 딱 두 줄입니다.

a, _ = self.attn(x, x, x) # Sublayer ①
x = self.norm1(x + a) # 잔차 → LN
f = self.ffn(x) # Sublayer ②
x = self.norm2(x + f) # 잔차 → LN

두 줄 다 LayerNorm(x + Sublayer(x)) 꼴이고, Sublayer 자리에 각각 어텐션과 FFN 이 들어갑니다.

### 셋을 나란히 세어 보면 — 같을까요, 다를까요?

먼저 예상해 보세요.

파라미터 수
① 내가 만든 블록 7,087,872
② nn.TransformerEncoderLayer 7,087,872
③ klue/bert-base 의 한 층 7,087,872

셋이 전부 같은가 : True

어제부터 한 조각씩 만들어 온 것이, 실제로 쓰이는 모델의 한 층과 개수가 정확히 맞습니다.

### ⚠️ 함정 하나 — dim_feedforward

nn.TransformerEncoderLayer 의 기본값은 2048 입니다.

dim_feedforward 를 안 넘기면 : 5,513,984
config 에서 가져와 넘기면 : 7,087,872

그래서 숫자를 손으로 적지 않고 config 에서 가져옵니다.

### ⚠️ 모양이 같은 게 아니라 개수가 같습니다

① 내 블록 : ['attn', 'norm1', 'ffn', 'norm2']
② 파이토치 : ['self_attn', 'linear1', 'linear2', 'norm1', 'norm2', ...]
③ BERT : ['attention', 'intermediate', 'output']

파이토치는 Q·K·V 를 in_proj_weight 하나로 합쳐 뒀습니다 — 어제 가중치를 심을 때 본 그것입니다.
