## 시작 전 확인

새 터미널에서:

echo ${OPENAI_API_KEY:0:7}

sk-proj 처럼 키 앞부분이 나와야 합니다. 빈 줄이 나오면 바로 손을 듭니다 —
어제 키를 ~/.bashrc 에 안 적은 것이니 한 줄이면 고칩니다.

수업 시작할 때 오후 도구도 미리 한 줄:

uv pip install streamlit

## 오전 — 배열이 자라는 것을 눈으로

- 응답을 통째로 연다 — 문자열이 아니라 객체. finish_reason(멈춘 이유)과
usage(토큰 사용량)를 읽으면, 빈 응답이 와도 원인이 보입니다

- 일부러 실패해 본다 — 가짜 키로 401을 내고 try/except 로 받습니다. 이제 아는 오류입니다

- 역할은 셋뿐 — system(지시) · user(나) · assistant(모델의 답).
지시 하나가 답의 성격을 통째로 바꿉니다

- 기억 테스트 — 모델은 "기억할게요"라고 답해 놓고, 다음 호출에서 모릅니다.
해결은 append 두 줄 — 이것이 오늘의 전부입니다

- 토큰이 자란다 — 질문은 매번 한 줄인데 보낸 토큰이 계속 커집니다. 왜인지 표로 봅니다.
이 대화의 값도 어림해 봅니다 (단가는 추정 — 가격표에서 갱신)

- 대화를 파일로 — 배열은 데이터입니다. 저장하면 껐다 켜도 이어집니다

## 막혔을 때

|

| 증상
| 해결

| 키가 안 잡힘
| ~/.bashrc 에 export 줄 추가 → 터미널 새로 열기

| 401
| 키 오타·따옴표 — ~/.bashrc 확인

| 429
| 몇 초 기다렸다 다시

| 응답이 비거나 잘림
| finish_reason 부터 — length 면 max_completion_tokens 를 늘린다

| 챗봇이 자기 말을 잊음
| 모델 답도 append 했는지 — ③ 줄

| 앱 대화가 매번 지워짐
| 배열을 st.session_state 에 뒀는지

| streamlit 명령 없음
| uv run streamlit run app.py
