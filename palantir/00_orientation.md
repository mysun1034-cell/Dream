# Palantir DS·FDSE를 위한 SQL·Python 학습의 출발점

**작성 기준:** 2026-09-11 · 한국어 · 비전공 입문자부터 실무형 프로젝트까지  
**본과정:** Python 30강 + SQL 30강 = 60강 / 연습문제 120개와 해설 / 프로젝트 6종  
**역할 해석:** 이 자료에서 DS는 **Deployment Strategist**입니다. Data Scientist를 뜻했다면 공통 SQL·Python 학습 후 12번 문서의 보충 경로를 적용합니다.

## 1. 목표를 “문법을 안다”에서 “문제를 해결한다”로 바꾸기

이 교육의 도착점은 다음 문장을 실제 증거와 함께 말하는 것입니다.

> “누가 어떤 결정을 내려야 하는지 확인했습니다. 어떤 데이터를 믿을 수 있는지 검사했습니다. SQL과 Python으로 같은 숫자가 나오는지 검증했습니다. 사용자가 그 결과를 행동으로 옮길 수 있도록 작동하는 흐름을 만들었습니다. 오류·권한·재실행·운영 한계도 설명할 수 있습니다.”

SQL은 데이터를 조건에 맞게 찾고 연결하고 요약하는 언어입니다. Python은 파일을 읽고 데이터를 검증하고 계산을 재사용 가능한 프로그램이나 서비스로 만드는 범용 프로그래밍 언어입니다. 둘은 경쟁 관계가 아닙니다. 같은 문제에서 역할을 나눕니다.

“지연 방문을 찾아라”라는 요청을 받았다고 곧바로 코드를 쓰지 않습니다. 지연 기준은 무엇인지, 취소 방문은 포함하는지, 실제 시작 시각이 없으면 무엇으로 처리할지 먼저 정합니다. 정확하지 않은 업무 정의를 아주 빠르게 계산해도 정확한 답이 되지 않습니다.

## 2. Palantir의 두 역할을 어떻게 반영했는가

2026-09-11 확인한 서울 DS 공고는 고객의 핵심 질문과 문제를 이해하고, 관련 데이터를 찾고, FDSE와 데이터 파이프라인 및 맞춤형 업무 흐름을 만들고, 사용자 교육과 결과 전달을 수행하는 내용을 담습니다. 프로그래밍 경험은 해당 공고에서 우대 사항으로 표현됩니다. 모든 DS 직무가 특정 언어 코딩만으로 평가된다고 해석하지 않습니다. [공식 DS 공고](https://jobs.lever.co/palantir/2e193bdf-e668-49c1-ba32-66cc1aa131a4)

서울 FDSE 공고는 고객과 직접 문제를 풀며 아키텍처부터 구현까지 폭넓게 다루는 역할을 설명합니다. 서울 신입 FDSE 공고의 프로그래밍 예시는 Python 등 여러 언어이며 Python 하나만이 유일한 경로라는 뜻은 아닙니다. 해당 서울 공고들의 한국어·영어 소통 요구도 학습 계획에 반영했습니다. 지역·경력 수준·공고 시점별 조건은 지원 직전에 다시 확인해야 합니다. ## 3. 이 교재의 하나의 큰 이야기

가상의 방문 서비스 운영 조직 **CareLink Learning**에 지점 4개가 있습니다. 담당자들이 고객을 방문하고, 방문 결과와 청구·입금이 따로 기록됩니다. 운영자는 어떤 지점에 문제가 있는지, 데이터가 믿을 만한지, 무엇을 바꿔야 하는지 알고 싶어 합니다.

```text
합성 원천 CSV / 실습 이벤트
        ↓ Python: 읽기·타입 변환·검증·오류 격리
정리된 관계형 데이터
        ↓ SQL: 연결·지표·이력·품질 검사
분석 결과 + 근거 행 + 데이터 품질 상태
        ↓ Python/API: 권한 있는 사용자에게 제공
사용자의 판단·처리·피드백
        ↓
감사 기록·운영 측정·다음 개선
```

이 흐름은 학습용 설계입니다. 실제 고객 데이터·의료 정보·Palantir 비공개 자료를 사용하지 않습니다. 방문 서비스 배정 예제는 임상 판단이나 실제 의료 인력 기준을 모델링하지 않습니다.

## 4. 첫 번째 완성된 문제 정의 예시

**모호한 요청:** “지점별 지연율 좀 보여 주세요.”

**정의한 질문:** “이 합성 데이터에 저장된 2026-08-01~03의 방문 중 완료되었고 실제 시작 시각이 확인되는 방문에서, 예정 시각보다 **10분을 초과**해 시작한 비율은 얼마인가?”

**입력 한 행의 뜻:** 방문 1건. 방문 ID가 고유해야 합니다. 실제 시작 시각이 없는 완료 방문은 지연 여부를 알 수 없습니다. 취소와 예정 방문은 이 지표의 분모에서 제외합니다. 실제 업무에서는 예정 시각 변경 이력과 보고 기준 시점도 추가로 정해야 합니다.

| 항목 | 합성 데이터의 기준값 | 의미 |
|---|---:|---|
| 전체 방문 | 24 | 상태와 무관하게 저장된 방문 |
| 완료 방문 | 18 | status가 completed |
| 완료 + 실제 시작 시각 확인 | 15 | 지연 여부를 평가할 수 있는 분모 |
| 10분 초과 지연 | 6 | 지연 분자 |
| 완료 + 실제 시작 시각 누락 | 3 | 지연 여부 미확인, 별도 품질 경고 |
| 지연율 | 6/15 = 40% | 이 교재가 합의한 주지표 |

6/24, 6/18, 6/15는 서로 다른 질문의 답입니다. 무엇이 자동으로 “정답”인 것이 아니라 질문과 계산이 일치해야 합니다. 미확인 3건이 모두 정시라고 가정하면 6/18, 모두 지연이라고 가정하면 9/18입니다. 이는 결측에 대한 가정 범위이지 통계적 신뢰구간이 아닙니다.

DS 연습은 이 정의서를 설명하고 사용자 동의를 얻는 것입니다. FDSE 연습은 동일한 계약을 코드·DB 쿼리·테스트·API에서 일관되게 구현하는 것입니다.

## 5. 컴퓨터가 처음인 독자를 위한 실행 문법

**터미널**은 컴퓨터에 명령을 입력하는 창입니다. **셸**은 그 명령을 해석하는 프로그램입니다. **폴더 경로**는 파일의 위치입니다. `cd`는 현재 작업 폴더를 바꾸고 `pwd`는 그 위치를 보여 줍니다. Python의 `print()`와 터미널의 `cd`는 서로 다른 언어의 명령입니다.

**Python 인터프리터**는 Python 코드를 실행합니다. `.py`는 Python 코드 파일입니다. `.sql`은 SQL 텍스트 파일이고, SQL을 실행할 DB 엔진이 따로 필요합니다. `.md`는 제목·표·코드 블록 등을 적는 Markdown 텍스트 파일이며, 그 자체를 Python으로 실행하지 않습니다.

```bash
# 터미널에서 입력하는 예
pwd
python --version
python -c "print(6 / 15)"
```

마지막 명령의 출력은 `0.4`입니다. `python` 명령이 없으면 환경 가이드대로 Python 3 가상환경을 활성화합니다. 명령 앞의 `#` 설명은 주석입니다. 문서에서 보이는 `$` 또는 `>>>` 같은 프롬프트 표시를 실제 코드와 혼동하지 마세요. 이 교재의 실행 명령에는 그런 프롬프트를 넣지 않았습니다.

Python에서는 `=`가 값을 붙이는 대입이고, `==`가 두 값이 같은지 비교합니다. `:` 뒤의 들여쓰기는 같은 블록에 속한다는 뜻입니다. 따옴표 안의 문자열은 문자이고, 따옴표 없는 숫자는 수입니다. `print()`는 값을 화면에 보여 주고, 함수의 `return`은 호출한 코드에 값을 돌려줍니다. 화면에 보였다고 반환값이 생기는 것은 아닙니다.

SQL에서는 `SELECT` 뒤에 보고 싶은 열, `FROM` 뒤에 출처 표, `WHERE` 뒤에 행 조건을 적습니다. SQL 키워드의 대문자 표기는 읽기 위한 스타일이며 문자열 값의 비교 규칙은 별개입니다.

## 6. 한 강의를 공부하는 실제 방법

한 강의를 읽기만 하고 완료 표시하지 마세요. 용어와 비유를 자기 말로 설명하고, 코드를 가린 채 결과를 예상합니다. 실행 결과와 예상이 다르면 어느 행 또는 조건 때문에 달라졌는지 추적합니다. 마지막에는 입력 하나를 바꾸고 두 연습문제를 풉니다.

권장 90분 학습 묶음은 개념 15분, 예측·실행 25분, 변형 문제 25분, 해설 비교 15분, 말로 설명·오답 기록 10분입니다. 이는 개인 학습 배분 예시이며 실제 필요 시간은 달라집니다. 처음에는 한 강의를 여러 묶음으로 나눠도 됩니다.

다음 날에는 핵심 코드를 보지 않고 다시 쓰고, 일주일 뒤에는 숫자·키·상태를 바꾼 문제를 풉니다. 한 달 뒤에는 다른 형태의 입력으로 검증합니다. **복습의 기준은 기억한 문장이 아니라 새로운 입력에서도 지킬 수 있는 계약**입니다.

### 오답 기록 템플릿

```markdown
## 날짜 / 강의 / 문제 ID
내가 예상한 결과:
실제 결과:
틀린 원인: 문법 / 자료형 / NULL / JOIN / 분모 / 시간 / 권한 / 기타
놓친 입력 또는 업무 가정:
가장 작은 반례:
수정한 규칙:
추가한 테스트:
코드를 보지 않고 다시 설명한 문장:
```

“안 돼요” 대신 실행 명령, 현재 폴더, 전체 오류 메시지, 기대 결과, 실제 결과, 사용한 입력을 함께 기록합니다. 비밀번호·실제 고객 데이터는 붙이지 않습니다. 오류 메시지의 마지막 줄만 읽지 말고 어느 파일의 어느 줄에서 시작됐는지 함께 봅니다.

## 7. 진도 조절용 진단 12문항

아래는 선발 시험이 아니라 시작점을 찾는 점검입니다. 답을 외웠어도 설명이나 예제를 못 만들면 해당 강의를 공부합니다.

| 2 | print와 return은 같은가? | 아니다. 화면 출력과 호출자에게 값 반환. PY-B07 |

| 5 | 리스트 두 변수에 같은 객체를 넣고 수정하면? | 공유한 객체가 바뀔 수 있다. PY-B04 |

| 7 | 청구 한 건에 입금 두 건을 JOIN한 뒤 청구 합계를 더하면? | 청구가 두 번 더해질 수 있다. SQL-I03 |
| 8 | 고객별 최신 방문을 정확히 1개 고르는 방법은? | 키별 ROW_NUMBER와 명확한 타이브레이커. SQL-I04 |
| 9 | await는 프로그램 전체를 멈추는가? | 현재 코루틴이 실제 대기를 하면 다른 준비된 작업이 진행 가능. PY-A04 |
| 10 | 같은 파일을 두 번 적재해도 중복이 없어야 할 때 필요한 것은? | 키·버전·멱등 처리·재실행 테스트. PY-A05 / SQL-A05 |
| 11 | branch_id만 바꾸면 다른 지점을 볼 수 있어도 되는가? | 안 된다. 인증 주체 기반 인가가 필요. PY-A06 / SQL-A08 |
| 12 | 파티션·인덱스를 만들면 성능이 반드시 좋아지는가? | 아니다. 대표 부하와 계획으로 검증. SQL-A01~02 / A09 |

## 8. 이 과정의 범위와 경계

이 자료는 SQL·Python 중심의 기초부터 운영 사고까지의 교육 자료입니다. 실제 Foundry 환경을 제공하거나 모든 기능을 구현한 상용 ERP를 제공하는 것은 아닙니다. 로컬 예제 API는 학습용이며 운영 인증·감사·비밀 관리·대규모 배포를 대신하지 않습니다.
