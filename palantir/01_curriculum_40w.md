## 4. 단계별 통과 시험

### 기본 통과: 90분 개별 과제

새 지점 하나와 완료 방문 2건을 추가한 별도 복사 데이터를 받았다고 가정합니다. 한 건은 10분, 한 건은 실제 시각 누락입니다. 기존 파일을 통째로 외우지 말고 입력 계약을 적용합니다. Python과 SQL로 상태별 건수·평가 가능 건수·지연율을 구하고 0건인 지점도 표시합니다.

통과 조건은 분모 설명, NULL/None 처리, 10분 초과 경계, 정렬, 실행 재현입니다. 원본 DB를 바꾸기보다 bootstrap 시드 함수를 이용한 메모리 DB 또는 임시 파일에서 실험합니다. 기준 숫자를 바꿨으면 수정 데이터에 맞는 기대값을 독립적으로 계산합니다.

### 중급 통과: 2시간 분석 과제

청구별 입금이 여러 번 존재하는 데이터를 연결하고, 고객별 최신 방문과 미방문 고객을 구합니다. 같은 KPI를 pandas와 SQL로 대사합니다. 날짜 범위·업무 시간대·누락 처리·동률 최신 기준을 정의합니다. 잘못된 JOIN 결과를 일부러 만들고 왜 합계가 커지는지 설명하는 반례도 제출합니다.

### 심화 통과: 구현·검토 과제

ETL 동일 입력 재실행, 잘못된 행 격리, 지점 권한 차단, 버전 충돌 처리, 품질 경고를 시연합니다. PostgreSQL을 실행하지 않았다면 해당 검증을 설계만 완료로 표시합니다. SQLite 통과를 PostgreSQL 성능·RLS·동시성 검증으로 대체하지 않습니다.

### 공통 평가 기준: 100점

| 영역 | 배점 | 좋은 증거 |
|---|---:|---|
| 업무 정의·분모·입출력 계약 | 20 | 사용자·의사결정·제외 기준 명시 |
| 계산·구현 정합성 | 25 | 키·JOIN·시간·NULL의 정확성과 재현 |
| 테스트·반례·검증 | 20 | 경계·결측·중복·권한 실패 검증 |
| 설계·운영·보안 | 20 | 권한·재실행·실패 복구·비밀 관리·한계 |

80점 이상을 권장 통과선으로 삼되, 분모를 설명할 수 없음·타 지점 데이터 유출·운영 DB 무단 변경·실제 개인정보 노출은 점수와 관계없이 수정합니다. 이 기준은 학습용이며 Palantir 공식 평가 기준이 아닙니다.

## 5. 역할별 깊이 조절

**DS 중심:** 60강의 정의와 실습을 모두 접하되, 기본·중급의 데이터 정합성과 사용자 문제 정의를 직접 풀 수 있어야 합니다. 심화에서는 핵심 API/ETL을 실행하고 제약과 위험을 설명하는 능력을 확보합니다. P01·P05·P06에서 의사결정 메모, 사용자 관찰, 도입 후 검증을 더 깊게 합니다. 기술을 전부 남에게 맡기는 경로로 사용하지 않습니다.

**FDSE 중심:** 모든 구현·테스트를 수행하고 SQL-A03의 동시 세션 실험, SQL-A08의 실제 앱 역할 검증, API 저장소 교체와 성능 측정을 확장합니다. P02·P03·P04·P06에서 오류·규모·보안·관측성을 강화합니다. 사용자 질문을 생략하는 경로로 사용하지 않습니다.

**병행 목표:** 주간 제출물마다 DS용 1쪽 판단 메모와 FDSE용 설계·테스트 설명을 함께 남깁니다. 같은 내용을 두 번 만드는 대신 같은 증거를 서로 다른 독자에게 설명합니다.

## 6. 독학 피드백의 최소 단위

매주 이번 주에 틀린 가장 중요한 가정 1개, 그 가정을 깨는 가장 작은 입력 1개, 다음에 자동으로 잡을 테스트 1개를 기록합니다. 새 라이브러리를 계속 추가하기보다 가장 작은 입력에서 원리를 확인합니다.

코드를 AI로 작성했더라도 예상 결과, 실패 조건, 입력 계약, 권한 경계를 직접 설명해야 합니다. 설명하지 못하는 코드는 포트폴리오의 완성 증거로 세지 않습니다.
