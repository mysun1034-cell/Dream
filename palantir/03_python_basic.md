## PY-B01 · 프로그램·변수·자료형: 컴퓨터에게 계산을 맡기는 첫 문장

**학습 목표:** 값을 저장하고 계산한 뒤, 숫자의 업무 의미를 설명한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

프로그램(program)은 컴퓨터가 수행할 명령의 묶음이다. 변수(variable)는 값을 가리키는 이름이다. 자료형(type)은 그 값으로 어떤 연산을 할 수 있는지 정하는 종류다. 정수 int, 실수 float, 문자열 str, 참/거짓 bool부터 익힌다.

### 2. 비유로 잡는 그림

변수는 상자 자체보다 상자에 붙이는 이름표에 가깝다. 같은 값에 이름표를 여러 개 붙일 수 있다.

### 3. 원리와 업무에서의 의미

SQL은 데이터베이스에 “어떤 결과가 필요한가”를 표현하고, Python은 파일 읽기·계산·통신·결과 저장처럼 여러 작업을 연결한다. 두 언어는 경쟁 관계가 아니라 역할 분담 관계다. 지점 지연율을 SQL로 계산한 뒤 Python으로 보고서를 만들 수 있다.

`=`는 수학의 등호가 아니라 대입이다. 오른쪽을 먼저 계산하고 왼쪽 이름에 연결한다. `late = late + 1`도 그래서 가능하다. `==`는 두 값이 같은지 묻는 비교다. 문자열의 따옴표는 글자라는 표시이며 숫자 6과 문자열 "6"은 다르다.

프로그램이 실행되는 순서를 위에서 아래로 따라가자. 계산 결과가 맞아도 분모가 잘못되면 업무 답은 틀린다. 아래 24는 전체 방문 수지만, 실제 시작 시간을 아는 완료 방문은 15건이다. 지연율을 설명할 때는 어느 집단의 비율인지 함께 말해야 한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B01
```

```python
total_visits = 24
eligible_visits = 15
late_visits = 6
late_rate = late_visits / eligible_visits
print(total_visits)
print(type(late_visits).__name__)
print(f"측정 가능한 방문의 지연율: {late_rate:.1%}")
```

### 5. 결과와 코드 해설

```text
24
int
측정 가능한 방문의 지연율: 40.0%
```

첫 세 줄은 업무 숫자에 이름을 붙인다. `/`는 나눗셈을 수행한다. `print`는 화면에 보여 주는 함수다. `f"...{값}..."`는 계산 결과를 문장에 넣는 문법이며 `:.1%`는 소수점 한 자리 백분율 형식이다. 저장된 비율 자체를 40으로 바꾸는 것은 아니다.

### 6. 자주 하는 실수

6/24=25%도 계산은 맞지만, 이 교재의 측정 가능한 완료 방문 지연율은 아니다. 변수 이름을 `x`, `y`로만 쓰면 이런 분모 혼동을 발견하기 어렵다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** “전체 방문”과 “측정 가능한 완료 방문”의 차이를 고객에게 설명한다.

**FDSE 관점:** 코드에서 어떤 숫자를 쓰는지 이름과 자료형으로 드러낸다.

## PY-B02 · 문자열·형 변환·금액: 사람의 입력을 계산 가능한 값으로

**학습 목표:** 공백과 대소문자를 정리하고, 금액의 단위를 명확하게 유지한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

문자열 메서드(method)는 문자열에 붙여 부르는 기능이다. 형 변환(casting)은 값의 표현 종류를 바꾸는 작업이다. Decimal은 십진수 계산을 위한 자료형이다.

### 2. 비유로 잡는 그림

고객이 쓴 신청서를 접수 규격에 맞추는 일이다. 공백 정리는 서식을 고치는 것이지, 내용을 마음대로 바꾸는 작업이 아니다.

### 3. 원리와 업무에서의 의미

CSV 파일의 숫자는 읽었을 때 문자열일 수 있다. "10000"을 합계에 쓰려면 정수로 바꾼다. `strip()`은 앞뒤 공백을 없애고 `lower()`는 영문 대문자를 소문자로 바꾼다. `" COMPLETED "`를 `completed`로 정규화한 뒤 허용된 상태인지 검증한다.

금액은 계산 단위를 먼저 정한다. 실습의 `_cents`는 1/100 화폐 단위를 뜻하며 실제 원화 매출이 아니다. 실제 KRW 시스템이라면 원 단위 정수 같은 도메인 규칙을 별도로 정해야 한다. 정수 단위 또는 문자열에서 만든 Decimal을 사용하면 이진 부동소수점 표현 때문에 생기는 금액 오차를 피하기 쉽다.

`Decimal(0.1)`은 이미 부동소수점으로 해석된 값을 받는다. 정확한 십진 입력을 표현하려면 `Decimal("0.1")`처럼 문자열을 사용한다. 반올림 시점과 방법 역시 회계·계약 규칙에 맞춰 합의해야 한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B02
```

```python
from decimal import Decimal

status = " COMPLETED ".strip().lower()
fee_cents = int("10000")
fee_units = Decimal(fee_cents) / Decimal("100")
print(status)
print(f"{fee_units:.2f}")
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))
```

### 5. 결과와 코드 해설

```text
completed
100.00
True
```

문자열 뒤의 점은 그 값에 속한 기능을 부르는 표시다. 메서드를 이어 붙이면 앞의 결과가 다음 메서드의 입력이 된다. `int`는 정수 변환, `Decimal`은 십진수 객체 생성에 쓰인다. 마지막 줄은 계산 결과가 같은지 비교하므로 True 또는 False를 출력한다.

### 6. 자주 하는 실수

쉼표나 통화 기호를 무조건 지우지 않는다. "1,234"가 천 단위인지 소수 표현인지는 입력 규약에 따라 다르다. 원본 값도 남긴다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 금액 단위와 상태값의 정의를 데이터 사전에 기록한다.

**FDSE 관점:** 정규화와 유효성 검증을 별도 단계로 구현한다.

## PY-B03 · 조건문·None·경계값: 업무 규칙을 빠짐없이 표현하기

**학습 목표:** 완료·취소·미측정 상태를 분리하고 10분 경계값을 정확히 처리한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

조건문은 조건에 따라 실행 경로를 선택한다. None은 값이 없음을 나타내는 특별한 값이다. 경계값은 규칙이 바뀌는 지점이다.

### 2. 비유로 잡는 그림

접수 담당자가 “취소인가? 완료인가? 시간을 기록했는가?”를 순서대로 확인하는 체크 절차다.

### 3. 원리와 업무에서의 의미

이 교재의 학습용 지연 규칙은 “완료되었고 시작 시간이 알려진 방문 중 실제 시작이 예정 시작보다 10분을 초과한 경우”다. 정확히 10분은 지연이 아니다. 실제 기관의 서비스 기준이라고 해석하지 않는다.

`if`, `elif`, `else`는 위에서부터 검사해 처음 참인 경로를 실행한다. Python은 들여쓰기로 코드 묶음을 구분한다. 상태가 취소이면 시간 비교까지 할 필요가 없다. 시간 값이 없으면 지연/정시 중 하나로 억지 분류하지 않고 unknown으로 둔다.

`if delay:`는 이 사례에서 위험하다. 0도 거짓으로 취급되므로 정시 도착을 결측처럼 처리할 수 있다. 값의 부재를 확인할 때는 `delay is None`을 쓴다. 이 구별은 분석 분모와 사용자 경고를 모두 바꾼다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B03
```

```python
status = "completed"
delay = 10

if status != "completed":
    label = "excluded"
elif delay is None:
    label = "unknown"
elif delay > 10:
    label = "late"
else:
    label = "on_time"
print(label)
```

### 5. 결과와 코드 해설

```text
on_time
```

`!=`는 같지 않다는 비교다. 먼저 분석 대상이 아닌 상태를 제외한다. 다음으로 측정 불가능한 경우를 제거한 뒤 숫자 비교를 수행한다. 이 순서 덕분에 `None > 10` 같은 잘못된 연산을 피한다. 출력은 `on_time`이다.

### 6. 자주 하는 실수

조건을 `>= 10`으로 바꾸면 업무 규칙도 바뀐다. 비슷해 보이는 연산자 한 글자가 보고서 수치를 바꿀 수 있다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 분석 전에 이해관계자에게 경계값·제외 조건·결측 정책을 확인한다.

**FDSE 관점:** 0, 10, 10.1, None, 취소 상태를 테스트 입력으로 만든다.

## PY-B04 · 리스트·튜플·참조: 여러 값을 안전하게 다루기

**학습 목표:** 여러 방문 값을 순서대로 보관하고, 원본 변경의 영향을 예측한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

리스트(list)는 순서가 있고 수정 가능한 자료구조다. 튜플(tuple)은 순서가 있지만 항목 교체가 불가능하다. 인덱스(index)는 항목의 위치이며 0부터 시작한다.

### 2. 비유로 잡는 그림

리스트는 수정 가능한 대기 명단, 튜플은 한 번 작성한 좌표 묶음으로 생각할 수 있다.

### 3. 원리와 업무에서의 의미

지연값 하나로는 지점을 비교할 수 없다. 리스트를 사용하면 여러 방문의 값을 하나의 이름으로 다룰 수 있다. `values[0]`은 첫 항목이고 `values[-1]`은 마지막 항목이다. `values[1:3]`은 위치 1부터 3 직전까지의 새 리스트다.

`b = a`는 리스트를 복사하지 않는다. 같은 리스트를 두 이름이 가리키게 한다. b를 통해 수정하면 a로 볼 때도 바뀐다. `a.copy()`는 바깥 리스트를 복사하지만 내부의 딕셔너리까지 깊게 복사하지는 않는다.

업무 분석에서는 원본과 가공본을 구별하는 습관이 중요하다. 원본을 실수로 바꾸면 이전 결과를 재현하기 어려워진다. 먼저 작은 예제로 참조를 확인하고, 이후 pandas에서 원본과 파생 표를 나누는 원리로 연결한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B04
```

```python
delays = [0, 15, 30]
alias = delays
copied = delays.copy()
alias.append(5)
print(delays)
print(copied)
print(delays[1:3])
window = ("2026-08-01", "2026-09-01")
print(window[0])
```

### 5. 결과와 코드 해설

```text
[0, 15, 30, 5]
[0, 15, 30]
[15, 30]
2026-08-01
```

append는 리스트 끝에 값을 추가하고 원본을 변경한다. alias는 같은 리스트를 가리키므로 delays에도 5가 생긴다. copied는 별도의 바깥 리스트이므로 [0,15,30]을 유지한다. 날짜 구간 튜플은 시작·끝의 한 쌍을 표현한다.

### 6. 자주 하는 실수

`new_list = old_list.append(5)`의 new_list는 리스트가 아니라 None이다. append는 변경 결과를 새 리스트로 돌려주지 않는다.

## PY-B05 · 딕셔너리·집합: 업무 객체와 중복을 표현하기

**학습 목표:** 방문 한 건을 속성 묶음으로 표현하고, 중복 ID를 탐지한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

딕셔너리(dict)는 키와 값의 대응이다. 집합(set)은 중복 없는 값의 모음이다. 키(key)는 값을 찾는 이름이다.

### 2. 비유로 잡는 그림

딕셔너리는 항목 이름이 붙은 신청서이고, 집합은 출석 여부만 확인하는 명단이다.

### 3. 원리와 업무에서의 의미

리스트 `[1, "completed", 15]`는 각 위치의 뜻을 기억해야 한다. 딕셔너리 `{"visit_id":1,"status":"completed"}`는 이름으로 뜻을 드러낸다. `row["status"]`는 필수 항목이 없으면 오류를 내고, `row.get("note")`는 없으면 None을 돌려준다.

어떤 키가 필수인지에 따라 접근법을 고른다. 모든 항목을 get으로 읽으면 필수 값 누락까지 조용히 통과할 수 있다. 데이터 계약에서 visit_id와 status를 필수로 정했으면 누락을 실패 또는 격리로 다루는 편이 명확하다.

집합은 ID 중복을 찾는 데 유용하지만 순서와 중복 개수를 잃는다. `len(ids) - len(set(ids))`는 전체 행 수에서 서로 다른 ID 수를 뺀 값이다. 어떤 행을 남길지 결정하는 중복 제거 정책과는 별개의 작업이다.

```python
print(sorted(set(ids)))
print(len(ids) - len(set(ids)))
```

```text

```

### 6. 자주 하는 실수

## PY-B06 · 반복문·컴프리헨션: 여러 행에서 답을 모으기

**학습 목표:** 반복 처리로 분모·분자를 계산하고, 누락값을 의도적으로 제외한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

반복문(loop)은 여러 항목에 같은 작업을 적용한다. 누산기(accumulator)는 반복 중 결과를 쌓는 변수다. 컴프리헨션은 반복과 조건을 이용해 새 자료구조를 만드는 문법이다.

### 2. 비유로 잡는 그림

방문 기록을 한 장씩 보면서 측정 가능 건수와 지연 건수에 각각 체크 표시를 한다.

### 3. 원리와 업무에서의 의미

for는 리스트 같은 반복 가능한 자료에서 항목을 하나씩 꺼낸다. 반복 안에서 누산기를 초기화하면 합계가 매번 사라진다. 그래서 eligible과 late는 반복문 밖에서 0으로 만든다.

`continue`는 현재 항목의 남은 처리를 건너뛰고 다음 항목으로 넘어간다. 결측값을 먼저 건너뛰면 그 뒤에는 숫자만 남는다. 컴프리헨션은 같은 처리를 간단히 표현하지만, 복잡한 검증·로그가 필요할 때는 일반 for가 더 읽기 쉽다.

아래는 이미 완료 방문에서 추출한 지연값이라고 가정한다. 실습 전체 CSV를 분석할 때는 먼저 status 필터도 필요하다. 코드가 맞는 범위를 명시하는 습관이 중요하다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B06
```

```python
completed_delays = [0, 15, 30, 5, None, 10]
eligible = 0
late = 0
for delay in completed_delays:
    if delay is None:
        continue
    eligible += 1
    if delay > 10:
        late += 1
print(eligible, late)
print([d for d in completed_delays if d is not None and d > 10])
```

### 5. 결과와 코드 해설

```text
5 2
[15, 30]
```

`+= 1`은 현재 값에 1을 더해 다시 저장한다. 결측 한 건을 제외해 eligible은 5, 지연값 15와 30 때문에 late는 2가 된다. 컴프리헨션의 두 조건은 `and`로 연결되며 왼쪽이 거짓이면 오른쪽을 평가하지 않아 None 비교를 피한다.

### 6. 자주 하는 실수

반복 중 원본 리스트에서 항목을 삭제하면 일부 행을 건너뛸 수 있다. 필요한 값으로 새 리스트를 만드는 방식이 더 명확하다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 제외된 건수도 함께 보고해 좋은 수치 뒤의 누락을 숨기지 않는다.

**FDSE 관점:** 반복의 시간 복잡도와 중간 데이터의 메모리 사용을 설명한다.

## PY-B07 · 함수·인자·반환값·범위: 규칙을 한 곳에 모으기

**학습 목표:** 입력과 출력을 명시한 함수를 만들고 재사용한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

함수(function)는 이름을 붙인 작업 단위다. 매개변수(parameter)는 함수가 받을 입력의 이름이고 인자(argument)는 실제 전달한 값이다. 반환값(return value)은 호출한 쪽에 돌려주는 결과다.

### 2. 비유로 잡는 그림

함수는 “완료 방문 지연율 계산기”처럼 입력과 출력을 약속한 작업 창구다.

### 3. 원리와 업무에서의 의미

같은 규칙을 노트북 세 곳에 복사하면 한 곳만 수정될 수 있다. 함수를 만들면 규칙을 한 곳에 모아 테스트할 수 있다. 좋은 함수는 이름만 보고도 무엇을 받아 무엇을 돌려줄지 짐작할 수 있다.

print는 화면에 보여 줄 뿐이고 return은 다른 코드가 결과를 사용할 수 있게 한다. 출력만 하는 함수는 결과를 JSON이나 API 응답으로 조합하기 어렵다. 함수 안에서 만든 지역 변수는 일반적으로 그 함수 안에서 사용한다.

`int`와 `float | None` 같은 타입 힌트는 의도를 표시하지만 자동 입력 검증을 대신하지 않는다. 비율 함수는 음수와 분자>분모를 명시적으로 검사한다. 0건에서의 지연율은 0%가 아니라 정의되지 않은 값으로 반환한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B07
```

```python
def rate(numerator: int, denominator: int) -> float | None:
    if numerator < 0 or denominator < 0 or numerator > denominator:
        raise ValueError("invalid counts")
    if denominator == 0:
        return None
    return numerator / denominator

result = rate(6, 15)
print(result)
print(rate(0, 0))
```

### 5. 결과와 코드 해설

```text

None
```

### 6. 자주 하는 실수

`def add_item(item, items=[])`처럼 수정 가능한 기본 인자를 쓰면 호출 사이에 같은 리스트가 공유될 수 있다. None을 기본값으로 두고 함수 안에서 새 리스트를 만든다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 0건의 지표를 0%로 표현할 때 생기는 오해를 사용자와 논의한다.

### 2. 비유로 잡는 그림

with는 자료실에서 파일을 빌린 뒤 작업이 끝나면 반납 절차까지 함께 묶어 두는 방식이다.

### 3. 원리와 업무에서의 의미

파일 경로는 파일이 있는 위치다. 상대 경로는 현재 작업 폴더를 기준으로 해석되므로 어느 폴더에서 실행하느냐에 따라 달라질 수 있다. 실습 보조 모듈은 자신의 파일 위치를 기준으로 data 폴더를 찾도록 작성했다.

`with open(...) as f`는 파일 작업 범위를 명확히 하고 범위를 벗어나면 닫도록 한다. CSV는 단순히 쉼표로 split하면 안 된다. 값 자체에 쉼표나 줄바꿈이 들어갈 수 있기 때문이다. csv.DictReader는 열 이름을 키로 하는 딕셔너리를 만든다.

JSON은 Python 딕셔너리 그 자체가 아니라 직렬화된 표현이다. `json.dumps`는 객체를 JSON 문자열로 바꾸고 `json.loads`는 반대로 읽는다. 기밀 데이터와 인증정보를 출력·저장하지 않는 습관도 이 단계에서 시작한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B08
```

```python
import csv
import json
from pathlib import Path

path = Path("data") / "visits.csv"  # lab 폴더에서 실행
with path.open(encoding="utf-8", newline="") as file:
    rows = list(csv.DictReader(file))
summary = {"rows": len(rows), "first_visit": int(rows[0]["visit_id"])}
print(json.dumps(summary, ensure_ascii=False))
```

### 5. 결과와 코드 해설

```text
{"rows": 24, "first_visit": 1}
```

Path의 `/`는 경로 요소를 결합한다. open은 파일을 열고 DictReader는 첫 행을 열 이름으로 사용한다. list로 감싸 전체 행을 메모리에 읽었다. 작은 학습 자료에는 적절하지만 대형 파일은 반복 읽기나 청크 처리를 고려한다. 출력은 rows 24, first_visit 1이다.

### 6. 자주 하는 실수

파일이 안 열린다고 임의로 전체 디스크를 검색하지 말고 `pwd`, 파일명, 현재 폴더, 대소문자를 차례로 확인한다. 경로와 인코딩 오류를 구분한다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 데이터를 받은 시점·파일 출처·행 수를 분석 기록에 남긴다.

**FDSE 관점:** 경로·인코딩·파일 닫기·대형 파일 메모리 문제를 설계에 반영한다.

## PY-B09 · 예외·검증·디버깅: 틀린 데이터를 조용히 통과시키지 않기

**학습 목표:** 예상 가능한 입력 오류를 분리하고, 실패한 행을 기록한다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

예외(exception)는 정상 흐름을 중단하는 오류 신호다. traceback은 오류가 발생한 호출 경로다. 검증(validation)은 입력이 약속한 조건을 만족하는지 검사하는 작업이다.

### 2. 비유로 잡는 그림

잘못 작성된 신청서를 쓰레기통에 버리지 않고, 사유를 적어 보완함에 넣는 과정이다.

### 3. 원리와 업무에서의 의미

프로그램 오류와 데이터 오류를 구별해야 한다. 숫자여야 할 칸에 "bad"가 들어온 것은 예상 가능한 데이터 오류다. 변수 이름을 잘못 쓴 NameError는 코드 오류다. 둘을 모두 except Exception으로 삼키면 진짜 버그가 숨는다.

try에는 실패할 수 있는 작업을, except에는 특정 예외가 발생했을 때의 대응을 둔다. 오류를 무시하는 대신 행 번호·원본 식별자·사유를 남기면 고객에게 무엇을 수정해야 하는지 설명할 수 있다.

디버깅은 무작정 코드를 바꾸는 작업이 아니다. 기대값을 먼저 적고, 가장 작은 실패 입력을 만들고, 중간 값과 자료형을 확인한 뒤 원인을 고친다. 수정 후에는 동일 오류가 다시 생기지 않도록 테스트를 추가한다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B09
```

```python
raw_ids = ["101", "bad", "-3", "102"]
valid = []
errors = []
for line, raw in enumerate(raw_ids, start=1):
    try:
        visit_id = int(raw)
        if visit_id <= 0:
            raise ValueError("ID must be positive")
        valid.append(visit_id)
    except ValueError as exc:
        errors.append({"line": line, "reason": str(exc)})
print(valid)
print([error["line"] for error in errors])
```

### 5. 결과와 코드 해설

```text
[101, 102]
[2, 3]
```

enumerate는 값과 함께 순번을 제공한다. int 변환 실패와 음수 검증 실패를 모두 ValueError로 다룬다. 통과한 ID는 101,102이고 실패 행 번호는 2,3이다. 오류 사유의 전체 문구는 Python 버전에 따라 달라질 수 있으므로 여기서는 행 번호를 검증한다.

### 6. 자주 하는 실수

`except: pass`는 성공처럼 보이는 데이터 손실을 만든다. 실패를 기록하거나 호출자에게 전달하고, 코드 버그까지 데이터 오류로 처리하지 않는다.

### 7. 같은 기술, 두 역할의 질문

**DS 관점:** 실패율이 높을 때 보고서를 중단할 기준과 고객에게 알릴 내용을 정한다.

**FDSE 관점:** 오류 분류·격리·재처리·회귀 테스트를 하나의 흐름으로 만든다.

## PY-B10 · 모듈·실행 진입점·명령행: 첫 업무 분석 프로그램

**학습 목표:** 작성한 계산을 다른 파일에서 불러와 재실행 가능한 분석으로 만든다.

**실행 구분:** Python 3.12 이상 대상; 제작 환경 Python 3.13.5에서 실행 확인

### 1. 용어부터 이해하기

모듈(module)은 가져와 사용할 수 있는 Python 파일이다. import는 모듈의 기능을 사용 가능하게 한다. CLI는 명령행에서 실행하는 인터페이스다. 진입점(entry point)은 프로그램 실행이 시작되는 지점이다.

### 2. 비유로 잡는 그림

함수는 부품이고 모듈은 부품 상자다. main은 어떤 부품을 어떤 순서로 사용할지 정하는 조립 설명서다.

### 3. 원리와 업무에서의 의미

노트북에서 우연히 실행된 변수에 의존하면 다른 사람이 재현하기 어렵다. 파일을 읽고 계산하고 결과를 출력하는 시작과 끝을 main 함수로 묶는다. 필요한 보조 기능은 course_lib.py에서 가져온다.

`if __name__ == "__main__"`은 이 파일을 직접 실행했을 때만 main을 호출한다. 다른 파일이 import했을 때 데이터 처리까지 자동으로 시작되지 않게 하는 장치다. 처음에는 낯설어도 “가져올 때와 실행할 때를 분리한다”는 뜻을 기억하면 된다.

가상환경은 프로젝트의 패키지 설치 공간을 분리한다. Git은 코드 변경 이력을 남긴다. .env는 비밀 저장소 자체가 아니라 환경 설정을 담는 관행적 파일명이며 저장소에 비밀을 커밋하면 안 된다. 이 기초 프로젝트는 인증정보 없이 실행되도록 만들었다.

### 4. 따라 하는 예제

```bash
python -m examples.PY_B10
```

```python
import json
from course_lib import read_csv, kpi

def main() -> None:
    rows = read_csv("visits")
    result = kpi(rows)
    print(json.dumps(result, ensure_ascii=False, sort_keys=True))

if __name__ == "__main__":
    main()
```

### 5. 결과와 코드 해설

```text
{"completed": 18, "eligible": 15, "late": 6, "late_rate": 0.4, "total": 24, "unknown": 3}
```

read_csv는 파일을 읽고 kpi는 업무 규칙을 적용한다. main은 작업 순서만 담당한다. 결과는 total 24, completed 18, eligible 15, late 6, unknown 3, late_rate 0.4다. 같은 입력을 다시 실행하면 같은 결과가 나와야 한다.

### 6. 자주 하는 실수

`pip install`을 했는데 import가 안 되면 다른 Python에 설치했을 수 있다. `python -m pip`와 `python -c "import sys; print(sys.executable)"`로 실행 환경을 확인한다.
