# 용어 100개·오답 패턴·복습 카드

처음 보는 단어를 만나면 이 사전에서 뜻을 찾고 해당 강의의 작은 예제로 돌아가세요. 아래 정의는 입문용이며 상세한 타입·DB 제품별 제약은 본문 공식 문서를 따릅니다.

## 데이터와 업무 의미

| 번호 | 용어 | 쉬운 정의와 주의점 |
|---:|---|---|
| 1 | 데이터 | 계산·판단에 사용하는 기록. 기록되었다고 자동으로 정확한 사실은 아니다. |
| 2 | 데이터베이스 / DB | 데이터를 구조적으로 저장하고 조회·변경하는 시스템. |
| 3 | 관계형 DB | 행과 열의 관계형 구조와 제약을 사용해 데이터를 관리하는 DB. |
| 4 | SQL | 관계형 데이터를 정의·조회·변경하는 데 사용하는 언어. DB 제품 이름이 아니다. |
| 5 | 테이블 | 같은 구조의 행을 담는 표. visits는 방문 표다. |
| 6 | 행 / row | 표에 저장된 기록 하나. visits에서는 방문 한 건. |
| 7 | 열 / column | 행마다 갖는 속성. status·visit_id 등이 열이다. |
| 8 | 스키마 | 데이터의 구조·타입·제약 정의. PostgreSQL에서는 이름 공간 의미도 있다. |
| 9 | grain / 행 단위 | 한 행이 정확히 무엇 하나를 뜻하는지 정한 기준. 방문과 입금은 다르다. |
| 10 | 기본키 / primary key | 각 행을 고유하게 식별하는 키. 같은 방문 ID는 두 행에 중복되면 안 된다. |
| 11 | 외래키 / foreign key | 다른 표의 참조 대상 키와 관계를 유지하는 제약. |
| 12 | 카디널리티 | 관계나 결과의 개수 특성. 청구:입금은 1:N일 수 있다. |
| 13 | 메타데이터 | 데이터를 설명하는 정보. 단위·기준 시각·출처·소유자 등이 예다. |
| 14 | 데이터 계약 | 키·타입·단위·누락·시점·책임·변경 규칙을 합의한 약속. |
| 15 | KPI | 업무 상태나 목표를 관찰하기로 정한 핵심 지표. 계산식만이 아니라 목적이 필요하다. |
| 16 | 분모 | 비율에서 기준이 되는 전체 대상의 수. 지연율의 의미를 결정한다. |
| 17 | 코호트 | 공통 기준으로 묶은 집단. 가입 월별 고객 집단 등이 예다. |
| 18 | 리텐션 | 정의한 초기 집단이 이후 기간에 다시 활동하는 정도. 단순 활성률과 다르다. |
| 19 | 합성 데이터 | 실제 개인 기록이 아니라 학습·시험을 위해 만든 데이터. |
| 20 | 대사 / reconciliation | 독립적인 합계·키·건수를 비교해 누락·중복·불일치를 확인하는 작업. |

## Python의 첫 구조

| 번호 | 용어 | 쉬운 정의와 주의점 |
|---:|---|---|
| 21 | 프로그램 | 컴퓨터가 수행할 절차를 적은 코드의 묶음. |
| 22 | 인터프리터 | Python 코드를 실행하는 프로그램. 터미널 자체와 다르다. |
| 23 | 변수 | 객체를 가리키는 이름. 이름과 객체를 같은 것으로 혼동하지 않는다. |
| 24 | 자료형 / type | 값이 어떤 종류인지 나타내는 규칙. int·str·list 등이 있다. |
| 25 | int / float | 정수와 부동소수점 수. 금액은 단위와 오차 처리를 정해야 한다. |
| 26 | 문자열 / str | 글자의 연속. 숫자처럼 생긴 문자열도 숫자 계산 전 변환이 필요할 수 있다. |
| 27 | bool | True·False의 참/거짓 값. None과 같은 타입이 아니다. |
| 28 | None | Python에서 값 없음·미확인 등을 표현할 때 사용하는 특별한 객체. |
| 29 | 리스트 / list | 순서가 있고 수정 가능한 여러 값의 컨테이너. |
| 30 | 튜플 / tuple | 항목 배치를 직접 바꿀 수 없는 순서 컨테이너. 내부 객체가 모두 불변인 것은 아니다. |
| 31 | 딕셔너리 / dict | 키로 값을 찾는 자료구조. 같은 키를 대입하면 이전 값을 바꿀 수 있다. |
| 32 | 집합 / set | 중복 없는 원소 집합. 표시 순서에 의존하지 않는다. |
| 33 | 가변 / mutable | 생성 뒤 내부 상태를 수정할 수 있다는 성질. list가 예다. |
| 34 | 참조 | 다른 이름이 같은 객체를 가리킬 수 있다는 관계. 얕은 복사에도 내부 공유가 남을 수 있다. |
| 35 | 함수 | 입력을 받아 정해진 작업을 수행하는 재사용 가능한 코드 단위. |
| 36 | 매개변수 / 인자 | 정의 쪽 입력 이름이 매개변수, 호출하며 전달한 값이 인자다. |
| 37 | return | 함수의 결과를 호출자에게 돌려주는 문장. print와 다르다. |
| 38 | *args / **kwargs | 추가 위치 인자를 튜플, 추가 키워드 인자를 딕셔너리로 받는 문법. |
| 39 | 스코프 / scope | 이름을 찾아 사용할 수 있는 범위. 함수 안의 지역 이름과 바깥 이름을 구분한다. |
| 40 | 컴프리헨션 | 반복·선택 규칙으로 리스트·집합·딕셔너리 등을 만드는 표현식. |

## Python 프로그램으로 확장

| 번호 | 용어 | 쉬운 정의와 주의점 |
|---:|---|---|
| 41 | 모듈 / 패키지 | 모듈은 불러 쓸 코드 단위이고 패키지는 관련 모듈을 구성하는 방식이다. |
| 42 | 가상환경 / venv | 프로젝트의 Python 패키지 환경을 다른 작업과 분리하는 공간. |
| 43 | 의존성 | 프로그램이 실행에 필요로 하는 외부 코드·서비스. 버전·호환성을 관리한다. |
| 44 | 예외 / exception | 실행 중 문제가 발생했음을 전달하는 제어 흐름. 무조건 숨기지 않는다. |
| 45 | with / 컨텍스트 관리자 | 자원 사용 전후의 처리를 정해진 범위에서 수행하는 구조. 모든 with가 연결을 닫는 것은 아니다. |
| 46 | CSV / JSON | 행·열 텍스트 파일 형식과 구조화된 값 표현 형식. 데이터 타입 보존 방식이 다르다. |
| 47 | 클래스 / 객체 | 클래스는 데이터·동작의 구조를 정의하고 객체는 그 구조의 구체적인 인스턴스다. |
| 48 | dataclass | 반복적인 초기화·표현 등 데이터 클래스 코드를 생성하는 Python 도구. |
| 49 | 타입 힌트 | 입출력 타입을 표시하는 정보. 일반 Python 실행에서 모든 타입을 자동 강제하지 않는다. |
| 50 | Protocol | 정해진 메서드·속성을 제공하는 구조를 타입으로 표현하는 방식. |
| 51 | 이터레이터 | 다음 값을 차례로 제공하는 객체. 전체 길이나 임의 인덱싱이 보장되지는 않는다. |
| 52 | 제너레이터 | 필요할 때 값을 순차 생성하는 방식. 한 번 소비한 결과를 자동 복구하지 않는다. |
| 53 | DataFrame | pandas에서 행·열 데이터를 다루는 표형 객체. |
| 54 | merge | pandas의 표 연결 작업. 키 중복과 NULL 키의 매칭 규칙을 확인한다. |
| 55 | 단위 테스트 | 작은 함수나 구성요소의 계약을 독립적으로 확인하는 검사. |
| 56 | 회귀 테스트 | 이미 해결한 동작이 변경 뒤 다시 깨지지 않았는지 확인하는 검사. |
| 57 | fixture / mock | 테스트 준비 데이터를 제공하는 도구와 외부 의존성을 통제된 가짜로 대체하는 방식. |
| 58 | 프로파일링 | 실행 중 어디에서 시간·자원이 쓰이는지 관측하는 작업. |
| 59 | 시간 복잡도 | 입력 크기가 커질 때 연산량이 어떻게 증가하는지 나타내는 모델. |
| 60 | 공간 복잡도 | 입력 크기가 커질 때 필요한 추가 저장 공간의 증가를 나타내는 모델. |

## SQL의 조회와 정합성

| 번호 | 용어 | 쉬운 정의와 주의점 |
|---:|---|---|
| 61 | SELECT / WHERE | 보고 싶은 열을 정하고 조건으로 행을 고르는 조회 구문. |
| 62 | NULL | SQL에서 값이 없거나 알려지지 않음을 표현한다. 0이나 빈 문자열과 다르다. |
| 63 | 3값 논리 | SQL 조건이 참·거짓·unknown을 가질 수 있는 논리. NULL 비교에 주의한다. |
| 64 | GROUP BY / HAVING | 행을 그룹으로 묶고 집계된 그룹을 조건으로 거르는 구문. |
| 65 | JOIN | 키·조건을 기준으로 표를 연결한다. 연결 뒤 한 행의 의미가 달라질 수 있다. |
| 66 | LEFT JOIN | 왼쪽 행을 보존하고 오른쪽 매칭이 없으면 오른쪽 값을 NULL로 둔다. |
| 67 | fan-out / 행 부풀림 | 1:N 연결로 왼쪽 행이 여러 번 나타나는 현상. 합계 중복의 원인이 된다. |
| 68 | CASE | 조건에 따라 값을 선택하는 SQL 표현식. 조건부 집계에 사용한다. |
| 69 | CTE | WITH로 이름을 붙인 쿼리 부분. 논리적 단계이지 항상 물리 저장을 뜻하지 않는다. |
| 70 | 서브쿼리 | 다른 쿼리 안에 들어 있는 쿼리. 결과의 단위·개수를 확인한다. |
| 71 | EXISTS | 관련 하위 행이 하나라도 존재하는지 검사하는 조건. |
| 72 | 윈도 함수 | 행을 유지하면서 그룹 안 순위·이전 값·누적 계산을 수행하는 함수. |
| 73 | 프레임 / frame | 윈도 계산에 실제로 포함할 행 범위. 누적 합의 경계에 영향을 준다. |
| 74 | 트랜잭션 | 관련 DB 작업을 하나의 성공/실패 단위로 묶는 경계. |
| 75 | COMMIT / ROLLBACK | 트랜잭션을 확정하거나 취소하는 명령. |
| 76 | 격리 수준 | 동시 트랜잭션이 다른 변경을 어떻게 관측하는지 정하는 규칙. |
| 77 | MVCC | 여러 행 버전을 활용해 동시 읽기·쓰기의 가시성을 관리하는 방식. |
| 78 | 낙관적 잠금 | 읽었던 버전과 현재 버전을 비교하고 같을 때만 변경하는 패턴. |
| 79 | UPSERT | 키가 없으면 INSERT, 있으면 정한 조건에 따라 UPDATE하는 처리. |
| 80 | 정규화 | 중복과 변경 이상을 줄이도록 데이터 관계·속성을 분리하는 모델링 원칙. |

## 운영·시간·권한·규모

| 번호 | 용어 | 쉬운 정의와 주의점 |
|---:|---|---|
| 81 | 인덱스 | 일부 조회를 효율적으로 지원하는 별도 접근 구조. 저장·쓰기 비용이 든다. |
| 82 | 실행 계획 / EXPLAIN | DB가 데이터를 읽고 연결하고 집계하려는 방식을 보여 주는 정보. |
| 83 | 파티셔닝 | 큰 논리적 표를 날짜 등 규칙에 따라 물리적 부분으로 나누는 설계. |
| 84 | materialized view | 조회 결과를 물리적으로 보관하는 구조. 새로고침·신선도 관리가 필요하다. |
| 85 | RLS | DB가 행별 접근 정책을 적용하는 기능. 실제 실행 역할과 적용 예외를 확인한다. |
| 86 | 인증 / 인가 | 누구인지 확인하는 일과 무엇을 할 수 있는지 판단하는 일. |
| 87 | API / HTTP | 프로그램의 약속된 접근 인터페이스와 웹 요청·응답에 쓰는 프로토콜. |
| 88 | 파라미터 바인딩 | 사용자 값을 SQL 코드와 분리해 전달하는 방식. 인가를 대신하지 않는다. |
| 89 | 페이지네이션 | 큰 결과를 정해진 단위로 나눠 읽는 방식. 정렬·커서 계약이 필요하다. |
| 90 | 멱등성 / idempotency | 같은 효과의 작업을 반복해도 목표 상태가 추가로 변하지 않는 성질. |
| 91 | ETL | 데이터 추출·변환·적재 흐름. 원천 계약·오류·재처리가 포함된다. |
| 92 | 격리 / quarantine | 유효하지 않은 행을 이유와 함께 따로 보관하는 처리. |
| 93 | 워터마크 | 어디까지 처리했는지 기록한 진행 위치. 실패·지연 도착 처리와 연결된다. |
| 94 | event time / available time | 사건 발생 시각과 그 정보를 사용할 수 있게 된 시각. 서로 다를 수 있다. |
| 95 | 데이터 누수 | 판단 당시 알 수 없던 정보가 평가·학습·과거 분석에 섞이는 문제. |
| 96 | async / await | 중단·재개 가능한 비동기 작업을 정의하고 기다리는 표현. 자동 병렬 실행은 아니다. |
| 97 | 이벤트 루프 | 비동기 작업의 진행과 대기 완료를 조정하는 실행 장치. |
| 98 | 동시성 / 병렬성 | 여러 작업을 겹쳐 진행하는 개념과 동시에 실제 계산을 수행하는 개념. |
| 99 | 로그 / 지표 / 추적 | 개별 사건 기록, 수치 관측, 요청의 여러 단계 연결 정보. |
| 100 | Ontology | 업무 대상·속성·관계·행동을 연결해 운영 흐름을 모델링하는 개념. Palantir 제품 기능과 로컬 표를 동일시하지 않는다. |

## 오답 패턴 20개

| 증상 | 잘못된 생각 | 교정 질문 |
|---|---|---|
| 숫자 문자열을 더함 | 숫자처럼 보이면 숫자다 | 실제 타입은 무엇인가? |
| print 결과를 재사용 못함 | 화면에 보이면 return된 것이다 | 함수 반환값을 저장했는가? |
| 공유 리스트가 같이 바뀜 | 이름마다 객체가 복사된다 | 두 이름이 같은 객체를 보는가? |
| kwargs 오타를 놓침 | 유연하면 모두 받아도 된다 | 허용한 키가 무엇인가? |
| 제너레이터 결과가 비어 있음 | 여러 번 순회해도 된다 | 이미 소비했는가? |
| 타입 힌트만 믿음 | 힌트가 실행 입력을 강제한다 | 실제 입력 검증이 있는가? |
| 예외를 모두 숨김 | 오류가 없으면 성공이다 | 어떤 행을 잃었는가? |
| SQL 합계가 증가 | JOIN은 옆으로 붙이기만 한다 | 오른쪽 키가 고유한가? |
| DISTINCT로 무조건 고침 | 중복처럼 보이면 모두 제거한다 | 같은 금액의 다른 거래인가? |
| 0건 지점 누락 | LEFT JOIN이면 언제나 보존된다 | WHERE가 NULL 행을 제거하는가? |
| 지연율이 낮아짐 | 누락은 0으로 채워도 된다 | 관측과 가정을 구분했는가? |
| 비율 평균 오류 | 비율도 그냥 평균하면 된다 | 분모가 같은가? |
| 최신 행이 여러 개 | MAX 시각이면 유일하다 | 동률 규칙이 있는가? |
| 시점 비교 오류 | UTC 날짜와 업무 날짜가 같다 | 어떤 시간대의 날짜인가? |
| RLS 관리자 테스트 오해 | 모든 역할에 같은 정책이 적용된다 | 역할 예외와 소유자는 누구인가? |
| 다른 지점 데이터 노출 | 파라미터 바인딩이면 안전하다 | 그 지점을 볼 권한이 있는가? |
| 무한 재시도 | 실패는 다시 하면 해결된다 | 재시도 가능한 오류이며 멱등한가? |
| API가 async인데 느림 | async는 자동 고속 병렬이다 | blocking 코드와 동시성 제한은? |
| 인덱스 남발 | 많을수록 빠르다 | 실제 계획과 쓰기 비용은? |
| 과장된 포트폴리오 | 예제를 실행하면 운영 경험이다 | 직접 구현·검증한 범위는 어디인가? |

## 설명 연습의 순서

한 단어의 뜻을 말하고, 교재의 입력으로 예를 들고, 잘못 적용한 반례를 듭니다. 마지막에는 DS에게 왜 중요한지와 FDSE가 어떻게 검증할지 설명합니다. 단어를 외워도 반례를 만들 수 없다면 해당 강의로 돌아갑니다.

정의의 상세 근거는 각 본문 강의의 Python·PostgreSQL·pandas·FastAPI 공식 문서 및 14번 출처 문서에 연결되어 있습니다.
