## Q9. k-최근접 이웃 알고리즘에 대해서 설명해 달라. `#ch01` `#N04`

### A.

**한 줄:** 새 데이터와 **가장 가까운 k개** 기존 샘플을 보고, **다수결**(분류) 또는 **평균**(회귀)으로 예측.

**책:** Ch.01-3 (도미 vs 빙어), Ch.03-1 (k-NN 회귀)

#### 1) 왜 "최근접 이웃"인가

- **학습:** 데이터를 **외워 두는** 쪽에 가깝다 (가중치를 크게 학습하지 않음).
- **예측:** 새 점 → 기존 점들과 **거리** 계산 → 가까운 k개 이웃의 label 참고.

#### 2) 책 예제 (도미 vs 빙어)

| | feature | label |
|---|---|---|
| 입력 | 길이, 무게 | (예측 대상) 도미 / 빙어 |

1. scatter plot: 가로=길이, 세로=무게, 점=생선  
2. 새 생선 (25cm, 150g)  
3. 기존 점들과 거리 계산 (보통 **유클리드 거리**)  
4. 가장 가까운 **k개** 이웃의 종류 확인  
5. **다수결** → "빙어 2, 도미 1"이면 → **빙어**

#### 3) k 값

| k | 특징 |
|---|---|
| **k=1** | 가장 가까운 1개만 → **민감**, 노이즈에 약함 |
| **k=3, 5** | 여러 이웃 투표 → **안정** |
| k 너무 큼 | 멀리 있는 다른 클래스까지 끌려와 **경계가 흐려짐** |

#### 4) 거리

두 점 (x₁,y₁), (x₂,y₂):

```
distance = √((x₂-x₁)² + (y₂-y₁)²)
```

feature **단위·스케일**이 다르면 거리가 왜곡됨 → Ch.2 **스케일링** 필요.

#### 5) fit / predict (sklearn)

```python
from sklearn.neighbors import KNeighborsClassifier

model = KNeighborsClassifier(n_neighbors=3)
model.fit(X_train, y_train)   # 학습 = 데이터 저장
model.predict([[25, 150]])    # 예측 = 이웃 찾기
```

- `fit`: 파라미터를 많이 바꾸는 게 아니라 **훈련 데이터를 기억**
- `predict`: 새 입력 → 거리 계산 → k개 이웃 → 다수결

#### 6) 장단점

| 장점 | 단점 |
|---|---|
| 개념·구현 **매우 쉬움** | 데이터 많으면 **느림** (매번 전체와 거리) |
| 비선형 경계도 어느 정도 | feature 많으면 **차원의 저주** |
| 첫 ML 입문에 최적 | k·거리·스케일에 **민감** |

#### 7) 분류 vs 회귀 (Ch.3)

| | k-NN 분류 | k-NN 회귀 |
|---|---|---|
| 예측 | k개 label **최빈값** | k개 값의 **평균** |
| 예 | 도미/빙어 | 집값, 매출 |

#### 8) 도메인 연결

| | 예 |
|---|---|
| **EDENING** | (길이=풀이시간, 무게=오답수) → 유형 분류 — **채점 자체는 규칙**, 유형 태깅은 ML |
| **케어링크** | 거래 금액·빈도 → 이상/정상 분류 (tabular) |

#### 9) 확인 3문

1. k=1 vs k=5, 노이즈 한 점이 있을 때 어느 쪽이 더 흔들리나?  
2. 길이(cm)와 무게(g) 스케일이 다른데 스케일링 안 하면?  
3. k-NN이 "학습"한다고 할 때 실제로 하는 일은?

**힌트:** 1→k=1 / 2→ 큰 쪽 feature가 거리 지배 / 3→ 데이터 기억, predict 때 이웃 탐색

## Q10. feature가 많으면 차원의 저주인데, k-NN은 x 하나 y 하나(일차함수)만 계산할 수 있어? x와 y가 뭐야? `#ch01` `#N04`

### A.

**아니요.** k-NN은 **feature가 1개든 100개든** 거리만 계산하면 됩니다. **일차함수 y=ax+b처럼 x 하나만 쓰는 알고리즘이 아닙니다.**

#### x, y 헷갈림 정리

| 이름 | 생선 예제에서 | 의미 |
|------|----------------|------|
| **feature (특성)** | 길이, 무게, … | 모델 **입력** (측정값). 개수 = **차원** |
| **label (레이블)** | 도미 / 빙어 | 맞히려는 **정답** |
| **그래프 x축, y축** | 가로=길이, 세로=무게 | **그림 그릴 때** 축 이름일 뿐 |

- Ch.01-3 그림: feature **2개** (길이, 무게) → **2차원** scatter plot  
- 축 이름을 x, y라고 부른 것 ≠ “계산은 2개만 가능”

#### feature 2개일 때 거리

한 생선 A = (길이 25, 무게 150), B = (28, 200):

```
distance = √((28-25)² + (200-150)²)
         = √(9 + 2500)
```

- 1번째 feature 차이 + 2번째 feature 차이 → **제곱합 → 루트**  
- feature 3개면 `(f3_A - f3_B)²` 항이 **하나 더** 붙음

#### feature 3개, 10개, 100개?

| feature 예 (케어링크) | 차원 |
|------------------------|------|
| 거래금액만 | 1차원 |
| 길이 + 무게 | 2차원 |
| 금액 + 빈도 + 최근일수 | 3차원 |
| ERP 컬럼 50개 | **50차원** |

k-NN은 **항상**: 새 점 ↔ 모든 훈련 점, **모든 feature**에 대해 거리 계산 → k개 이웃.

**선형 회귀(Ch.3)** 와 비교:

| | k-NN | 선형 회귀 |
|---|---|---|
| 입력 | feature **여러 개** 가능 | feature **여러 개** 가능 |
| 출력 | label (분류) / 숫자 (회귀) | **숫자 하나** (y) |
| 하는 일 | 이웃 찾기 | **직선/평면** fitting |

#### “차원의 저주”가 뭔 뜻이냐

**2D만 된다**는 뜻이 **아님**. **차원(= feature 개수)이 늘수록**:

1. **공간이 기하급수적으로 커짐** → 같은 데이터 수로는 점들이 **듬성듬성**  
2. **가장 가까운 이웃**도 절대 거리는 **멀어지기 쉬움**  
3. 모든 점이 서로 **비슷한 거리**처럼 보임 → “이웃” 의미가 약해짐  
4. k-NN은 **느려짐** (매번 고차원 거리 계산)

→ feature 많을수록 k-NN **불리** (트리·DL 등 다른 선택 검토)

#### EDENING 예

| | feature | label |
|---|---|---|
| 2차원 그림 | 풀이시간, 시도횟수 | 오답유형 |
| feature 10개 | + 스킬태그, 단원, … | 같은 label |

**가능**하지만, feature 많으면 Ch.2 **스케일링** + 차원의 저주 고려.

#### 확인 2문

1. 생선 (길이, 무게, 지느러미 길이) 3개면 몇 차원?  
2. scatter plot은 2 feature까지만 그리기 쉬운데, k-NN은 3 feature에서도 동작하나?

**답:** 1→3차원 / 2→**동작함** (그림은 2D projection일 뿐)

## Q11. feature에 여러 특성이 있고 특성이 x,y로 표현되는 건가? x,y 두 개뿐? label은 y가 아니면 뭐야? `#ch01` `#N04`

### A.

**x, y = feature가 딱 2개**라는 뜻이 **아님**. **그래프 축 이름**일 때가 많음. feature 3개면 **z** 또는 **x₃**까지 씀.

#### 한 표로 정리

| 말 | ML에서 의미 | 생선 예 |
|---|---|---|
| **feature** | 입력 **측정값** (여러 개) | 길이, 무게, … |
| **label** | **정답** | 도미 / 빙어 |
| **그래프 x축** | 보통 **1번째 feature** | 길이 |
| **그래프 y축** | 보통 **2번째 feature** | 무게 |
| **수학 y (회귀)** | **예측할 숫자**(label) | 집값 — Ch.1 분류와 **다른 y** |

#### 핵심

- **label ≠ y축**
- **y축 = feature 하나**(무게)를 그린 것
- **label = 도미/빙어** → scatter **색/범례**

#### feature 3개 이상

- f1, f2, f3 → 3D 그림 (x,y,z) 또는 **3차원 거리**
- f1~f10 → k-NN **10차원** 계산. 사람은 2~3개만 그림

#### k-NN 한 줄

```
입력: [feature1, feature2, …, featureN]
출력: label
```

#### `fit(X, y)`의 y

sklearn에서 **y = label** (변수 이름). **y축(무게)과 무관.**

#### y 글자가 두 번

| 문맥 | y 의미 |
|---|---|
| scatter | 2번째 **feature** |
| fit(X,y), y=ax+b | **label / 타깃** |

→ **feature / label**이라고 부르면 덜 헷갈림.

#### 기억

> feature = 질문지 (여러 항목) · label = 채점 결과 · x/y축 = 2D 그림용 이름

**확인:** y축=무게일 때 label은? → **도미/빙어**. feature 5개 거리? → **5차원**.

## Q12. feature 2개=일차함수? 3개=z 포함 3D? 3,4,5차원 이미지로 볼 수 있어? `#ch01` `#N04`

### A.

**반은 맞고, 표현만 고침:**

| feature 수 | 공간 | 그림 |
|---:|---|---|
| 1 | **1D** (직선 위 점) | 일차함수 **그래프와 다름** |
| 2 | **2D 평면** (x,y) | scatter — **y=ax+b 직선이 아님** |
| 3 | **3D** (x,y,z) | 3D scatter 가능 |
| 4+ | **4D, 5D…** | **한 장 4D 그림 불가** → pair plot / parallel coords |

**3차원:** z축 = **3번째 feature** (예: 지느러mi 길이). label은 여전히 **색**.

**4차원:** feature 4개 조합 중 **2개씩** 6장 2D 그림 (`dim4_pairplot.png`).

**5차원:** **평행 좌표** — 샘플마다 line 1개 (`dim5_parallel.png`).

## Q15. 우리 눈은 왜 4D, 5D를 못 보나? `#ch01`

### A.

**한 줄:** 눈·뇌는 **3방향 공간**만 보도록 만들어졌고, **4번째 “공간 방향”** 을 감지하는 기관이 없음.

#### 1) 눈은 원래 2D 화면

- 망막 = **2D** (가로×세로)
- **3D**는 두 눈 시차·크기·가림·움직임 등 **단서 조합**으로 **추정**
- 그래서 3D까지는 “본다”고 느낌

#### 2) 4D “공간”이란

- x⊥y, y⊥z처럼 **네 번째 축**이 x,y,z **모두에 수직**인 방향
- 우리 몸·눈에는 그 방향 **감지·이동** 구조 없음
- **5D** = 한 축 더 → 더더욱 없음

#### 3) 진화 (직관)

- 필요한 건 **걷기·잡기** → **3D**면 충분
- 4번째 공간 축 세계를 **경험할 선택 압력**이 없음

#### 4) 색·시간 = 4D 공간?

| | 4D **공간**? |
|---|---|
| label **색** | ❌ (3D 점에 정보 추가) |
| **시간** 애니메이션 | ❌ (3D를 순서대로 보여줌) |
| pair plot / parallel coords | ❌ (고차원 **데이터**를 2D **그림**으로 번역) |

**데이터**는 4D·5D여도 **그림**은 2D 화면.

#### 5) ML

- k-NN 4D 거리: √((Δf1)²+…+(Δf4)²) → **계산 OK**
- **보기**만 pair plot / parallel coords / PCA(Ch.6)

#### 비유

> 3D 방의 앞·옆·위는 본다. 4D 방의 “4번째 방향”은 **상상**은 되어도 **눈으로는** 없다.

**확인:** 3D scatter **색** = 4D 축? → **아니오**. feature 5개 k-NN 동작? → **예**.

## Q17. 거리 공식은 x,y 좌표로 구하는데, 점마다 x,y 하나씩. k-NN은 어떻게 구해? `#ch01` `#N04`

### A.

**헷갈린 지점:** “점마다 x **하나**, y **하나**” → **맞음**.  
다만 k-NN에서 **x,y = feature 2개**일 뿐. feature 3개면 **(f1, f2, f3) 좌표 3개**를 **한 점**이 가짐.

#### 점 = feature 값 묶음 (벡터)

| 생선 | f1 길이 | f2 무게 | f3 지느러미 |
|------|--------|--------|------------|
| A | 25 | 150 | 8 |
| B | 28 | 200 | 9 |

→ A는 **(25, 150, 8)** 이라는 **한 점**. x만 있거나 y만 있는 게 아님.

#### 2 feature (책 그림 = x,y)

A=(25,150), B=(28,200):

```
d = √((28-25)² + (200-150)²)
  = √(9 + 2500) ≈ 50.0
```

- 1번째 feature 차이 + 2번째 feature 차이 → **같은 공식**, 이름만 f1,f2.

#### 3 feature

```
d = √((28-25)² + (200-150)² + (9-8)²)
```

#### N feature (일반식)

```
d = √((f1₂-f1₁)² + (f2₂-f2₁)² + … + (fN₂-fN₁)²)
```

#### k-NN 절차

1. 새 생선 ★ 좌표 (모든 feature 값)
2. **훈련 생선마다** 위 공식으로 거리 1개
3. 거리 **가장 작은 k개** 선택
4. 그 이웃들 **label** 다수결

#### sklearn

```python
model.fit(X, y)   # X: 각 행 = [f1,f2,…], y: label
model.predict([[25, 150, 8.5]])
```

#### 오해 vs 정리

| 오해 | 정리 |
|------|------|
| 점마다 숫자 1개? | **feature 개수만큼** 숫자 (좌표) |
| x,y만 쓸 수 있음? | feature **N개**면 **N차원** 거리 |
| label도 거리에? | **아니오** — label은 **다수결**에만 |

**확인:** (25,150) vs (28,200) 2D 거리? → **√(9+2500)**. feature 3개면 항 **1개 더**?

## Q19. sklearn은 fit만으로 어떻게 훈련해? 안에 숨겨진 과정? `#ch01` `#N05` `#ch02`

### A.

**한 줄:** `fit(X, y)`는 **알고리즘마다 다른** “학습”을 실행하고, 결과를 **모델 객체 안에 저장**한다. k-NN은 **거의 저장만**, 선형회귀·트리는 **파라미터를 계산**.

#### sklearn 공통 API

```python
model.fit(X_train, y_train)   # 학습 → 내부 상태 저장
model.predict(X_new)          # 저장된 상태 + X_new → 예측
```

- **X:** 행=샘플, 열=feature (2D 배열)
- **y:** 각 행의 label
- 학습 결과: `coef_`, `tree_`, `_fit_X` 등 **속성**에 저장

#### 1) k-NN — `fit` = **기억 + (선택) 색인**

| 단계 | 하는 일 |
|------|---------|
| 1 | `X_train`, `y_train` **복사·보관** |
| 2 | (옵션) **KD-Tree / Ball Tree** — 이웃 빠르게 찾는 **색인** |
| 3 | 가중치·공식 **학습 없음** |

**`predict` 때:** 새 점 ↔ train 거리 → k개 → 다수결.  
→ **Lazy learning** — 무거운 일은 **predict** 쪽.

#### 2) 선형 회귀 (Ch.3) — `fit` = **계수 구하기**

- 목표: `y ≈ w1·f1 + w2·f2 + … + b` 의 **w, b** 찾기
- `fit` 안: 최소제곱 등으로 **w, b 계산** → `model.coef_`, `intercept_`
- `predict`: `X @ coef_ + b` (**공식 한 번**)

#### 3) 결정 트리 (Ch.5) — `fit` = **나무 만들기**

- feature·기준값으로 **반복 분할** (if 길이>30 then …)
- `fit` 안: **트리 구조** 생성 → `tree_`
- `predict`: 트리 **따라 내려감**

#### 4) 신경망 (Ch.7) — `fit` = **에포크 반복**

- 가중치 초기화 → forward → loss → **backward** → optimizer
- `fit` 안: **수백~수천 번** 업데이트
- k-NN보다 **훨씬 무거움**

#### 비교표

| 모델 | fit이 하는 일 | predict |
|------|---------------|---------|
| **k-NN** | 데이터 저장 (+색인) | 거리 k번 + 다수결 |
| **선형회귀** | w, b 계산 | 행렬 곱 |
| **트리** | 분할 규칙 생성 | 트리 traverse |
| **신경망** | 가중치 반복 학습 | forward 1회 |

#### fit 내부 흐름 (개념)

```text
fit(X, y) 호출
    → 입력 검증 (shape, NaN …)
    → 알고리즘별 _fit() 실행
    → learned state를 self.??? 에 저장
    → self (같은 model 객체) 반환
```

#### Ch.1 코드 다시

```python
kn = KNeighborsClassifier(n_neighbors=3)
kn.fit(X, y)
# kn.classes_  — label 종류
# kn._fit_X   — (내부) 저장된 train (버전에 따라 이름 다름)
kn.predict([[25, 150]])
```

#### 오해

| | |
|---|---|
| fit = 마법 한 줄 | **알고리즘 전체**가 그 안에 |
| k-NN fit = 가중치 학습 | **아니오** — **기억** |
| predict = fit 없이 | **fit 먼저** (NotFittedError) |

**확인:** k-NN에서 무거운 단계는 fit/predict 중? → **predict** (데이터 많을 때).

## Q25. Ch.2-01 — NumPy는 뭐야? `#ch02` `#N06`

### A.

**책:** 02-1 · 노드 **N06 NumPy** (Ch.2 데이터 다루기의 **바닥 도구**)

#### 1) 한 줄

**NumPy** = Python에서 **숫자 배열**을 빠르게 다루는 라이브러리. ML에서 **feature·label·거리·행렬 연산**은 거의 전부 NumPy **ndarray** 위에서 돌아간다.

```python
import numpy as np   # 관습적 별칭
```

#### 2) 왜 Python 리스트가 아니라 NumPy?

| | Python `list` | NumPy `ndarray` |
|---|---|---|
| 원소 타입 | 섞일 수 있음 `[1, "a"]` | **같은 타입** (float64 등) |
| 속도 | 루프 돌며 하나씩 | **C로 벡터 연산** (한 번에) |
| shape | 길이만 | **차원·형태** `(샘플, feature)` |
| ML | 불편 | **sklearn·pandas 기본 입력** |

Ch.1 생선 (길이, 무게)를 **표**로 생각하면:

```python
X = np.array([
    [25, 150],   # 생선 1
    [28, 200],   # 생선 2
    [30, 180],   # ...
])
# shape = (3, 2)  → 3마리, feature 2개
```

#### 3) ndarray 핵심 개념

| 개념 | 의미 | 예 |
|------|------|-----|
| **ndarray** | n차원 숫자 배열 | 1D = 벡터, 2D = 표 |
| **shape** | 각 축 길이 | `(100, 2)` = 100샘플 × 2 feature |
| **dtype** | 원소 숫자 타입 | `float64`, `int32` |
| **벡터화** | for 없이 전체 연산 | `X * 2`, `X[:, 0] - mean` |

#### 4) Ch.1·Ch.2와 연결

```python
# Ch.1 k-NN — sklearn 안에서도 내부적으로 NumPy
from sklearn.neighbors import KNeighborsClassifier

model = KNeighborsClassifier(n_neighbors=3)
model.fit(X_train, y_train)      # X: 2D ndarray, y: 1D ndarray
model.predict(X_test)

# Ch.2 — train/test split도 NumPy 배열을 잘라냄
from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)
```

- **X (대문자)** = feature 행렬, 보통 **2D** `(n_samples, n_features)`
- **y (소문자)** = label, 보통 **1D** `(n_samples,)`
- Ch.1에서 말한 **x축·y축 그래프**의 x,y와 **다름** — ML 관습에서 **X=입력, y=정답**

#### 5) 자주 쓰는 연산 (Ch.2~에서 반복)

```python
X.shape          # (몇 샘플, feature 몇 개)
X[0]             # 첫 번째 샘플
X[:, 0]          # 모든 샘플의 첫 번째 feature (길이만)
X.mean(axis=0)   # feature별 평균 → 스케일링(02-2) 전초
np.sqrt(((a - b) ** 2).sum())   # 2D 거리 (Ch.1 거리 공식)
```

#### 6) pandas·matplotlib과 관계

| 라이브러리 | 역할 |
|------------|------|
| **NumPy** | 숫자 배열·연산 **엔진** |
| **pandas** | 표(DataFrame) — 내부는 NumPy, **열 이름·CSV** 편함 |
| **matplotlib** | 그래프 — `ax.scatter(X[:,0], X[:,1])` |
| **sklearn** | ML — **입력은 ndarray**(또는 pandas→자동 변환) |

## Q26. `[25, 150]`도 모양은 리스트 아닌가? `#ch02` `#N06`

### A.

**맞다 — 겉모양(문법)은 리스트와 같다.** Python은 `[]`로 리스트도, NumPy 입력도 쓴다. **차이는 “모양”이 아니라 “만든 뒤의 타입·동작”**이다.

#### 1) 리스트 vs ndarray

```python
row_list = [25, 150]
row_arr  = np.array([25, 150])

type(row_list)   # <class 'list'>
type(row_arr)    # <class 'numpy.ndarray'>

row_list * 2     # [25, 150, 25, 150]  ← 반복(concat)
row_arr * 2      # array([50, 300])     ← 숫자×2 (벡터 연산)
```

**같은 `[25, 150]`처럼 보여도**, `np.array(...)`로 감싸면 **ndarray**가 되고 연산이 달라진다.

#### 2) 큰 표도 마찬가지

```python
X = np.array([
    [25, 150],
    [28, 200],
])
# 바깥·안쪽 모두 [] 문법 — 입력은 “리스트의 리스트”
type(X)       # ndarray
X.shape       # (2, 2)
X.dtype       # int64 (또는 float64)
```

**만드는 순간** 리스트 내용을 **한 덩어리 숫자 배열**로 바꿔서, sklearn·거리·평균 같은 ML 연산에 쓴다.

#### 3) 한 줄 정리

| | 리스트 | NumPy |
|---|---|---|
| 문법 | `[25, 150]` | `np.array([25, 150])` — **입력**은 `[]` |
| 타입 | `list` | `ndarray` |
| ML | 보통 **중간 입력** | **실제로 연산·학습** |

**비유:** 종이 설계도(리스트) vs 공장에 넣은 금형(ndarray) — 그림은 비슷해도 **쓰는 쪽**이 다르다.

**확인:** `np.array([1, 2, 3]) * 2` 결과는? → **`array([2, 4, 6])`** (반복이 아님)

## Q28. Ch.2-02 데이터 전처리 — split · 스케일링 `#ch02` `#N10` `#N11`

### A.

**책:** 02-2 · N10 `train_test_split` · N11 `StandardScaler`

#### 1) 전처리 = 모델에 넣기 **전** 데이터 정리

| 단계 | 뭐 하냐 |
|------|---------|
| **분리** | train(연습) / test(모의고사) |
| **스케일링** | feature **단위·크기** 맞춤 (cm vs g) |
| (다음) | 결측 · 범주 인코딩 |

#### 2) train_test_split

```python
from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
```

- **test는 fit에 절대 넣지 않음** — Ch.1 전체 fit = 시험 안 본 문제 없음
- `stratify=y` — train/test에 빙어·도미 **비율** 유지

#### 3) 왜 스케일링? (Ch.1 연결)

- 길이 **3cm** 차 → 거리 √9 = **3**
- 무게 **50g** 차 → 거리 √2500 = **50**
- k-NN은 **무게만** 보게 됨 → **스케일링 필요**

#### 4) StandardScaler (표준화)

$$z = \frac{x - \mu}{\sigma}$$

- feature마다 **평균 0, 표준편차 1** 근처로
- **★ `fit`은 train만**

```python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)   # train으로 μ, σ 학습
X_test_s  = scaler.transform(X_test)          # 같은 μ, σ 적용
```

**test로 fit하면 leak** — 모의고사 답을 미리 본 것.

#### 5) 올바른 순서

```text
split → scaler.fit(train) → transform(train, test) → model.fit → predict(test)
```

#### 6) 한 표

| | train | test |
|---|-------|------|
| split | ✓ fit | ✓ 평가만 |
| scaler.fit | ✓ | ✗ |
| scaler.transform | ✓ | ✓ |
| model.fit | ✓ | ✗ |
| model.predict | (선택) | ✓ |

**PNG:** `ml/images/preprocess_01~03.png`

**다음:** 02-3 결측 · 원-핫 · `Pipeline`
